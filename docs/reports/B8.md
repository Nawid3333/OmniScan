# B8 — Ollama client (local + cloud, retry/backoff, JSON schema)

## Changes

- `src/omniscan/llm/__init__.py` (new): package marker re-exporting the client's public API
  (`ChatResponse`, `RunningModel`, `OllamaError`, `OllamaRateLimitError`, `OllamaClient`).
- `src/omniscan/llm/ollama.py` (new): `httpx`-based client for Ollama's native `/api/chat` and `/api/ps`,
  exactly per the card's interfaces:
  - **Endpoint selection** in `_endpoint`: local → `cfg.local_url` without auth; cloud → `cfg.cloud_url`
    with `Authorization: Bearer <key>`. `cloud=True` with no key raises `ValueError` before any I/O.
  - **`chat`**: `stream=False` body with `format`/`options`/`keep_alive` included only when not `None`
    (so `keep_alive=0` is sent, and omission means the key is absent, not `null`); `messages` passed
    through byte-for-byte. Response fields lifted into `ChatResponse`; missing count/duration keys map to
    `None` (not 0); `raw` keeps the full decoded body.
  - **Retry policy** (shared by `chat` and `ps` via `_request`): retries `httpx.TransportError`, 429 and
    ≥500; every other status raises `OllamaError` (with `status_code` + `body` truncated to 2000 chars)
    after exactly one attempt. `max_retries` = total attempts. Backoff `min(1.0 * 2**attempt, 30)` +
    jitter `uniform(0, delay * 0.25)`; a 429's integer `Retry-After` overrides the curve via
    `max(delay, retry_after)`. All sleeps go through the injected `sleep`.
  - **429 fail-fast:** when 429 retries are exhausted the client raises `OllamaRateLimitError`
    (`status_code` always 429) whose message says the account's session-usage cap is hit and the run
    should stop — this is the failure mode that previously cost 71 lost turns.
  - **`ps`:** fixed `max_retries=5`; parses `models` into `RunningModel` with `size_vram` defaulting to 0
    and `expires_at` to `None`.
  - **Ownership:** `close()` only closes an internally created `httpx.Client` (injected ones stay open);
    idempotent; context manager support.
- `tests/unit/test_llm_ollama.py` (new): all 12 acceptance tests from the card plus two extras (transport-
  error retry path, and the backoff curve/`Retry-After` bounds asserted directly against the spec
  formula), 14 tests total, all via `httpx.MockTransport` — no network, no new dependency.

## Deviations

- Tests construct `Secrets` via `Secrets.model_construct(...)` instead of `Secrets(...)`. Reason:
  `Secrets` is a `BaseSettings` — plain construction would read the developer's real
  `~/.config/omniscan/secrets.env` / `OLLAMA_API_KEY` env var, so the "no API key" test (acceptance #3)
  would fail on any machine with a key configured. `model_construct` bypasses all settings sources, keeping
  the tests deterministic; pydantic-settings' private `_env_file=None` kwarg would have worked at runtime
  but fails pyright. No production code affected.
- `test_chat_404_is_not_retried` asserts on `OllamaError` **not** being `OllamaRateLimitError` in addition
  to the card's requirements — free coverage of the error hierarchy.
- The injected `sleep` is also passed to the transport-error test (not in the card's list) because
  `httpx.ConnectError` from a `MockTransport` handler exercises a retry path the 12 acceptance tests
  otherwise miss.

## Questions

- None blocking. One note for downstream cards (translation/judge): `ChatResponse.content` defaults to
  `""` if a 200 body lacks `message.content`; `model`/`done` use direct indexing, so a malformed 200 body
  raises `KeyError` rather than an `OllamaError`. The card didn't specify malformed-200 behavior; I kept
  it simple and loud (crash on structurally broken success bodies) rather than inventing a status code.

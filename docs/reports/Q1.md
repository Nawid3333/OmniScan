## New tests

In `tests/unit/test_slicer_mutation_gaps.py` (all pass on the original code):

- `test_tolerance_bounds_are_inclusive` — a pixel exactly at `med ± tol` keeps a row uniform; `med±(tol+1)` breaks it.
- `test_uniformity_needs_every_pixel_in_range` — one out-of-range pixel makes the row non-uniform (all-pixel semantics).
- `test_drift_is_mean_over_channels` — a 6-per-red-channel jump between solid rows has mean drift 2.0, so it stays one band (pins mean-over-channels semantics; see Questions).
- `test_non_uniform_row_breaks_band_even_when_median_matches` — a row with an outlier pixel splits a band even though its median equals both neighbours'.
- `test_band_color_uses_all_rows_and_all_channels` — band colour is per-channel, no R/B swap (existing tests used only grey bands).
- `test_band_color_is_lower_median_for_odd_length` — 99-row ramp 0..98 -> colour (49,49,49): full band, torch.median lower-median semantics.
- `test_gradient_flag_threshold_is_exclusive` — first/last row medians differing by exactly `uniform_tol` is *not* a gradient.
- `test_forced_cut_lands_on_least_detail_row` — forced cut = window's minimum-detail row, ties to the target row (first window: flat rows 5100..5102 -> cut 5102; second: least-detail art row 10690). Also kills detail-scale mutants and the half-width-median mutant via the pinned second cut.

Added for the cuts group (same file):

- `test_cost_penalises_only_below_min_height` / `test_cost_penalises_only_above_max_height` — segments of exactly min/max height carry no penalty; DP chooses the cut path it must (cuts `[250]` / `[500]` on hand-computed strips).
- `test_min_height_penalty_is_small_enough_to_lose` — with a wide `max_height`, a sub-minimum segment (penalty 4) still beats one huge slice (cuts `[100]` on H=20000); penalty 40 would flip the choice.
- `test_max_height_penalty_at_exact_boundary` — a 1000px candidate-free strip (max_height 1000) needs no cut; `>=` would split it.
- `test_max_height_penalty_magnitude_is_decisive` — with target 100 / max 200 / hard 2000, the two-segment path beats the single by 99, so penalty 400 flips the DP choice (cuts `[999]` vs none).
- `test_dp_breaks_position_ties_by_earlier_cut` — equal-cost paths tie-break on fewest cuts then earliest positions (`[250]` beats `[750]`).
- `test_band_at_edge_threshold_becomes_edges` — a band of exactly `min_height + band_min` rows contributes edges, not a centre.
- `test_no_cuts_when_gap_equals_hard_max` — a candidate-free gap of exactly `hard_max_height` gets no forced cut (strict `>`).
- `test_forced_cut_window_bounds` / `test_forced_cut_window_lower_bound` — the least-detail window is `[t-256, t+256]` with `t = round(i*gap/(k+1))`: a detail-0 row at exactly `t+256` wins the cut; rows below `lo` never do.
- `test_centre_for_odd_length_band` — odd-length short band centre is `(y0+y1)//2` (existing tests only had even sums, where `+1` is a no-op).

## Equivalent mutants

- bands.py:29 `min` -> `max` on the chunk bound — `max(start + chunk_rows, height) >= height`, so chunk 0 always spans the strip; identical output, only chunking/memory behaviour changes (and memory growth is bounded by the strip itself).
- bands.py:55 dropping `uniform[1:] &` from `link` — `uniform[j+1] & ~(uniform[j+1] & uniform[j] & drift)` ≡ `uniform[j+1] & (~uniform[j] | drift)`; the mutant computes exactly that expression.

## Questions

- `max_drift` compares the **mean over channels** of the per-channel median jump against `max_drift` (bands.py:54-55). A hard jump in one channel (e.g. +6 red) has mean 2.0 and does NOT split a band, while the same total spread spread across channels would. `test_drift_is_mean_over_channels` pins the mean semantics (matching the code), but `docs/ARCHITECTURE.md` does not spell out mean-vs-max — worth a sentence there if mean is intended.

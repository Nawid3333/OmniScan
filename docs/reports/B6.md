# B6 — Promo filter (file-level + slice-level, perceptual hash)

## Changes

- `src/omniscan/filter/__init__.py` (new): re-exports the public API of the package.
- `src/omniscan/filter/hashing.py` (new): `dhash` (dHash, hash_size=8 → 64-bit, MSB-first packing,
  LANCZOS grayscale resize), `hamming` (`int.bit_count`), `similarity` (clamped to [0, 1]).
  Pixel access uses `tobytes()` — `Image.getdata()` is deprecated in this Pillow version.
- `src/omniscan/filter/decide.py` (new): `ExampleHash`, `load_examples` (global + series dirs,
  non-recursive, case-insensitive `.jpg/.jpeg/.png`, forward-slash names), `best_match`,
  `decide_files` (pHash per raw file; filtered → `shutil.copy2` into `filtered_dir`),
  `decide_slices` (pHash per strip crop; filtered → crop saved at quality=95),
  `effective_decision` (last-write-wins), `restore` (appends a `manual`/"restored" decision,
  metadata-only, atomic save via `FilterArtifact.save`).
- `src/omniscan/cli.py`: removed the `filter` stub (`cmd_filter` + `_STUB_COMMANDS` entry); added a
  `filter_app` Typer sub-app mounted at `app.add_typer(filter_app, name="filter")` with
  `omniscan filter run <series> <chapter> [--threshold 0.90]` and
  `omniscan filter restore <series> <chapter> <file|slice> <index>`. `run` loads `ingest.json` /
  `slices.json` via `paths.artifact(...)` + `Model.load`, assembles the strip on the CPU
  (`Image.new` + paste of each raw resized to its strip-space y-range at its `y0`), runs
  `decide_files` + `decide_slices`, saves `filter.json`, prints the one-line summary. No other
  command touched.
- `tests/fixtures/images.py`: added `gradient_jpeg(path, size, invert=False)` — a horizontal
  luminance ramp (falling when inverted) so dHash has non-uniform content to work with.
- `tests/unit/test_filter_hashing.py`, `tests/unit/test_filter_decide.py` (new): the acceptance
  tests below.

## Deviations

1. **Acceptance test 2 as written cannot pass with any correct dHash.** dHash compares adjacent
   pixel columns; a solid-color image has no variation, so *every* solid image — red, blue, any
   color — hashes to all-zero bits regardless of color. Verified empirically:
   `dhash(solid_red) == dhash(solid_blue) == 0` → `similarity(...) == 1.0`, not `< 0.5`. This is
   inherent to the algorithm specified in this card (and the reason dHash needs *structured*
   content to discriminate). I adapted the test to preserve its stated intent ("very different
   images hash far apart") using the new `gradient_jpeg` fixture: rising vs falling ramp →
   similarity 0.0 < 0.5. I also added `test_solid_color_images_hash_to_zero` to pin the
   uniform-field invariance explicitly. **The card should be amended** (test 2 → structured
   images); see Questions.
2. `omniscan filter run` treats a missing `slices.json` the same way as a missing `ingest.json`
   (message to stderr + exit 2). The card only specified the `ingest.json` case; `decide_slices`
   needs `slices.json`, so exiting 2 with a "run slice first" message mirrors the specified
   pattern instead of crashing with a raw traceback.
3. `load_examples` iterates `global` first, then the series directory, each in sorted-filename
   order (the card fixed neither the order of the two directories nor ordering within them).
4. Added the `gradient_jpeg` helper to `tests/fixtures/images.py` (allowed by the card: "extend …
   with a small helper if useful"); no existing helper was changed.

## Questions

1. Acceptance test 2 names solid red vs solid blue as the "very different" pair. As shown above,
   dHash cannot separate two uniform fields — is the intended fixture something with structure
   (the fix I applied), or was a different algorithm/behavior intended for uniform pages? Solid
   promo end-cards *are* a plausible real-world case; with pHash they will hash to all-zeros and
   match *each other* at 1.0 while never matching structured pages — worth keeping in mind for
   the planned embedder stage.
2. Confirm the symmetric missing-`slices.json` CLI behavior (exit 2, "run slice first") is wanted,
   or whether `run` should proceed file-level-only when `slices.json` is absent.

# B30 — Web debug tool: Filtered review panel (with Restore)

## Changes

- `src/omniscan/web/app.py`
  - CORS `allow_methods=["GET", "POST"]` (origins unchanged).
  - Helpers `source_names(chapter)` (SourceFile index → name from `ingest.json`) and
    `slice_ranges(chapter)` (Slice index → (y0, y1) from `slices.json`), both `{}` on missing/invalid
    input (never a 500), in the style of the existing `final_lines` helper.
  - `GET /api/series/{series}/filtered` → `list[FilteredChapter]` in `SeriesPaths.chapters()` order.
    An item exists for every `(target, index)` with at least one `filtered` decision in
    `filter.json`; `state` = `effective_decision(...)`; `score`/`matched_example`/`method` come from
    the last `filtered` decision of the pair; `name` from `ingest.json` (file items, `null` when
    missing/invalid), `y0`/`y1` from `slices.json` (slice items, `null` when the slice is absent or
    the artifact is missing/invalid). Sorted file-before-slice then by index. Chapters without
    `filter.json`, with only keep decisions, or with an invalid `filter.json` are skipped (status 200,
    never a 500); unknown series → `[]`; `..` escapes → 404 via the existing `series_paths` check.
  - `POST /api/series/{series}/chapters/{chapter}/filter/restore` with body model `RestoreBody`
    (pydantic, `Literal["file", "slice"]`, `index: int` with `ge=0`, `extra="forbid"` via core's
    `Model`):
    1. content-type must start with `application/json` (case-insensitive) → else `415` and nothing
       is written (the CSRF guard — a cross-site page can send `text/plain` POSTs without a
       preflight);
    2. `chapter_paths` validation → 404 on any escape;
    3. missing `filter.json` → 404 (`"filter.json not found"`); invalid `filter.json` → 404 too
       (see Questions);
    4. effective decision must be `"filtered"` → else `409`
       (`{"detail": "item is not currently filtered"}`), nothing written;
    5. `omniscan.filter.decide.restore(paths, target, index)` → the new decision as JSON (200).
- `webui/src/api.ts`: types `FilteredItem` / `FilteredChapter`; generic `postJson<T>(path, body)`
  helper (sets `Content-Type: application/json`, throws on non-2xx like `getJson`, appends the

  `listFiltered(series)` and `restoreFiltered(series, chapter, target, index)` (every path segment

## Deviations

- The restore endpoint parses the JSON body itself (`RestoreBody.model_validate_json(request.body())`)
  instead of declaring the model as a FastAPI body parameter. With a body parameter, FastAPI parses
  and validates the request body before the endpoint runs, so a `text/plain`/form-urlencoded request
  with a *valid* JSON body was answered `422` before the CSRF guard could answer `415` — the guard
  order the card specifies (415, nothing written) was unobservable. Parsing after the guard keeps
  `RestoreBody` (Literal, `ge=0`, extra-forbidden) and the 422 status (pydantic errors list as
  `detail`, same shape FastAPI would produce).
- The three scratch scripts used for the manual check (`b30_demo_setup.py`, `b30_serve.py`,
  `b30_curl.py`) could not be deleted because `rm` was denied in this session. They are untracked and
  NOT committed — please `rm b30_demo_setup.py b30_serve.py b30_curl.py` and `rm -rf /tmp/b30_demo`.

## Questions

1. An unreadable/invalid `filter.json` on the restore route is currently answered `404` (detail:
   `filter.json is not a valid filter artifact: ...`). The card specifies 404 only for a *missing*
   file and 409 for a not-filtered item; the only alternatives were a 500 (violates the spirit of
   "never a 500") or treating invalid like missing. I chose the explicit 404; say the word if you
   prefer a 409 or the plain `"filter.json not found"` detail.
2. `summarizeFiltered` counts anything not `"restored"` as filtered (the state type only has the two
   values, so it is equivalent to counting by state). No pluralization is applied to the summary line
   ("1 chapters" is possible); the card's example line uses that exact format, so I kept it literal.

# Q2 — Mutation review of the promo filter, glossary matcher and importer planner

## Summary

Hand-written mutants (via `scripts/mutate.py`) were run against the seven existing test files of the three module groups; every surviving mutant was classified and, when it was a real gap, closed with a new test that was proven to kill it (`--only` rerun). A second round probed the same code with fresh angles. Production code was not modified (`git diff --stat -- src` empty after every run).

| Group | Mutants | Killed first pass | Survived first pass | Closed by new tests | Equivalent |
|---|---|---|---|---|---|
| filter (`decide.py` + `hashing.py`) | 35 | 25 | 10 | 10 | 0 |
| glossary (`match.py` + `store.py` + `yaml_io.py`) | 32 | 27 | 5 | 4 | 1 |
| importer (`plan.py` + `execute.py`) | 35 | 31 | 4 | 4 | 0 |
| round 2 (all groups) | 13 | 12 | 1 | 1 | 0 |
| **total** | **115** | **95** | **20** | **19** | **1** |

14 new tests in `tests/unit/test_filter_glossary_importer_mutation_gaps.py`; all pass on the original code and each kills at least one former survivor. The surviving mutants fell into three themes:

1. **Scores on "keep" decisions and default thresholds were unpinned** — a "keep" decision could report `score=0.0` instead of the best similarity found, and both default thresholds (`0.90`) could move to `0.80` without any test noticing. Scores and the inclusive-threshold boundary are now asserted exactly.
2. **Exact bit patterns of `dhash` were never pinned** — dropping the first hash row, flipping `>` to `<`, or changing the default `hash_size` all left the old tests green (they only check similarity *between* two hashes, and a solid image hashes to 0 under several of those mutations too). The hash of the synthetic rising/falling ramp fixtures is now pinned to `0` / `2**64 - 1`.
3. **Ordering contracts** — `find_by_source` lowest-id rule, glossary export id-ascending order, replace-import file order, case-C chapters-ascending, natural-order warnings, and the "resume scanning *after* the particle" rule of the matcher were all untested.

Note on the harness: `scripts/mutate.py` prints via the console encoding (cp1252 on this machine), so a mutant label or snippet containing non-ASCII crashes it with `UnicodeEncodeError`; runs here used `python -X utf8 scripts/mutate.py ...`. (Only an observation — `scripts/` was not touched.)

## Equivalent mutants

- `yaml_io.py:18` — `tmp = path.with_suffix(path.suffix + ".tmp")` → `tmp = path` (SURVIVED, judged equivalent): with `tmp == path` the same bytes are written to `path` and `tmp.replace(path)` degenerates to a self-rename, so the final file content is identical in every reachable scenario. The removed property is crash-atomicity (a failure mid-write would truncate the real file) which cannot be observed by a test without fault injection into the middle of `write_text`.

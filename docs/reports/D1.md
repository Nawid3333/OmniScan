# D1 — Detect: catch a cross-class duplicate when one box is contained in the other

## Changes

- `src/omniscan/detect/postprocess.py` (only `_items` + one new constant):
  - New constant `_CROSS_CLASS_CONTAIN_IOA = 0.85` directly below `_CROSS_CLASS_DUP_IOU`, with the
    card's comment. `ruff format` wrapped it into a parenthesised 3-line block because the line
    (constant + comment) exceeds the repo's line length; value and comment unchanged.
  - The cross-class dedup loop's `continue` guard now triggers on a disjunction instead of the IoU
    test alone. A `(text_free, text_bubble)` pair counts as a duplicate when **any** of
    `iou(free.box, tb.box) >= _CROSS_CLASS_DUP_IOU`, `ioa(free.box, tb.box) >= _CROSS_CLASS_CONTAIN_IOA`
    (free mostly inside tb) or `ioa(tb.box, free.box) >= _CROSS_CLASS_CONTAIN_IOA` (tb mostly inside
    free) holds — written as a named `duplicate = (...)` local before the guard so the intent reads
    in one place. The tie-break is byte-for-byte unchanged: higher score survives, and `free.score >
    tb.score` drops the bubble one, else the free one (with the same inner-loop `break`).
    `_CROSS_CLASS_DUP_IOU` itself was not lowered or otherwise touched, and nothing else in the file
    changed (`iou`, `ioa`, `_TEXT_IN_BUBBLE_MIN_IOA`, `merge_detections`, `reading_order`, `build_regions`).
- `tests/unit/test_detect_postprocess.py` (extended; nothing removed or edited):
  - Import line gains the public helpers `ioa`, `iou` (ruff wrapped it into parenthesised form).
  - `test_build_regions_drops_contained_cross_class_duplicate_solo_leveling_pair` — the exact real
    pair from the card: `text_bubble (140, 11622, 605, 12018)` score 0.7 vs
    `text_free (140, 11626, 603, 11845)` score 0.5. Asserts the pinning shape (`iou < 0.6`,
    `ioa(free, tb) >= 0.85`) and that `build_regions` emits exactly one region — `bubble_text`,
    confidence 0.7, no bubble — where the old rule emitted two. The boxes sit at strip y≈11.6k–12k,
    so the test supplies its own non-blank `Slice(index=0, y0=11000, y1=12000)` instead of the
    module's `_slices()` fixture (whose middle slice is blank and would have swallowed both regions
    and made the test vacuous).
  - `test_build_regions_drops_free_text_mostly_inside_text_bubble` — free is the inner box, *mostly*
    (95%, not 100%) inside the tb: IoU ≈ 0.25, `ioa(free, tb) = 0.95`, `ioa(tb, free) ≈ 0.26`; the
    free box wins the score tie-break and survives as the only region. Exercises the
    `ioa(free, tb)` branch specifically (asserted the other direction stays < 0.85).
  - `test_build_regions_drops_text_bubble_mostly_inside_text_free` — the same geometry with the
    classes swapped, exercising the `ioa(tb, free)` branch; tb wins on score and survives.
  - `test_build_regions_keeps_two_distinct_partly_overlapping_captions` — negative test: two
    realistically stacked captions (300×100 each, 20 px vertical overlap) with IoU ≈ 0.11 and IoA
    ≈ 0.20 both ways stay two regions, one of each kind.
- Nothing else: `detect/stage.py`, `detect/tiles.py`, `core/**`, config and data files untouched.

Sensitivity check that the new tests really pin the fix (not part of the suite, run ad hoc): with
`_CROSS_CLASS_CONTAIN_IOA` monkeypatched to 1.01 (which reproduces the pre-fix IoU-only behaviour —
IoU still never reaches 0.6 for these pairs), all three new duplicate tests **fail** (two regions
instead of one) and the negative test **passes**. So the trio cannot pass without the new rule, and
the negative test does not depend on it.

Numbers of the real pair, as on the card: `iou = 101397 / 184140 ≈ 0.5506` (old rule: no drop),
`ioa(free, tb) = 101397 / 101397 = 1.0` (new rule: drop).

## Deviations

- `ruff format` wrapped the new constant and the test import line into parenthesised multi-line
  forms (repo line length); content is exactly the card's snippet otherwise.
- The Solo Leveling regression test supplies its own slice list rather than the module's `_slices()`
  fixture: the real pair's y (≈11.6k–12k) falls in that fixture's *blank* middle slice, where
  `build_regions` drops everything, which would have made the test pass even without the fix.

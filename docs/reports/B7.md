# B7 — Web debug tool: OCR view

## Changes
- `src/omniscan/web/app.py` — added exactly one route, `GET /api/series/{series}/chapters/{chapter}/ocr`, serving `ocr.json` byte-for-byte via the existing `artifact_bytes` helper. Nothing else changed.
- `tests/unit/test_web_app.py` — appended three tests (exact bytes, 404 when missing, traversal on the ocr route) plus the `_ocr_artifact` helper building a 2-region `RegionsArtifact`.
- `webui/src/api.ts` — added `BBox`, `RegionKind`, `OcrLine`, `Region`, `RegionsArtifact` types (matching `core/schemas.py`) and `getOcr()` in the same style as `getSlices()`.
- `webui/src/strip.ts` — added `fileAtStripY` and `stripBoxToStackBox` (pure functions, no DOM).
- `webui/src/ocr.ts` (new) — `LOW_CONFIDENCE`, `kindColor`, `disagrees`, `isLowConfidence`, `filterRegions`, `summarize`.
- `webui/src/ocr.test.ts` (new) — unit tests for all of the above.
- `webui/src/strip.test.ts` — appended tests for `fileAtStripY` and `stripBoxToStackBox` (single scale=1 file, scale=0.5 file, box on the second of two files).
- `webui/src/OcrView.svelte` (new) — stacked-`<img>` + absolutely positioned `<svg>` overlay copied from the `SlicerView` layout; kind checkboxes, summary line, per-region rects (kind colour, 0.08 fill, dashed when low-confidence), yellow inflated disagreement rect, dotted gray bubble rect, `reading_order · confidence(≠)` labels, click-to-select (stroke-width 4, click again or "clear" to deselect) and the fixed side panel with full region detail.
- `webui/src/App.svelte` — view switcher buttons `Slicer`/`OCR` with `let view = $state<"slicer" | "ocr">("slicer")`; `SlicerView` untouched.

Manual check: a synthetic chapter (one 800x1000 JPEG, `ingest.json`, hand-written `ocr.json` with 4 regions covering all kinds — including one low-confidence SFX with a disagreeing `ocr_alt` and one bubble with `bubble_bbox`) served with real uvicorn on 127.0.0.1:8777:
- `GET .../ocr` → 200 with the artifact JSON (`schema_version`, `regions`, ...).
- `GET .../chapters/Nope/ocr` → 404 `{"detail":"ocr.json not found"}`.
- `GET /api/series/..%2Fsecret/.../ocr` → 404, clean.
The script and fixture were deleted afterwards (not committed). The Svelte view was not exercised in a browser; its mapping logic is covered by the pure-function vitest suite and `npm run check`/`npm run build` both pass.

## Deviations
- The missing-artifact message renders as `<error> — no ocr.json yet — run ocr first.` (error prefix + required phrase on one line) rather than the bare phrase, because the view cannot distinguish a missing `ocr.json` from a missing `ingest.json` at the fetch level.
- One `svelte-ignore` comment on the region `<rect>` (`a11y_click_events_have_key_events`, `a11y_no_static_element_interactions`): SVG rects are not keyboard targets and the side panel is read-only debug UI; making dozens of rects focusable was not desirable.

# G1 — `omni_builder.py ask`: read-only GLM lookups for the director

## Changes
- `scripts/omni_builder.py` — new `ask` subcommand plus helpers:
  - `ASK_SYSTEM` (constant): the read-only research-assistant rules text from the card.
  - `build_ask_prompt(question, files)`: `ASK_SYSTEM + "\n\nQuestion: <q>"` and, when files are given, `"\n\nStart with these files (relative to the repo root): <a, b>"`.
  - `extract_answer(stream)`: parses a stream-json log line by line, keeps the last `"type":"result"` object, returns its stripped `"result"` text; `None` for error results, empty results, or no result object.
  - `try_acquire_slot()`: one non-blocking pass over the slot lock files (extracted from `acquire_slot`, which now loops calling it — messages and 30 s sleep unchanged).
  - `run_claude(..., *, settings=None, permission_mode="acceptEdits")`: new keyword-only args; defaults reproduce the old argv exactly, so `run`/`resume`/`smoke` are unchanged. The ask session runs with `settings=.builder/ask-settings.json`, `permission_mode="default"`, log `LOG_DIR/ask-<UTC YYYYmmdd-HHMMSS>.jsonl`, cwd `--cwd` (default `REPO`).
  - Exit codes: `0` answer only on stdout; `1` failed/no answer (message via `say()` on stderr); `3` no free slot without `--wait` (`omni-builder: no free slot (all N builders busy); use --wait or read the file yourself`).
- `.builder/ask-settings.json` — allow `Read`/`Glob`/`Grep` only; deny `Bash`, `Edit`, `Write`, `NotebookEdit`, `WebFetch` plus the `~/.config/omniscan/**`, `**/.env*`, `**/secrets.env` read rules; `env: CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`.
- `tests/unit/test_omni_builder_ask.py` — 16 tests covering the card's 8 numbered acceptance tests, using a fake `claude` executable (payload + platform shim: `claude.cmd` on Windows, shebang script on POSIX) that records argv/stdin/cwd and plays back a canned stream-json transcript; `LOCK_DIR`/`LOG_DIR`/`SLOTS`/`check_ollama` are monkeypatched, `CLAUDE_BIN` selects the fake.
- `docs/HANDOFF.md` — new section "Looking things up with `ask`" (usage, exit codes, what it may/may not read).

## Deviations
- The card's helper signature list said `run_claude` gets "an optional keyword `settings: Path | None = None`"; I also added the keyword `permission_mode: str = "acceptEdits"` the card describes in the same sentence. Both are keyword-only after `*extra`, so existing positional calls are unaffected.
- Ruff no longer wants `# noqa: F841` on the `slot = acquire_slot()` lines (the ask branch now reads `slot`), so the stale noqa directives were replaced with plain "held until …" comments; behaviour unchanged.
- One test lesson worth recording: a slot handle kept only inside a generator expression (`all(try_acquire_slot() … for …)`) is garbage-collected at once, releasing the Windows file lock — the busy-slot test must bind the handles to a list. Test 3 (`test_try_acquire_slot_cycles_and_acquire_slot_regression`) documents this.
- Not covered by tests: a live `run` regression (test 7 in the card names only `smoke` as the concrete regression); a real `run` in a unit test would create a git worktree, so only `smoke`'s argv is pinned (`--settings …settings.json`, `--permission-mode acceptEdits`, `--max-turns 3`). The `run`/`resume` argv is unchanged by construction (keyword defaults only).

## Questions
- None blocking. One note for the director: two `ask` calls started within the same second would share one log filename (`ask-<UTC seconds>.jsonl`); acceptable because a director rarely runs two asks concurrently, but rename the stamp to include milliseconds if that ever bites.

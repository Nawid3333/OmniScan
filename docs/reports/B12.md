# B12 — Web debug tool: Reader view

## Changes

- `src/omniscan/web/app.py`
  - New helper `output_paths(series, chapter)`: `chapter_paths` plus a check that the resolved
    `output_dir` is under `cfg.paths.output_root` (404 otherwise). `chapter_paths` never checks the
    output root, so a chapter of `..` would otherwise resolve to the output root itself — that is
    rejected explicitly too.
  - `GET /api/series/{series}/chapters/{chapter}/output` → `list[str]` of `list_images(output_dir)`
    file names in natural order, `[]` when the directory is absent.
  - `GET /api/series/{series}/chapters/{chapter}/output/{name}` → `FileResponse` with
    `mimetypes.guess_type(name)[0] or "application/octet-stream"`; 404 when the name contains
    `/`, `\` or `..`, the lower-cased suffix is not in `IMAGE_SUFFIXES`, the file is missing, or the
    resolved path is not inside the resolved `output_dir` (symlink escape → 404).
- `webui/src/api.ts`
  - `listOutput(series, chapter)` and `outputImageUrl(series, chapter, name)` (every segment
    `encodeURIComponent`-ed), same style as the existing wrappers.
  - Added the `filtered?: boolean` field to the `SourceFile` interface (type-only; see Deviations).
- `webui/src/reader.ts` (new): `ScrollMetrics`, the four width constants, `ReaderMode`,
  `scrollRatio`, `scrollTopForRatio`, `clampColumnWidth`, `fitColumnWidth` — pure, DOM-free.
- `webui/src/ReaderView.svelte` (new): fetches `listOutput` on mount/prop change; empty or failing
  list → `no output yet — the export stage has not produced images for this chapter` and nothing
  else. Controls: mode toggle (`final only` / `raw | final`), width slider
  (MIN..MAX step 20, default `DEFAULT_COLUMN_WIDTH`, value shown in px) and the
  `{n} output image(s)` summary. Column width = `fitColumnWidth(mode, sliderValue, viewportWidth)`
  with `viewportWidth` kept in `$state` and updated on `resize`. final-only = one centred scroll
  container (`overflow-y: auto; height: calc(100vh - 140px)`, one `display:block; width:100%`
  `<img>` per name, no `loading="lazy"`). compare = two containers side by side
  (`COLUMN_GAP`); left = raw pages from `getIngest` (files with `filtered !== true`, in order),
  fetched lazily when the mode is first selected; on failure the view shows
  `raw pages unavailable (no ingest.json) — showing final only` and falls back to the final-only
  layout. Linked scrolling: on either container's `scroll`, the other gets
  `scrollTopForRatio(scrollRatio(source), target)`; writes only when the difference is > 1 px and
  the echo event is ignored via a `syncing` flag cleared on the next animation frame.
- `webui/src/App.svelte`: view state extended to `"slicer" | "ocr" | "translation" | "reader"`,
  fourth `Reader` button and `<ReaderView {series} {chapter} />` branch. Nothing else changed.
- `webui/src/reader.test.ts` (new): vitest coverage of the four helpers exactly as the card's
  acceptance cases specify.
- `tests/unit/test_web_app.py`: appended the B12 section — natural-order listing (ignoring
  `notes.txt` and a sub-directory), `[]` for an absent output dir, traversal 404s, exact bytes +
  content types, and 404s for a missing file / `notes.txt` / `..` escapes / backslash / a symlink
  pointing outside the output dir (real JPEG/PNG files written with Pillow into
  `tmp_path/"out"/SERIES/CHAPTER/`).
- `README.md`, `docs/USER_GUIDE.md`: Reader view described next to the existing view text and the
  two new routes added to the `omniscan serve` route list.

## Deviations

- `webui/src/api.ts`: the card says `getIngest`'s `files[]` carry a `filtered` flag, but the
  `SourceFile` TypeScript interface did not have it (the Python schema does:
  `filtered: bool = False`). I added `filtered?: boolean` to the interface — optional, because
  `webui/src/strip.test.ts` (which I may not modify) builds `SourceFile` objects without it. The
  Reader renders files with `filtered !== true`, which behaves as `filtered === false` for real
  artifacts (the JSON always contains the field) and keeps pre-B12 test data valid.
- `src/omniscan/web/app.py`: the output routes reject a chapter value containing `..` explicitly
  in addition to the documented output-root containment check, because `chapter_paths` only
  checks the library/work roots and a bare `..` chapter would otherwise resolve to the output
  root itself. This is required by the acceptance test "`..` in the series or chapter value →
  clean 404".

## Review addendum (director)

Fixed a request loop in `ReaderView.svelte`: the raw-pages effect was guarded by `rawFiles.length === 0`, so a chapter
whose ingest has no unfiltered files (all pages filtered) would refetch `ingest` forever in compare mode. It is now
guarded by a `rawLoaded` flag that is reset per chapter. Not covered by a unit test (no DOM tests in this repo yet).
The rebase onto `main` conflicted in the README status table only (B23 added the queue row); both rows kept.

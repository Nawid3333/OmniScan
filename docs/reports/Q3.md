## New tests

In `tests/unit/test_acquire_mutation_gaps.py` (rules gaps): `test_every_drm_platform_is_pinned_by_name`, `test_www_without_dot_is_a_different_host`, `test_http_urls_look_like_pages`, `test_template_with_first_equal_to_last`, `test_template_bounds_must_be_integers`, `test_template_names_may_not_repeat_without_placeholder`, `test_empty_template_table_is_ignored`, `test_template_name_must_be_a_string`.

Appended to `tests/unit/test_acquire_download.py` (download gaps, placed there to reuse `Server` / `noise_image`): `test_retries_zero_fails_on_the_first_transport_error`, `test_unparsable_retry_after_falls_back_to_the_backoff`, `test_default_retries_covers_three_5xx_responses`, `test_size_exactly_at_the_limit_is_kept`, `test_truncated_body_with_valid_header_is_undecodable`, `test_failure_detail_is_sorted_by_position`, `test_manifest_and_files_are_in_position_order_not_completion_order`.

Notes on two subtleties the gap tests had to expose:
- Mutant 14 (`probe.verify()` dropped): the existing truncated fixture (`noise_image("JPEG")[:40]`) dies inside `Image.open` itself, before `verify()` could matter — the new test truncates a PNG *inside the IDAT payload* (`[:200]`), so the header is intact and only `verify()` rejects it.
- Mutants 29/30 (unsorted manifest / result files): the first-run kills depended on thread-completion timing; the new test makes position 1 provably finish last (two 5xx retries with the real backoff) so the ordering assertions are deterministic.

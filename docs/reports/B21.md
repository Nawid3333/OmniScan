# B21 — Local import (folders/loose files → library layout)

## Changes

New `omniscan.importer` package implementing the second acquisition path, plus one new CLI command.

### New files

- `src/omniscan/importer/__init__.py` — re-exports `plan_import`, `execute_import` and their types.
- `src/omniscan/importer/plan.py` — `ImportPlanError`, `ImportPlanItem`, `ImportPlan`,
  `plan_import(source, *, series, chapter)`. Read-only shape detection over the source's
  immediate children: Case A (single chapter folder: `--chapter` given or the chapter read off
  the folder name via `chapter_number` + `%g` formatting), Case B (folder-of-chapter-folders,
  subfolder order via `list_chapters`, files via `list_images`, `--chapter` rejected as
  ambiguous, `series` defaulting to the source folder's own name), Case C (flat dump: per-file
  `chapter_number` on every image, grouped per distinct number, chapters ascending, files in
  natural order). Mixed shape (subfolder + loose image) and unparseable/unplannable sources
  raise `ImportPlanError`; non-image files become `warnings` (`skipped non-image file: <name>`).
- `src/omniscan/importer/execute.py` — `ImportResult`, `execute_import(plan, library_root, *,
  move=False)`. Copies (`shutil.copy2`) or moves (`shutil.move`) into
  `library_root/<series>/<chapter>/`; existing destinations with identical content
  (`hash_file` from `core/manifest.py`) are idempotent no-ops (with `move=True` the redundant
  source file is still deleted); different content raises `ImportPlanError` naming both paths
  and the count of files already written. Fail-fast, no rollback.
- `tests/unit/test_importer_plan.py` — the 11 acceptance tests for planning, plus one extra
  (`test_case_c_wins_over_case_a_when_folder_has_no_chapter`, see Deviation 2).
- `tests/unit/test_importer_execute.py` — the 5 acceptance tests for execution, plus one extra
  (`test_move_with_existing_identical_destination_deletes_source`, covering the specified
  move+duplicate rule).
- `docs/reports/B21.md` — this report.

### Modified files

- `src/omniscan/cli.py` — added `cmd_import` (registered via `app.command("import")(cmd_import)`,
  same pattern as `doctor`; stubs untouched) with `--series`, `--chapter`, `--move`,
  `--dry-run`; `library_root` from `get_config().paths`; `ImportPlanError` → `import: <msg>`
  on stderr, exit 2. Also added the previously-missing `from pathlib import Path` import the
  new argument annotation needs.

## Deviations

1. **Source paths are resolved.** The card says `ImportPlanItem.files` are absolute source
   paths; `plan_import` calls `source.resolve()` first so plans built from a relative `source`
   still carry absolute file paths (execute can then be called from any cwd).
2. **Case C's mechanical rule vs. test 2.** Case C "always wins over Case A when
   `--chapter`/folder-level chapter is absent and per-file numbers are present": since
   `chapter_number("1.jpg") == 1.0` (the chapter prefix in `core/paths.py`'s regex is optional),
   a folder named `raws` containing bare page numbers (`1.jpg, 3.jpg`) is planned as a *flat
   dump* of `Chapter 1` and `Chapter 3`, not an error. Acceptance test 2 (folder name doesn't
   parse → raise) is therefore satisfied with filenames that carry no digits (`a.jpg`, …),
   which is the only reading that makes tests 2 and 7 consistent. Practical consequence: to
   import bare-numbered pages as one chapter, pass `--chapter`. This is locked in by the extra
   test `test_case_c_wins_over_case_a_when_folder_has_no_chapter`.
3. **Two unplannable all-file edge cases raise `ImportPlanError`** (the card doesn't name them
   explicitly): a source containing no image files at all, and a source whose files' names
   contain no chapter numbers while neither `--chapter` nor the folder name provides one (the
   latter is acceptance test 2 itself).
4. **Loose non-image files in a Case B source** (e.g. a `notes.txt` next to the chapter
   subfolders) are ignored by planning but recorded in `warnings`, consistent with Case A's
   rule; the card only specifies silent skipping for non-images *inside* subfolders (via
   `list_images`), which is unchanged.

## Questions

None blocking. One worth flagging for the record (Deviation 2): if the intent was that
bare-numbered filenames like `1.jpg` should count as *pages*, not per-file chapters, then
Case C's detection rule needs a marker in the regex or the filename (e.g. require an explicit
`ch`/`ep` prefix for Case C grouping) — that's a `core/paths.py` contract question for the
owner, so I implemented the card's detection rule exactly as written.

# B14 — Page-mode passthrough in the slicer

## Changes
- Created `src/omniscan/slicer/page_mode.py`: `slice_by_pages(source_files, strip_width, strip_height) ->
  SlicesArtifact`, one `Slice` per `SourceFile` with `y0`/`y1` copied verbatim, `bands=[]`,

## Deviations
- The card's Definitions implied a single pass that checks order and contiguity together. Taken literally,
  that makes the order check unreachable: once a pair passes the contiguity check, the list is already
  ascending there, and the ascending-order violation can only occur where a gap/overlap violation would fire
  first (for a list that tiles when sorted, the first out-of-order pair is always preceded by a
  gap/overlap pair). Test 8 would then pass only by accident of the gap error also firing. So the
  ascending-`y0` check runs as its own pass **before** the contiguity pass; there is still no sorting
  anywhere, and out-of-order input is rejected without being silently fixed. Test 8 uses
  `[p02, p01, p03]` (tiles correctly once sorted) and gets the "pages out of order" error naming
  `p02.jpg`/`p01.jpg`.
- Error message word order: the gap/overlap size precedes the file names
  (`"gap of 5px between page 'p01.jpg' ... and page 'p02.jpg' ..."`); both file names and the size are
  named, as the card requires.

## Questions
- None blocking. One note: the first-page check (`y0 != 0`) runs after the order check, so an out-of-order
  list whose first file also starts above 0 reports the ordering problem first — both are `ValueError`, so
  this only affects which message the caller sees.

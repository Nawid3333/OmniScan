# F14 — torch-free `load_patches` import path in `inpaint/patches.py`

## Changes

- `src/omniscan/inpaint/patches.py` — moved the module-level `import torch` into a
  `typing.TYPE_CHECKING` guard (for pyright, which resolves the `torch.Tensor` annotations in
  `save_patches`'s signature; `from __future__ import annotations` already makes them lazy strings at
  runtime) plus a local `import torch` inside `save_patches`'s body (runtime, only when that function is
  called). `load_patches`'s body and both functions' logic are unchanged.
- `tests/unit/test_inpaint_patches.py` — added `test_module_import_is_torch_free`: spawns a fresh
  `sys.executable` subprocess (`subprocess.run`, explicit argv list, `timeout=30`, `capture_output=True`)
  that imports only `omniscan.inpaint.patches` and asserts `"torch" not in sys.modules`; the parent test
  asserts `returncode == 0` with `stderr` as the message. `PYTHONPATH` is pinned to this worktree's `src/`
  via `Path(__file__).resolve().parents[2] / "src"` (same pattern as `test_gui_library.py`), because the
  shared `.venv`'s editable install may point at another worktree.
- `docs/reports/F14.md` — this file.

No other file touched. `web/app.py`, `inpaint/stage.py`, `inpaint/lama_stage.py`, `export/stage.py` are
untouched, per the card.

## Tests

- `uv run pytest tests/unit/test_inpaint_patches.py -q` → `5 passed` (4 pre-existing byte-for-byte
  unchanged + the new subprocess test).
- Negative control (run by hand, not part of the suite):
  `python -c "import sys; import torch; import omniscan.inpaint.patches; assert 'torch' not in sys.modules, 'torch leaked'"`
  → exit 1, `AssertionError: torch leaked` — i.e. the subprocess test would fail loudly if torch leaked.
- `uv run pytest -q -m "not gpu"` → all passed (1 pre-existing XFAIL, unrelated file
  `test_hw_hf_mutation_gaps.py`); `web/app.py`'s import of `load_patches` stays green.
- `uv run ruff format . && uv run ruff check .` → clean (`380 files left unchanged`, all checks passed).
- `uv run pyright` → `0 errors, 0 warnings, 0 informations`.

Note on command invocation: plain `uv run` initially failed to run pytest because uv tried to rebuild the
editable install and could not replace the shared `.venv`'s `omniscan.exe` (locked by another running
process; the worktree `.venv` is a symlink to `V:\OmniScan\.venv`). All commands above were therefore run
as `uv run --no-sync ...`; the editable install in the shared venv points at this worktree's `src`
(verified: `omniscan.__file__ == 'V:\\OmniScan-wt\\F14\\src\\omniscan\\__init__.py'`), so this tested the
worktree's code, and the subprocess test additionally pins `PYTHONPATH` to this worktree's `src`. The
`omniscan.exe` rebuild is only the console-script shim and is unaffected by this card's change; any later
`uv sync` on a free venv completes it.

## Deviations

- The local import line carries a `# noqa: F401` suffix: ruff (correctly) sees no runtime use of the name
  `torch` inside `save_patches`'s body — every `torch.Tensor` mention is a lazy annotation string — so the
  bare local import in the card's shape block trips F401 and acceptance-test #4 (ruff clean) would fail.
  The noqa comment uses the repo's existing inline-noqa style (`# noqa: <code> — reason`), same as the
  `# noqa: N812` lines in `lama_pipeline.py`/`warmup.py`. Nothing else differs from the card's shape.

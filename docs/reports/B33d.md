# B33d report — `omniscan acquire` (plan, run, check)

## Changes

- **`src/omniscan/acquire/run.py` (new)** — the Qt-free run loop. `acquire_chapters(plan, series_dir,
  extractor, *, client, max_credits, page_run, apply_filters, on_event) -> list[ChapterOutcome]`
  follows the card's seven behaviour rules: done chapters become `skipped` ("already acquired");
  a credit budget skips this and every later chapter ("credit budget reached");
  `AuthError`/`QuotaError` fail the chapter and mark every later one `stopped: <message>` and stop;
  `ExtractError`/`DrmPlatformError` fail only that chapter; extraction credits accumulate into
  `spent` (`ChapterOutcome.credits` carries the per-chapter charge); `<chapter_dir>/acquire_selection.json`
  (`page_url`, `kept`, `dropped` with reasons, indent 2, UTF-8, `ensure_ascii=False`) is written before
  the download; a filtered-to-nothing page list fails with
  `no page images found (N image(s) on the page were filtered out)`; downloads go through
  `download_chapter` with `ImageRef(url, referer=item.source.url)` and `AcquireError`/`DrmPlatformError`
  fail the chapter keeping partial files and no `accepted.json`; completeness runs `inspect_chapter` +
  `check_pages(median_pages=<median of the other chapters' accepted.json pages when ≥ 3 exist>,
  previous_pages=<nearest earlier accepted chapter>)`; a `failed` verdict fails the chapter with the
  first error finding as its error, `ok`/`review` write `accepted.json`; `on_event` fires for every
  outcome; the function never raises for per-chapter problems.
- **`src/omniscan/acquire/cli.py` (new)** — the `acquire` typer app with `plan`, `run` and `check`.
  `plan` prints the table + `N chapter(s): T to do, D done — estimated credits: C (mode M)` or the
  `--json` payload `{"series": ..., **to_json(plan)}`. `run` shows the NOTICE and plan, exits 0 with
  "nothing to do" when `todo == 0`, confirms `Spend up to C credit(s)?` (declined/EOF → `aborted`,
  exit 2), reads the API key from `get_secrets().extractpics_api_key` (missing/empty → the exact
  `EXTRACTPICS_API_KEY is not set; put it in ~/.config/omniscan/secrets.env` on stderr, exit 2; the
  key is never printed), builds the extractor through the module-level `make_extractor` and the image
  client through `make_image_client` (both test-injection seams), streams one progress line per chapter
  (✓/?/✗/-, ASCII fallback when the stream cannot encode the symbols), prints the
  `ok A, review R, failed F, skipped S — credits used C` summary and exits 1 when any chapter failed;
  `--json` keeps stdout to the final result JSON with all progress on stderr; the image client and the
  extractor (`close` when present) are always closed. `check` is the offline completeness report per
  chapter folder with numbering gaps; exit 1 on any failed chapter, exit 1 for an unknown series.
  Shared source handling: `--urls FILE|-`, `--link` (repeatable, `--first-number`), `--template
  --first --last [--name]`, else `sources.toml` via `sources_path` + `load_sources`; at most one
  source group (exit 2); missing sources → `no chapter sources: give --urls, --link, --template or
  create <path>` (exit 2); DRM URLs exit 2 naming the platform; every `ValueError`/`OSError` prints
  on stderr and exits 2.
- **`src/omniscan/cli.py`** — removed `acquire` from `_STUB_COMMANDS`, deleted `cmd_acquire`, and

## Deviations

- The card's example table message says `5 chapter(s): 3 to do, 0 done — estimated credits: 3` for a
  template of five chapters with `--select 2-4`. In the shipped implementation `build_plan` receives
  only the **selected** sources (selection filters before planning, as B33c's `select_chapters` is
  applied upstream), so `N` in the summary is the number of table rows (3), which keeps the summary
  consistent with the table above it. The estimate value (`3`) matches the card exactly.
- `download_chapter` names kept pages `001.jpg`, `002.jpg`, … (3 digits, `max(3, digits of the page
  count)`) rather than the card's illustrative `0001.jpg`; that naming is B33b's downloader contract
  and is not changed here.
- `tests/unit/test_docs.py` was edited beyond the card's listed files: its stub-example test asserted
  `omniscan acquire DemoSeries` errors with "stub", which cannot hold once `acquire` is a real group
  (the card requires `test_docs.py` to stay green). The test now exercises the still-existing
  `reference` stub; behaviour and assertion strength are unchanged.
- The per-chapter progress line uses `?` for `review` and `✗` for `failed` (card's marker table), with
  ASCII fallbacks (`review`, `FAILED`) when the output stream cannot encode the symbols.

# B34 — `omniscan usage`: aggregate LLM token/request usage per chapter/series

## Changes

- **`src/omniscan/usage.py`** (new) — pure aggregation, no typer imports:
  - `UsageRow` frozen/slots dataclass (`series`, `chapter`, `source`, `model`, `usage`) exactly as
    the card pins it.
  - `collect_usage(cfg, series=None)` — walks `work_root`; series sorted by name (casefold), chapters
    in reading order (`natural_key`), within a chapter the `translations/*.json` rows first
    (alphabetical, dot-prefixed partials skipped — same rule as `judge_chapter._load_runs`), then the
    `final.json` judge row last (`source="judge"`, `model=judge_model`). Chapter/series dirs starting
    with `_`/`.` are skipped. An artifact whose `usage` is missing or empty yields a row with
    `usage == {}` (legacy = zeros, never an error); a file that fails to load (invalid JSON, schema
    validation) is skipped silently.
  - `totals(rows)` — generic element-wise sum of every usage key present in any row; `{} for []`.
- **`src/omniscan/translate/judge_chapter.py`** — the done path now populates `FinalArtifact.usage`
  from the `JudgeStats` it already holds, in the pinned key order: `prompt_tokens`,
  `completion_tokens`, `requests`, `repair_requests`, `regions`, `seconds`, `rate_limited` — every
  value `float(...)`, `rate_limited` via `float(stats.rate_limited)`. No pipeline metrics
  (`judged`/`auto_picked`/`untranslated`/`violations_left`) are added. The accepted minimal
  `assert stats is not None` was **not** needed: `stats` is unpacked from `judge_regions`'s
  non-optional return, so pyright narrows it fine.
- **`src/omniscan/cli.py`** — `@app.command("usage")` on the top-level app, per the card's exact
  signature; unknown series (not a dir under `work_root`) echoes to stderr and exits 2 (the
  no-chapters exit-2 pattern used across the CLI); `--json` prints `{"rows": [asdict(row)...],
  "totals": totals(rows)}` with `indent=2` and nothing else on stdout; the table prints
  `SERIES CHAPTER SOURCE MODEL PROMPT COMPLETION REQUESTS SECONDS` (text columns left-aligned,
  numbers right-aligned, widths fitted to the content), one line per row then a single `TOTAL` line;
  `PROMPT`/`COMPLETION`/`REQUESTS` print `int(x)` when whole, else the float (`cmd_translate`'s echo
  style), `SECONDS` prints one decimal. Helpers `_usage_count` / `_usage_lines` stay private to the
  CLI.
- **`tests/unit/test_usage.py`** (new) — the card's tests 2–8 (one test each, CLI tests via
  `CliRunner` + `monkeypatch.setattr(omniscan.cli, "get_config", ...)`; fixtures follow the
  `test_filter_cli.py` cfg pattern).
- **`tests/unit/test_judge_chapter.py`** — added `test_judge_chapter_records_usage` (test 1) using
  the file's existing `write_ocr`/`disagreeing_runs`/`FakeClient` fixtures; asserts the saved
  `final.json`'s usage key set (in order) and every value, with `seconds` via
  `pytest.approx(stats.seconds)` (the only nondeterministic value).
- **`docs/USER_GUIDE.md`** — new `### omniscan usage` section right after `omniscan judge`, with an
  argument table, exit behaviour, and fenced examples using the real command/flag names
  (`omniscan usage SoloLeveling`, `omniscan usage --json`).

```

SERIES        CHAPTER    SOURCE            MODEL             PROMPT  COMPLETION  REQUESTS  SECONDS
SoloLeveling  Chapter 1  gemma4-12b-local  gemma4:12b        123456        9876        12     42.5
SoloLeveling  Chapter 1  judge             gemma4:31b-cloud    5000        1200         3     11.2
```

(`--json` `totals` sums every stored key — `regions`, `missing`, `rate_limited` included — while the
table shows only the four display columns, per the card.)

## Deviations

None against the card's pinned interfaces, ordering, legacy/corrupt rules, key sets or exit codes.
Two presentation judgement calls the card left open, noted for the director:

- The header line is printed only when there is at least one row — the card pins "print only the
  TOTAL line" for the empty case, so the header cannot be unconditional.
- Table column widths are fitted to the content (the card pinned column order/format, not widths).

## Questions

1. **Pricing/budget caps (out of scope here, needs an owner decision).** The report intentionally
   shows only tokens/requests/seconds. A budget-cap card needs an owner-supplied price table (per
   model or per profile — cloud vs local differ wildly) and a decision on whether cost should live
   in the artifacts at write time or be joined at report time from a config file.
2. Should usage ever surface in the web viewer / GUI (card lists it as out of scope)? If wanted, the
   natural surface is the web UI's Translation view header, fed by a read-only API endpoint over
   `collect_usage`.

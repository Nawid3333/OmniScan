# B9 — Glossary store (SQLite + YAML, alias/particle matcher)

## Changes
- `src/omniscan/glossary/__init__.py` (new): package exports (`GlossaryStore`, `Match`, `KOREAN_PARTICLES`,
  `find_terms`, `term_present`, `export_yaml`, `import_yaml`).
- `src/omniscan/glossary/store.py` (new): `GlossaryStore` — sqlite3 with `journal_mode=WAL` +
  `foreign_keys=ON`, auto-created `glossary` table (one column per `GlossaryEntry` field except `id`;
  `aliases` stored as JSON TEXT). `add`/`get`/`update`/`delete`/`list`/`find_by_source` exactly per the card
  contract (`ValueError` on bad `id` use, `KeyError(entry_id)` on unknown id, `model_copy` for the returned
  copy, deterministic `ORDER BY id`). `close()` is idempotent via a `_closed` flag; context-manager support.
- `src/omniscan/glossary/yaml_io.py` (new): `export_yaml` (all statuses, id ascending, plain dicts via
  `model_dump(mode="json")`, `yaml.safe_dump(sort_keys=False, allow_unicode=True)`, atomic tmp+`replace`) and
  `import_yaml` (`merge` updates in place by exact `source` match keeping the existing row id, `replace`
  deletes all rows then re-inserts ignoring file ids; returns entries written).
- `src/omniscan/glossary/match.py` (new): `KOREAN_PARTICLES` exactly as specified (glued pair forms included);
  lookup tries particles longest-first (stable sort of the tuple) so `에게`/`에서` beat `에`. `find_terms` is a
  greedy left-to-right non-overlapping scan: candidates (entry.source then aliases) pre-sorted longest-first
  with ties broken by entries list order, then source-before-alias — deterministic, no hashing involved. One
  particle max per match. `Match` dataclass per contract. `term_present` is a plain substring check on
  `entry.target`.
- `src/omniscan/cli.py` (modified): removed `cmd_glossary` and `"glossary"` from `_STUB_COMMANDS`; added
  `glossary_app` Typer sub-app mounted with `app.add_typer(glossary_app, name="glossary")` — `list`
  (rich table, `--status`, exit 2 with clear message when the db is missing), `export`, `import`
  (`--mode merge|replace`; exit 2 when glossary.yaml is missing). No other commands touched.
- `pyproject.toml`: added `pyyaml>=6.0` (the one allowed exception), ran `uv sync`.
- Tests: `tests/unit/test_glossary_store.py` (13), `tests/unit/test_glossary_yaml_io.py` (5), 
  `tests/unit/test_glossary_match.py` (10) — all 19 acceptance points covered, plus extra edge cases
  (glued pair particle `이가` preferred over its halves, alias+particle, length-tie entry-order determinism,
  non-overlap scan resume, case-sensitive `term_present`, id-less entry rejection in `find_terms`).

## Deviations
- `GlossaryStore` keeps the connection non-Optional with a `_closed` flag instead of nulling it in `close()`,
  so using the store after close raises the natural `sqlite3.ProgrammingError` (asserts would have turned
  that into `AssertionError`). `close()` twice is still safe per the card.
- `find_terms` raises `ValueError` for entries whose `id` is None (`Match.entry_id` is `int` per the frozen
  contract; store-produced entries always have ids). Documented in the docstring and tested.
- `glossary import` exits 2 when `glossary.yaml` is missing (the card specifies exit-2-on-missing-db only for
  `list`; the same convention applied to the import file seemed obviously intended, not a behavior change).
- Row→entry conversion uses `GlossaryEntry.model_validate(dict)` instead of `GlossaryEntry(**dict)` to keep
  pyright clean (sqlite rows are untyped); identical behavior, plus validation of what comes out of the db.

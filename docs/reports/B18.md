# B18 — extract.pics webhook relay

## Changes

Created the Cloudflare Worker relay under `relay/` and the GitHub Action deploy
workflow.

### New files

- `relay/package.json` — project scripts and dev dependencies.
- `relay/package-lock.json` — resolved dependency tree.
- `relay/tsconfig.json` — strict TypeScript, Workers + Vitest types.
- `relay/wrangler.jsonc` — Worker `omniscan-relay`, `compatibility_date`
  `"2026-09-01"`, `compatibility_flags: ["nodejs_compat"]`, Durable Object
  binding `HUB` → `EventHub`, migration `v1` with `new_sqlite_classes`.
- `relay/vitest.config.mts` — vitest-pool-workers config with test bindings
  `HOOK_SECRET="test-hook-secret"` and `CLIENT_TOKEN="test-client-token"`, and
  `isolatedStorage: false` (see Deviations).
- `relay/src/types.ts` — shared types and allowed hook types.
- `relay/src/hub.ts` — `EventHub` Durable Object: SQLite schema, hook ingestion,
  event pagination, ack, WebSocket hibernation, broadcast, and 14-day retention
  alarm.
- `relay/src/index.ts` — Worker entry point, constant-time bearer auth, routes
  all traffic to the single `EventHub` instance.
- `relay/test/env.d.ts` — augmentation of `cloudflare:test` `ProvidedEnv`.
- `relay/test/relay.test.ts` — 12 acceptance tests covering all API behaviors.
- `relay/README.md` — deploy instructions, webhook URL format, client API.
- `.github/workflows/relay-deploy.yml` — deploy workflow with typecheck, test,
  conditional deploy, and secret upload.
- `docs/reports/B18.md` — this report.

## Deviations

1. **Dependency versions.** The card lists `wrangler`, `vitest`,
   `@cloudflare/vitest-pool-workers`, `@cloudflare/workers-types`, and
   `typescript` without pinning. `npm install` today resolved to the versions
   committed in `package-lock.json`. To avoid type conflicts between Wrangler
   4.135.0 (which depends on `@cloudflare/workers-types` v5) and the version of
   Wrangler required by `@cloudflare/vitest-pool-workers` (4.35.0, which depends
   on workers-types v4), `package.json` pins `wrangler` to `~4.35.0` and
   `@cloudflare/workers-types` to `^4.20260702.1`. This keeps the type
   definitions consistent and all tests passing.

2. **`isolatedStorage: false`.** With the default per-test isolated storage,
   vitest-pool-workers failed to pop the Durable Objects storage stack frame
   after the first SQLite-accessing test, reporting that it expected a `.sqlite`
   file but found the `.sqlite-shm` file. Disabling isolated storage lets the
   suite run. The test file was adjusted to clear events at the start of tests
   that need a clean slate and to avoid hard-coding sequence numbers.

3. **Compatibility-date runtime warning.** Wrangler/miniflare warns that the
   installed local runtime does not support `2026-09-01` and falls back to
   `2025-09-06`. The `wrangler.jsonc` still contains the exact requested date;
   the warning only affects local tests and will not affect production deploy
   once the runtime supports it.

4. **Type import for `DurableObjectState`.** `cloudflare:workers` does not export
   a `DurableObjectState` type directly, so `src/hub.ts` derives it via
   `ConstructorParameters<typeof DurableObject>[0]`. The resulting class works
   at runtime and passes typecheck.

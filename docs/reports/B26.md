## Deviations

- The card's example environment used `mktemp -d`; this session is sandboxed to the worktree, so the
  throw-away directory was `.tmp-demo/` inside the worktree, deleted after the run. Nothing in `.tmp-demo/`
  is committed.
- `typer` in this lockfile vendors its own `click` (`typer._click`), so `typer.main.get_command(...)`
  does NOT subclass the PyPI `click` package's `Group`. The test therefore uses
  `isinstance(x, typer.core.TyperGroup)` instead of `click.Group` for the group/subcommand rule
  (behaviour is identical). `_check_stub` reads `help` via `getattr` so it works for both group and
  command objects under pyright's standard mode.
- USER_GUIDE's folder-layout table adds one entry the card didn't name: `work_root/<Series>/watermarks.json`
  (written by `watermark add`/`remove`), verified during the example run.

## Questions

- `work_root/<series>/series.db` is required by all three `glossary` sub-commands (exit 2 without it),
  but no command today creates it — glossary seeding belongs to a pipeline stage that hasn't landed.
  USER_GUIDE documents this honestly ("no command creates it yet"); flag if a later card wants the
  glossary commands to bootstrap the db instead.
- `omniscan import` has no `--move`-and-`--dry-run` interaction problem, but `pack` reads
  `output_root/<series>/<chapter>/*.jpg`, which stays empty until the export stage exists — so `pack`
  is only usable on hand-placed finished images today. Documented in the `pack` section; flag if the
  status table should instead call `pack` "working (no producer yet)".

# S2 — Slicer strategies and a compare mode

## Changes

- **`src/omniscan/slicer/strategies.py`** (new): `STRATEGIES`, the dispatcher
  `slice_with_strategy(strip, cfg, source_files=None, *, strategy=None)`, the three new strategies
  `slice_page`, `slice_fixed`, `slice_simple_gutter`, and `gutter_cut_rows` (the centre row of every
  maximal gutter run — public because the card's golden test pins the run centres
  `[2920, 5050, 8025]`, which are not all recoverable from the artifact). A private `_finalize`
  builds every non-smart artifact: blank flags from `row_stats(strip, cfg.uniform_tol).uniform`,
  `source_files` overlap mapping, `bands=[]`, `params = {**cfg.model_dump(), "strategy": <name>}`.
  All row math is tensor ops (`.mean(0)`, `.var(dim=1)`, `diff` on the padded bool mask); the only
  Python loops are over runs/cuts.
- **`src/omniscan/slicer/compare.py`** (new): `StrategySummary` (frozen dataclass),
  `compare_strategies` (dict in `strategies` order), `summarize` (height stats, forced/blank
  counts, `cuts` = y of every internal boundary; all zeros/empty for an empty artifact).
- **`src/omniscan/slicer/__init__.py`**: exports `STRATEGIES`, `slice_with_strategy`,
  `slice_fixed`, `slice_page`, `slice_simple_gutter`, `gutter_cut_rows`, `StrategySummary`,
  `compare_strategies`, `summarize`.
- **`src/omniscan/slicer/stage.py`**: `SliceStage.run` calls `slice_with_strategy(strip,
  ctx.cfg.slicer, ingest.files)`; version bumped 2 → 3 (`# 3: strategies`); metrics unchanged.
- **`src/omniscan/cli.py`**: one new command `slice-compare` next to `slice` (nothing else touched).
  Resolves the chapter (default: first in reading order; unknown series/chapter → stderr, exit 1),
  runs `IngestStage` through `make_context` only when `ingest.json` is missing (so `series.toml`
  `[slicer]` overrides are honoured via `ctx.cfg`), builds the strip exactly as `SliceStage` does
  (`load_strip`), runs `compare_strategies` over all four strategies and prints the table or, with
  `--json`, `{"series", "chapter", "strip_height", "strategies": [asdict(StrategySummary)...]}`.
  Nothing is written to the work dir (no `slices.json`).
- **`docs/USER_GUIDE.md`**: `omniscan slice-compare` command section + a "Slicer strategies"
  subsection (the four strategies and the knobs each one reads).
- **Tests** (new): `tests/unit/test_slicer_strategies.py` (dispatcher, fixed examples incl. tail
  merge, simple_gutter golden + window/tie/threshold/short-run/60k pins, page boundaries/fallback/
  propagated tiling errors, 24-seed four-strategy tiling property, stage wiring incl. `series.toml`
  and version 3 + config hash), `tests/unit/test_slicer_compare.py` (order/keys, unknown-name
  propagation, summarize medians/counts/cuts/empty/frozen), `tests/unit/test_slicer_compare_cli.py`
  (table rows, `--json` shape, default chapter, `series.toml` honoured, nothing written, unknown
  series/chapter exit 1).

## Deviations

1. **`gutter_cut_rows` is a new public function** (not in the card's interface list): the golden
   test pins the gutter cut rows `[2920, 5050, 8025]`, but `8025` is never used as a slice
   boundary, so it must come from the run finder itself. Exported from `slicer/__init__`.
2. **`slice_page` is public** (same shape as `slice_fixed` / `slice_simple_gutter`) though the card
   listed only the dispatcher and the two baseline functions; all four strategies are exported for
   symmetry. Nothing outside the card's file list was touched.
3. **Page fallback params**: on fallback the artifact records
   `params = {**cfg.model_dump(), "strategy": "page", "fallback": "smart"}` — `strategy` keeps the
   requested name so the card's property test (`params["strategy"] == name` for all four over
   `random_strip`) holds, while `fallback` records that the cuts actually came from `smart`
   (including smart's bands; the card does not pin bands for the fallback case).
4. **`fixed` flags for H=10000**: the card's example lists boundaries
   `[0,3000) [3000,6000) [6000,10000)`; with the definition's `while H - pos > target` loop the
   1000-row tail after the cut at 9000 merges back, so the last slice keeps its own (forced) flag —
   `True, True, True`. H=9000 gives the card's `True, True, False`.

## Questions

1. **Fallback params/bands** (deviation 3): is `strategy: "page"` + `fallback: "smart"` the record
   you want, or should the fallback stamp `strategy: "smart"` instead? The property test implies
   the former; keeping smart's bands in the fallback artifact was the other judgment call there.
2. **`series.toml` strategy errors**: an unknown strategy name in `series.toml` fails
   `SlicerConfig` validation (`SeriesConfigError` from `series_config`) — good. But a *valid*
   strategy that then fails per chapter (e.g. `page` on a strip whose files do not tile it) fails
   the chapter; `slice-compare` would propagate that `ValueError` as a crash. Acceptable, or should
   `slice-compare` catch per-strategy errors and mark the row as failed?
3. **`fixed`'s merge rule and `simple_gutter`'s lack of one** are implemented exactly as specified;
   the two strategies therefore disagree at the tail (e.g. H=6500: `fixed` → 2 slices,
   `simple_gutter` → `[0,3000) [3000,3500)` is impossible, it stops at max_height and emits the
   short remainder as its own slice). Intended as baseline semantics — no change requested.

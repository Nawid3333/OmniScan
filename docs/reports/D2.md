# D2 — Detect: reject an implausibly oversized bubble when pairing text with its speech bubble

## Changes

- `src/omniscan/detect/postprocess.py` (only `_items` + one new constant):
  - New constant `_MAX_BUBBLE_TO_TEXT_AREA_RATIO = 8.0` directly below `_TEXT_IN_BUBBLE_MIN_IOA`, with
    the card's comment. `ruff format` wrapped it into a parenthesised 3-line block because the line
    (constant + comment) exceeds the repo's line length; value and comment unchanged (same thing
    happened to D1's `_CROSS_CLASS_CONTAIN_IOA`).
  - The `_items` pairing loop's `candidates` comprehension gained a second, conjunctive condition:
    `area(b.box) <= _MAX_BUBBLE_TO_TEXT_AREA_RATIO * area(tb.box)`, alongside the unchanged
    `ioa(tb.box, b.box) >= _TEXT_IN_BUBBLE_MIN_IOA`. Both must hold. Everything downstream is
    byte-for-byte unchanged: with candidates remaining, the smallest by area still wins
    (`min(candidates, key=lambda c: area(c[1].box))`); with none remaining, the text falls through the
    existing `if not candidates:` branch to the no-bubble path (`bubble=None`) — the same path a text
    with zero nearby bubbles takes today. `_TEXT_IN_BUBBLE_MIN_IOA`, `ioa`/`area`/`iou`,
    `merge_bubble_text`'s grouping, and the D1 cross-class-duplicate loop above it were not touched.
- `tests/unit/test_detect_postprocess.py` (extended; nothing removed or edited):
  - Import line gains `area` (used to pin ratios in the new tests).
  - `test_build_regions_rejects_oversized_only_bubble_solo_leveling_pair` — the exact real pair from
    the card: `text_bubble (226, 11896, 539, 12010)` score 0.7 vs `bubble (52, 11488, 710, 12098)`
    score 0.9. Asserts the pinning shape (`ioa(tb, bubble) >= 0.6` — the old rule's only bar — and
    `area(bubble)/area(tb) > 8.0`) and that `build_regions` emits exactly one region — `bubble_text`,
    confidence 0.7, `bubble_bbox is None` — the same assertion shape as the existing
    "no nearby bubble" test (`test_build_regions_text_without_bubble_and_cross_class_duplicate`).
    The real ratio is 401380 / 35682 ≈ 11.25, inside the evidence gap [8, 11).
  - `test_build_regions_still_pairs_text_when_oversized_bubble_has_a_normal_rival` — the same
    oversized bubble plus a second candidate `bubble (206, 11876, 559, 12030)` (ratio ≈ 1.52, IoA 1.0);
    the text must pair with the normal-sized one. Proves the fix does not fail open to "no bubble"
    whenever an oversized candidate exists.
  - `test_build_regions_keeps_legitimate_bubble_well_under_the_area_ratio` — a bubble exactly 5x its
    text's area (200×100 vs 100×40), only candidate, IoA 1.0, still pairs with it. Proves this is not
    a general "always prefer a smaller bubble" change.
- Nothing else: `detect/stage.py`, `detect/tiles.py`, `core/**`, config and data files untouched.

`_MAX_BUBBLE_TO_TEXT_AREA_RATIO` monkeypatched to 1e9 (reproducing pre-fix behaviour), the regression
test **fails** (the text pairs with the oversized bubble, `bubble_bbox = 52,11488,710,12098`) while
the "normal rival" and "5x legitimate" tests return the same results with and without the constant —
so the regression test cannot pass without the fix, and the other two do not depend on it.

## Deviations

- `ruff format` wrapped the new constant into a parenthesised multi-line form (repo line length);
  content is exactly the card's snippet otherwise.
- Pyright's standard mode rejects `region.bubble_bbox.x0` without a None guard (`bubble_bbox` is
  `BBox | None`), so the "normal rival" test asserts `region.bubble_bbox is not None` before its
  attribute checks (the 5x test already did so by construction). The 4 `reportOptionalMemberAccess`
  errors were the only pyright findings; none elsewhere.
- The oversized-pair tests supply their own `Slice(index=0, y0=11000, y1=12500)` instead of the
  module's `_slices()` fixture, as D1's Solo Leveling test did: the real pair sits at strip
  y≈11.5k–12.1k, and the fixture's layout would place the text's centre in its *blank* middle slice,
  where `build_regions` drops everything and the test would pass vacuously.

## Questions

- None blocking. One observation for the director, out of scope here: the cap scales with the *text*
  box's own area, so a very small `text_bubble` box (e.g. a one-character exclamation, ~10³ px²)
  shrinks the acceptable bubble ceiling with it (8×10³ px² ≈ a 90×90 bubble). If a legitimate pairing
  with a tiny text box ever renders unpaired after this change, that interaction is the first place
  to look — the six-chapter evidence had no such case (ratios 0.9–7.9 across 225 pairings), so no
  incident is known. Boundary semantics are inclusive (`<=`): a pairing at exactly 8.0 still pairs.

# U6 — Updater core: find, download and verify a newer OmniScan release

## Changes

Created (`src/omniscan/update/`):

- `__init__.py` — empty package marker, as the card asked.
- `version.py` — `Version` (frozen/slots dataclass with `major/minor/patch/pre` and a `__str__`

  `download_update()` (fetches `SHA256SUMS` first, streams the asset to `<updates_dir>/<tag>/<name>.part`
  while hashing with a `(done, total|None)` progress callback, deletes the `.part` on any failure,
  verifies the SHA-256 and `Path.replace()`s it to `<name>`, writes `staged.json` with
  `{"tag","version","asset","sha256","downloaded_at"}`, reuses an already-staged file with a matching
  checksum without requesting the asset again; checksums are still fetched).

## Deviations

- `os.replace` → `part.replace(...)`: `Path.replace` calls `os.replace` (same atomic
  rename-on-same-volume semantics); ruff rule PTH105 requires the `Path` form, so the code keeps the
  card's intent (atomic replace) in the form the linter wants.
- Added `Version.__str__` (the CLI and `staged.json` need a plain rendering of a version; the card's
  JSON example shows `"current": "0.1.0"`, not a dataclass repr). Additive only.
- `check --json` reports `"asset": null` (instead of failing) when a newer release exists but has no
  build for this platform — the card's JSON shape says `"asset": name|null`; text `check` output
  never touches assets.
- `check_for_update`'s `channel` parameter is `str` per the card's signature; the `Literal` value for
  `latest_release` is produced with a `cast` (the CLI restricts it to stable/beta through a typer
  `StrEnum`).

## Questions

- None blocking. For later cards: U4 (GitHub Actions) must publish app tags `vMAJOR.MINOR.PATCH` with
  assets named `omniscan-<platform_key>.zip` plus a `SHA256SUMS` file (sha256sum format, digest then
  two spaces or `*` + asset name) — the updater's contract depends on exactly those two names.
- The staged.json schema is deliberately minimal (`tag`, `version`, `asset`, `sha256`,
  `downloaded_at`); the replace/restart cards (U4/U5) may want the release's `published_at` or notes
  in there — cheap to add later without breaking readers (they should ignore unknown keys).

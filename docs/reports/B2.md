# B2 — Turbo (CPU baseline) JPEG codec backend + benchmark harness

## Changes

- `src/omniscan/gpu/codec/turbo.py` (new): `TurboCodec` implementing the `JpegCodec` contract per the card —
  Pillow/libjpeg-turbo decode on a `ThreadPoolExecutor`, pinned-memory staging upload to GPU, single pinned
  staging buffer reused across the `decode_into` loop, `encode` via `Image.fromarray(...).save(...)` with
  `optimize=False`. `info()` is header-only (`PIL.JpegImagePlugin.get_sampling` with the `img.layer` fallback
  and `"400"` for single-band images). `close()` is idempotent and the pool is **lazily recreated** on the
  next decode (documented in the module and `close` docstrings).
- `tests/unit/test_codec_turbo.py` (new): all 8 acceptance tests from the card (10 test functions — added
  grayscale/progressive-free coverage where it fell out naturally). GPU-dependent tests marked `pytest.mark.gpu`.
- `scripts/bench_codec.py` (new): argparse CLI exactly as specified; writes the markdown table to stdout and
  appends it to `docs/benchmarks/codec.md` (creating the file with a one-line header first).
- `tests/fixtures/images.py`: **not modified** — card B3 already landed `plain_jpeg` (and `rotated_jpeg`),
  which covered everything the tests needed.
- `docs/benchmarks/codec.md` (new, generated by the bench script): the card's file list doesn't name it, but
  the bench-script spec requires the script to write it; committed as a generated artifact.


Bench (`uv run python scripts/bench_codec.py --n 50`, synthetic 800×1400, turbo on cuda:0):

| backend | images | wall (s/decode) | Mp/s | peak GPU (MiB) | CPU % |
|---|---|---|---|---|---|
| turbo | 50 | 0.379 | 147.9 | 3 | 3291% |

CPU % ≈ 3300% confirms the decode is fully parallel across worker threads (GIL released in libjpeg-turbo);
this is the number for card C2's `hybrid` backend to beat on wall time.

## Deviations

- Card's interface says `info` reports `width, height = img.size`; for an EXIF-rotated JPEG that is the
  **stored** (pre-orientation) size, while `decode()` applies `exif_transpose`. That asymmetry is inherent in
  the contract (header-only parse), not a deviation — a test pins it down.
- The pinned-memory staging in `decode_into` copies each `[3, h, W]` slice into a slice of the shared pinned
  buffer and then copies that to the GPU with `non_blocking=True`, matching the card. The "peak GPU memory"
  bench column therefore reports only the delta after the strip was preallocated (≈ the staging buffer),
  since the strip itself is allocated before `reset_peak_memory_stats()`.

## Questions

- None blocking. One note for C2: torch emits a one-time "NumPy array is not writable" `UserWarning` on the
  first `torch.from_numpy(np.asarray(img))` under Pillow 12 (the decoded array is read-only). It is harmless
  (the data is copied by `.contiguous()`/`copy_` immediately after), but C2 may want `np.array(img)` if it
  wants warning-free output.

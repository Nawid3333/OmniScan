# B31 — Duplicate / near-duplicate chapter detection within one chapter set

## Changes

- `src/omniscan/match/chapters.py`: `_chapter_qualities` renamed to public `chapter_qualities`
  (no signature or behaviour change); its one call site in `match_chapters` updated. Everything
  else in the file untouched (`_read`, `_chapter_match`, `_add_runner_ups`, `_best_other` stay
  private).
- `src/omniscan/match/duplicates.py` (new): `DuplicateThresholds` / `DuplicatePair` /
  `DuplicateReport` models and `find_duplicate_chapters(root, thresholds=None)` exactly per the
  card's implementation shape — `list_chapters(root)`, `chapter_hashes` per chapter, the chapter
  set passed as both sides into the now-public `chapter_qualities` (its `Thresholds` built from
  the `DuplicateThresholds` knobs; `chapter_gap`/`review_quality` left at defaults, unused —
  confirmed `chapter_qualities` never reads them), `i < j` pairs only, quality rounded to 4
  decimals, sorted by `(-quality, a, b)`, `ValueError("no chapter folders with page images under
  {root}")` when the root has no chapter folders.
- `src/omniscan/match/cli.py`: new `match duplicates` command mirroring the `chapters` command's
  style (`Annotated` options, refuse-overwrite wording, `ValueError` → echo + `Exit(2)`,
  `--json` vs `_duplicates_summary`, `"match: "` echo prefix). `DEFAULT_DUPLICATES_OUT =
  "chapter-duplicates.json"`. The summary prints
  `match: <n> likely duplicate pair(s) -> <dest>` then one `match:   'a' <-> 'b' quality q.qq`
  line per pair in the artifact's (already sorted) order.
- `tests/unit/test_match_duplicates.py` (new): 8 CPU tests — exact-duplicate pin (exactly one
  pair, quality exactly `1.0`, "Chapter 002" absent), three well-separated chapters → no
  duplicates, no self-pairs + the identical-trio pair set (each of three copies pairs with the
  other two, `a` always natural-sort-earlier, all qualities 1.0), two equal-quality pairs tie-break
  by ascending `(a, b)`, an empty chapter folder never appears in a pair, only-empty-folders → no
  duplicates, chapter-less root raises with the exact pinned message (asserted as `str(exc) ==
  f"..."` because `pytest.raises(match=...)` cannot take a Windows path containing `\U`), custom
  thresholds reach the run and the report (min_quality 1.1 → no pairs).
- `tests/unit/test_match_cli.py` (extended): 6 new CLI tests following the existing `chapters`
  pattern — writes + summarises, default `chapter-duplicates.json` + `--json` prints the full
  report, refuse-overwrite (`--force` cycle, exit 2, file untouched), zero-pairs summary, empty
  root exit 2, threshold flags reach the artifact.
- `docs/USER_GUIDE.md`: new `### omniscan match duplicates` section right after the
  `omniscan match chapters` section — what it is for (accidental duplicate imports within one
  set, not cross-set matching), why the default `--min-quality 0.9` is deliberately high vs the
  matcher's 0.3, option table, and the hand-editable-JSON note. `tests/unit/test_docs.py`
  validates documented commands against the real CLI and is green.

  `a == b`") is tested over the 3-copy set plus the pinned exact-duplicate set; the third copy is

  `Chapter 001 copy`, so the pair set is asserted accordingly.

  docstring matches the card verbatim.

  implementation already green (code + tests + docs), and the report lands in the final commit.

## What changed (files)

- `src/omniscan/gpu/timeline.py` **new** — `mark(name)` / `format_table(marks)`; enabled with `OMNISCAN_TIMELINE=1` (stderr at exit) or a file path. Committed early (`83f38ba`), with `tests/unit/test_gpu_timeline.py`.
- `src/omniscan/gpu/vram.py` — **prefetch machinery**: `prefetch(group)` queues a background load; a **single worker thread** (`_prefetch_run_all`) runs queued loaders one at a time in request order and **waits for the first `acquire`** (`_first_acquire` event) so no MIOpen find overlaps the startup decode; `acquire` adopts finished prefetches (`_take_prefetch`), falls back to the synchronous load on failure; `first_acquire_event` property exposes the gate. **Evict-skip**: `_ensure_vram` evicts a resident local Ollama LLM only when a load would leave less than `est + 4 GiB` free (`_EVICT_MARGIN_GIB = 4.0`; CPU/MPS with no VRAM info keeps the always-evict behaviour).
- `src/omniscan/pipeline/runner.py` — `_prefetch_groups(gpu, passes, cfg, client)` queues every GPU group **except the first** (a first-group prefetch is net-negative: its loader competes with the startup decode), skips `OLLAMA_GROUP` and schedulers without `prefetch`; gated off when `cfg.gpu.warmup` is false. `TimedStage` wraps every stage with timeline marks.
- `src/omniscan/gpu/warmup.py` — the warm-up thread **gates on `first_acquire_event`** (`start_warmup(device, gate=...)`): the MIOpen find no longer overlaps the startup decode.
- `src/omniscan/gpu/groups.py` — wires the gate into the warm-up start.
- `src/omniscan/inpaint/lama.py` — LaMa's two warm-up forwards (its MIOpen find) run with **no lock**, i.e. as early as the prefetch worker can reach them, behind the vision pass. (A `miopen_lock` serialising them against the warm-up thread was tried and removed — see "What did not help".)
- `src/omniscan/gpu/codec/turbo.py` — `decode_into` builds **one pinned mirror of the whole strip and issues a single contiguous H2D copy** (CPU path unchanged).
- `src/omniscan/ingest/strip.py` — byte reads hoisted before the decode + timeline marks.
- `scripts/measure_run.py` **new** — fresh-child wall-clock measurer for the exact card command (`--runs`, `--stages`, `--models-dir`, `--env KEY=VALUE`).
- `scripts/hash_outputs.py` **new** — sha256 of a series' export folder (bit-identicality evidence).
- `scripts/probe_warmup_lock.py` **new** — the diagnosis probe: during the warm-up's 8.1 s `conv3x3`, a Python loop, contiguous pinned/pageable H2D and a 180 MiB pinned alloc all take 0.00–0.07 s (no GIL, no driver lock).
- `tests/unit/test_gpu_vram.py`, `test_gpu_warmup.py`, `test_gpu_groups.py`, `test_pipeline_prefetch.py` **new/extended** — prefetch behaviour, gate, wiring (see "Tests").

## Mechanisms (probe-verified; `scripts/probe_warmup_lock.py`)

1. **The MIOpen find starves CPU work, not the GPU.** During the 8.1 s `conv3x3`: a 3M-iteration Python loop runs at full speed (no GIL held), contiguous pinned and pageable H2D copies take 0.00 s, a 180 MiB pinned alloc 0.04 s — but torch's dispatch stream (2 200 small ops) starves 1.7 → 9.4 s and JPEG decode workers starve 0.04 → 7.5–9 s.
2. **Contiguous vs non-contiguous H2D**: per-page slice copies (`out[:, y:y+h, :].copy_(page)`) launch copy *kernels* queued behind the MIOpen load; a single contiguous full-strip `copy_` takes the memcpy path and is instant even during a find.
3. **Concurrent finds stretch each other but end at the same time as serialized ones** (17 s + 28 s concurrent vs 12 s + 15.5 s solo). A lock only delays the start: holding a `miopen_lock` across the whole warm-up delayed LaMa's find start to t≈17 → wall 38.0 s; removing it → 34.2 s. Shipped without the lock.

## What did not help (measured, reverted or not shipped)

- **`miopen_lock`** serialising the warm-up finds against LaMa's forwards: 38.0 s vs 34.2 s (delayed the start, saved nothing).
- **Prefetching the first (vision) group**: its loader competes with the startup decode; the first group stays synchronous.
- **Concurrent loader threads** (one per group): they starve each other's library init — one sequential worker wins.
- **Gating the LaMa prefetch on a `library_ready` event / any lock**: every variant measured within noise of the simplest design, so the simplest shipped.

1. The card quotes a 67.5 s baseline; re-measured on the pre-G3 tree in today's conditions the same command runs 44.6–45.0 s (the card's number was presumably taken under GPU contention from other builders). The table above compares both states measured the same way.

## Open questions

1. **JA OCR engine** (`paddleocr_vl`) needs `ocr.rec_model`/a catalog default — card O1d territory. Once it lands, re-run the full 6-stage JA check and hash its export slices for the complete bit-identicality evidence.
2. The 25 s stretch needs the ~28 s MIOpen find chain gone (library load 8 s + finds ~20 s). A MIOpen kernel-db pre-seed (shipping `~/.miopen` per GPU, or `MIOPEN_USER_DB_PATH` pointing at a shipped db) might cut it without changing selection — needs its own card with a bit-identicality check.
3. Peak VRAM for detect rose 1.32 → 1.59 GiB (metric only, outputs identical) — the pinned full-strip staging is allocated while the detector loads. Harmless at 16 GiB; flag it if a smaller-GPU config matters.

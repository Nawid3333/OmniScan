# B33a — Acquisition plumbing: image-list downloader, page filters, DRM refusal, sources.toml

## Changes

- `src/omniscan/acquire/__init__.py` (new, empty)
- `src/omniscan/acquire/drm.py` (new): `NOTICE`, `DRM_PLATFORMS` (the 8 hosts of the card),
  `DrmPlatformError(ValueError)`, `drm_platform(url)` (lower-cased `urlsplit().hostname`, one leading
  `www.` removed, match on `host == key` or `host.endswith("." + key)`), `check_allowed(url)`
  (raises with the platform name and the `omniscan import` hint).
- `src/omniscan/acquire/filters.py` (new): `NON_PAGE_URL_TOKENS` in the card's order,
  `url_looks_like_page` (non-http(s) scheme → "not an http(s) url"; token search over the lower-cased
  URL **path** only, first token in tuple order reported), `image_looks_like_page` (checks in the
  card's order, first failure wins: `width < 300`, `height < 100`, `width / height > 6.0`,
  `size_bytes < 8000`).
- `src/omniscan/acquire/sources.py` (new): `ChapterSource` (frozen/slots dataclass),
  `sources_path(library_root, series)`, `load_sources(path)` — `tomllib` parse; explicit
  `[[chapter]]` entries first in file order, then `[template]` chapters `n = first..last` inclusive
  (`url.format(n=…)` so `{n:03d}` works; `name` defaults to `"Chapter {n}"`). Validation errors
  exactly as the card lists them (missing name/url, template missing url/first/last, `first > last`,
  more than 1000 template chapters, non-http(s) url, unsafe names — empty/blank, `/`, `\`, `.`, `..`
  — duplicates). Unknown keys/tables ignored; empty file → `[]`; missing file → `FileNotFoundError`;
  invalid TOML → `tomllib.TOMLDecodeError` propagates.
- `src/omniscan/acquire/download.py` (new): `USER_AGENT` (fixed Chrome string), `SUPPORTED_FORMATS`,
  `MAX_IMAGE_BYTES`, `MANIFEST_NAME = "acquire.json"`, `AcquireError`, `ImageRef`, `DownloadResult`,
  `download_chapter(...)` with the card's exact behaviour:
  1. every ref goes through `check_allowed` before anything else (a DRM ref raises
     `DrmPlatformError` before any request, before `dest` is created, nothing written);
  2. position = 1-based index; file name `f"{position:0{w}d}{ext}"` with `w = max(3, len(str(len(refs))))`
     and `ext` from the decoded format, never from the URL; `dest` created (parents included);
     writes go to `<name>.part` then `Path.replace` (atomic; no `.part` left on success or failure;
     the manifest uses the same mechanism);
  3. manifest `acquire.json` (UTF-8, `indent=2`, `ensure_ascii=False`), written at the end of every
     call that got past the DRM check — also when it raises `AcquireError` — as
     `{"images": [...], "rejected": [...]}` sorted by position, carrying the earlier-run entries
     that are still valid plus the new ones; an unreadable/invalid manifest is treated as empty;
  4. resume: (url, position) hit in `images` with the recorded file present and `st_size == bytes`
     → skipped (no request); hit in `rejected` → skipped (counted as rejected, no request); files
     the manifest does not know are never touched or deleted;
  5. GET with `User-Agent` (+ `Referer` when set); status 200 required; `> MAX_IMAGE_BYTES` →
     "too large"; retries for `httpx.TransportError`, 429 and ≥ 500 (`retries + 1` attempts,
     `sleep(backoff_s * 2**k)` before retry k; 429 with integer `Retry-After` → `sleep(min(n, 30))`);
     any other status fails at once;
  6. Pillow `verify()` then reopen for size; undecodable or a format outside `SUPPORTED_FORMATS`
     → `not a supported image (<fmt or 'undecodable'>)`; with filters on, a decoded image failing
     `image_looks_like_page` is rejected (never written);
  7. failures never stop the other images; after all refs, `AcquireError(f"{n} of {total} image(s) failed: …")`
     with `#<position> <message>` sorted by position — good files and manifest are kept;
  8. `ThreadPoolExecutor(max_workers=max(1, concurrency))` does the requests; all file writes,
     manifest handling and `on_progress(done, total)` (inline-resolved skips/rejections counted
     too; monotonic; last call `(total, total)`) happen in the calling thread as results arrive;
     result and manifest are identical for any `concurrency`;
  9. returns `DownloadResult(files, downloaded, skipped, rejected)` with `files` in position order.
- `tests/unit/test_acquire_drm.py`, `test_acquire_filters.py`, `test_acquire_sources.py`,
  `test_acquire_download.py` (new): the 11 acceptance groups of the card, all on CPU with
  `httpx.MockTransport`, Pillow-made seeded-noise images (> 8 kB), and a `sleep` recorder so tests
  are instant. No network access anywhere.

## Deviations

- **Card test-table row `(800, 100, 50000)` is impossible to satisfy together with the rest of the
  table and the Part-2 rule.** Part 2 says `width / height > 6.0` → "banner shape", and the table
  itself pins that rule with `(600, 100, 50000)` ok / `(601, 100, 50000)` "banner shape". But
  800 / 100 = 8.0 > 6.0, so `(800, 100, 50000)` must be "banner shape" under the very rule the card
  specifies — "ok" is provably inconsistent (no monotonic ratio rule can make 6.01 a banner and
  8.0 ok). I implemented Part 2 exactly and the test expects `(800, 100, 50000)` → "banner shape";
  the height-boundary "ok" is covered by `(500, 100, 50000)` instead. If the intent was a different
  threshold or a different rule shape, it is a one-constant change in `filters.py`.
- Retry-After parsing accepts integer values only, per the card ("an integer `Retry-After`");
  non-integer headers fall back to the normal backoff. Negative values would be handed to
  `sleep(min(n, 30))` verbatim (the card's literal wording); real servers do not send them.
- Carried-over manifest entries keep the file name recorded by the earlier run (even if a re-run
  with more refs would compute a wider number width for that position); new downloads always use
  the current width. The card does not pin this corner.

# B10 — Web debug tool: translation review view

## Changes
- `src/omniscan/web/app.py` — added the five read-only routes from the card:
  `GET .../translations` (natural-sorted stems of `translations/*.json`, dot-stems skipped, `[]` when the
  directory is absent), `GET .../translations/{run_id}` (byte-for-byte; 404 when the id contains `/`, `\`,
  or `..`, or the resolved path is not `_under` the translations dir), `GET .../final` (byte-for-byte via
  `artifact_bytes`), `GET /api/series/{s}/glossary` (all entries via `model_dump(mode="json")`, `[]` — and
  no db file created — when `series.db` is missing) and `GET .../glossary-hits` (per-region `find_terms`
  hits over proposed/locked entries with `target_in_final` checked against the matching `FinalLine`;
  invalid `final.json` treated as absent). Helpers `glossary_entries` / `final_lines` reuse the existing
  `series_paths` / `chapter_paths` validation, so traversal stays a clean 404.
- `tests/unit/test_web_app.py` — appended 12 tests covering all card acceptance items 1–8 plus two extras
  (invalid `final.json` treated as absent; natural ordering of run ids with the dot-file skip).
- `webui/src/api.ts` — added `Candidate`, `CandidateRun`, `FinalLine`, `FinalArtifact`, `GlossaryEntry`,
  `GlossaryHit`, `GlossaryHits` types and the five fetch functions (every path segment
  `encodeURIComponent`-ed, including `runId`).
- `webui/src/translation.ts` (new) — `ReviewRow`, `sortRegions` (slice_index → reading_order → numeric-aware
  id, non-mutating), `candidatesDisagree`, `buildRows` (first candidate wins per region per run, first final
  line wins per region), `highlightSource` (sorted, overlap/out-of-range hits ignored, end clamped,
  concatenation exact), `summarizeReview`, `filterRows`, `hitColor`.
- `webui/src/translation.test.ts` (new) — vitest coverage for all of the above (card items 9–13).
- `webui/src/TranslationView.svelte` (new) — parallel fetch of `getOcr` / `listTranslations` (+ per-run
  `getTranslation`) / `getFinal` / `getGlossaryHits` via `Promise.allSettled`; missing `ocr.json` shows
  `no ocr.json yet — run ocr first`; failing `getFinal`/`getGlossaryHits` are treated as `null`; a failing
  run is dropped with `could not load run <id>` under the toolbar. Toolbar has the `only rows needing
  attention` checkbox and the full `summarizeReview` line; the sticky-header table shows `#` (id / slice /
  order / kind), the highlighted source (glossary `<mark>`s tinted `hitColor` at 0.2 alpha via hex suffix
  `33`, `alt` in gray below when it differs), one column per run (title `profile · model`, notes in
  `title`, `—` for missing candidates), the final cell (decision badge, flag chips red for
  `glossary_violation` / amber otherwise, `why` details with the rationale) and the glossary chips
  (`✗ ` prefix on violations). Row backgrounds: `#fef2f2` on violations, `#fffbeb` on other
  needs-attention. Text cells use `white-space: pre-wrap`.
- `webui/src/App.svelte` — view state extended to `"slicer" | "ocr" | "translation"`, third `Translation`
  button, `<TranslationView>` branch. Nothing else touched.
- `README.md` / `docs/USER_GUIDE.md` — status line and the web-viewer section now mention the Translation
  view and the new endpoints; `tests/unit/test_docs.py` stays green.

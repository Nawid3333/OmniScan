## Changes

**`src/omniscan/web/app.py`** — three routes, nothing else touched:

- `GET .../inpaint` and `GET .../layout`: `inpaint.json` / `layout.json` byte-for-byte passthrough via the
  existing `artifact_bytes` helper (same pattern as `get_ocr`).
- `GET .../inpaint/patches/{region_id}.png`: the region's patch from `patches.npz` re-encoded as an RGBA PNG
  (alpha = mask scaled 0/255) with PIL + numpy only — no torch tensors, no GPU. Guard order per the card:
  missing `inpaint.json` → 404; `region_id` not in the artifact's items → 404 `"region not found"` (this
  lookup-key validation **is** the route's traversal guard — `region_id` never builds a filesystem path,
  noted in a comment); missing `patches.npz` → 404; id absent from the npz (a flat/none item) → 404
  `"no patch stored for this region"`.

## Deviations

1. **`web/app.py` now transitively imports torch.** Part 1 step 4 directs `from omniscan.inpaint.patches
   import load_patches`, and `inpaint/patches.py` has `import torch` at module level — so the serve process
   now pulls torch transitively, though no torch tensor or GPU work happens in it (`load_patches` is
   numpy-only and the card's "do not import torch here" is honoured in the direct sense; `export/composite.py`
   is not imported anywhere). Question F14 in `docs/OPEN_QUESTIONS.md` asks whether strict torch-freedom of
   `serve` matters (it would need a numpy-only npz helper outside read-only `inpaint/patches.py`).
2. Test placement: created **no** new test files; extended `test_web_app.py` following the file's precedent.
3. `layout.ts` gained `filterItems` beyond the card's two listed exports — the Part 4 `$derived` filter is
   required to "mirror `ocr.ts`'s `filterRegions`", which needs the item-type counterpart; tested.
4. `hasStoredPatch` is used against a derived set of `method !== "none"` ids minus the `onerror`-failed ones
   (the card offers both the derived-Set and the `onerror` reading; this combines them — the `<img>` renders
   for every attempted patch and the failure flag swaps that one item to its flat-fill div).
5. The patch PNG test compares alpha with PIL `tobytes()` instead of the deprecated `getdata()` (Pillow
   warns; pixel-for-pixel semantics unchanged).
6. `test_inpaint_missing_returns_404` / `test_layout_missing_returns_404` build the chapter via
   `write_chapter` only (matching `test_ocr_missing_returns_404`'s pattern) instead of unlinking a written
   artifact.

# B5 — Web debug tool v0 (chapter browser + slicer view)

## Changes

Backend:
- `src/omniscan/web/__init__.py` (new) — package docstring.
- `src/omniscan/web/app.py` (new) — `create_app(cfg, *, cors_origins=...)`: five read-only endpoints
  (`/api/series`, `/api/series/{s}/chapters`, `.../ingest`, `.../slices`, `.../pages/{index}`).
  `ingest.json`/`slices.json` are served as the exact file bytes (no pydantic round-trip); pages are
  served via `FileResponse` with the media type guessed from the file suffix. All paths are built
  through `SeriesPaths.from_config` / `SeriesPaths.chapter` only.
- `src/omniscan/cli.py` — `serve` is no longer a stub: `cmd_serve(host, port, reload)` lazily imports
  `uvicorn` + `create_app` inside the function (like `version`), registered via
  `app.command("serve")`, removed `"serve"` from `_STUB_COMMANDS`. No other command touched.
- `pyproject.toml` — added `fastapi>=0.115`, `uvicorn[standard]>=0.32` to `dependencies`; `uv sync` run
  (`uv.lock` updated as a consequence).

Frontend (`webui/`):
- `package.json` — name `omniscan-webui`, scripts dev/build/check/test; devDeps are exactly what
  `npm create vite@latest -- --template svelte-ts` produces today (vite `^8.3.0`, svelte `^5.57.0`,
  `@sveltejs/vite-plugin-svelte ^7.3.0`, svelte-check `^4.7.6`, typescript `~6.0.2`) plus
  `vitest ^5.0.1` (pairs with vite 8).
- `vite.config.ts` — svelte plugin + `server.proxy { "/api": "http://localhost:8000" }`.
- `tsconfig.json` — single self-contained config (the card lists only one tsconfig; the template's
  `tsconfig.app.json` options were inlined, with `types: ["svelte", "vite/client"]` replacing the
  template's `src/vite-env.d.ts`, which the card does not allow).
- `index.html`, `src/main.ts` — standard svelte-ts Vite entry points.
- `src/api.ts` — typed fetch wrappers; every series/chapter is `encodeURIComponent`d; `getIngest`/
  `getSlices` throw on non-OK (SlicerView catches and shows inline).
- `src/strip.ts` — `stripYToStackY` / `stackTotalHeight` / `stackWidth` exactly per the card's spec.
- `src/App.svelte` — series/chapter `<select>`s populated on mount / on series change; plain-text
  loading/error states; renders `<SlicerView>` once both are chosen.
- `src/SlicerView.svelte` — stacked raw images (natural size, no CSS scaling) + absolutely
  positioned SVG overlay: translucent green band rects, cut lines at every `slice.y0` plus the last
  slice's `y1` (red when the slice starting at that boundary has `forced_cut`), strip-space height
  labels, dashed gray lines at raw-file boundaries.
- `src/strip.test.ts` — vitest cases 10–14 of the card.

Other:

- `webui/package-lock.json` — produced by `npm install` (deviation, see below).

## Deviations

1. **`.gitignore`** (modified, not in the card's file list): `npm install` creates
   `webui/node_modules/` (~35k files); without ignoring it the worktree is unusable. Added
   `webui/node_modules/` and `webui/dist/` next to the existing web-frontend entries.
2. **`webui/package-lock.json`** (created, not in the card's file list): unavoidable output of the
   card-mandated `npm install`; committed for reproducible installs (`npm ci`).
3. **Not created** (template defaults the card's file list omits): `svelte.config.js`,
   `tsconfig.app.json`/`tsconfig.node.json`, `src/vite-env.d.ts`, `public/`. A single
   `tsconfig.json` with inlined options covers svelte-check, vitest and the build.
4. **Traversal guard beyond the card's wording**: the card says using `SeriesPaths`/`ChapterPaths`
   makes escapes "impossible by construction", but pathlib joining *preserves* `..` segments (and an
   absolute component replaces the root entirely), so `library_root / "../x"` does escape. `app.py`
   therefore additionally checks `resolve()`d containment under `library_root`/`work_root` and
   returns 404 otherwise (acceptance case 9 requires exactly this).
5. **`stripYToStackY` below the first file**: the card specifies the last-file rule for
   `yStrip >= first y0` but not `yStrip < first y0`; it clamps to 0.

## Questions

1. **`forced_cut` semantics.** `core/schemas.py` says `Slice.forced_cut` marks "the cut at **y1**
   was forced", while this card says to color the line at `slice.y0` red when *that slice* has
   `forced_cut === true` (i.e. the cut at its top). I implemented the card as written. If the
   schema comment is the intended semantics, the red line should move one boundary down (to the
   forced slice's `y1`) — a one-line change in `SlicerView.svelte`; please confirm which is right.
2. Committing `package-lock.json` (deviation 2) — keep, or is an unpinned install preferred?
## Review (applied during merge review, not by the builder)

- **Question 1 (forced_cut semantics): the schema is right, the card was wrong.** `slice_strip` sets
  `forced` from `cuts[i]`, the cut at slice i's **y1**, so `Slice.forced_cut` means "the cut at this slice's
  y1 was forced". `SlicerView.svelte` now colors the line at `slice[i].y0` red when the **previous** slice
  (`slice[i-1]`) has `forced_cut`, and the final line at the last slice's `y1` when that slice has it. The
  first line (nothing before it) is never red.
- **Question 2:** keep `webui/package-lock.json` (reproducible `npm ci`, same as `relay/`).
- Deviations 1-5 accepted as written; deviation 4 (resolve()-based containment check) is a genuine
  improvement over the card's "impossible by construction" claim, which was wrong for `..` segments.

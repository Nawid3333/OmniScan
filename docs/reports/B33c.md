# B33c — Chapter selection, completeness checks and the acquire plan

## Changes

- `src/omniscan/acquire/sources.py` (modified — additions only): `template_chapters(url, first, last, name="Chapter {n}")`
  delegates to the existing private `_template_sources` (so it inherits every `[template]` rule and error
  message, including the `template:` label), and `named_chapters(entries)` validates `(name, url)` pairs
  with the existing `_check_url` (label `chapter #N`, N = 1-based position), `_check_name` and
  `_check_duplicate`. Added `from collections.abc import Sequence`; nothing else touched.
- `src/omniscan/acquire/selection.py` (new): `read_url_list` — `splitlines()` (handles CRLF), blank lines
  and `#` comments skipped, each usable line becomes one entry; `NAME | URL` split via `str.partition`
  (first ` | ` only, both sides stripped), unnamed lines get `name_template.format(n=first_number + k)`
  with k the 0-based index among the non-ignored lines (so numbering continues across named lines);
  validation/errors come from `named_chapters`; no usable lines → `ValueError("no chapter links found")`.
  `select_chapters` — `None`/blank/`all` (case-insensitive) → everything; otherwise tokens split on `,`,
  each stripped and parsed as `N` / `A-B` / `A-` / `-B` (regex `\d+(?:-\d*)?|-\d+` fullmatch). Basis:
  `number` = `core.paths.chapter_number(name)`, `position` = 1-based index, `auto` = number when every
  name has a number else position. Errors (`selection:` prefix): empty token, invalid token, reversed
  range, and `selection: nothing matches '<token>'`. Matches are collected as an index set and returned
  in original order (no duplicates); decimal chapters (5.5) match ranges, never the bare `5`.
- `src/omniscan/acquire/completeness.py` (new): `PageInfo`, `Finding` (frozen/slots dataclasses);
  `inspect_chapter` walks `list_images` (natural order), reads bytes once (size + sha256) and takes the
  Pillow header size; undecodable file → `Finding("error", "unreadable", "<name>: cannot be decoded")`,
  no `PageInfo`; missing/empty dir → `([], [])`. `check_pages` emits the card's codes in order:
  `no_pages` (error, only finding when empty), `few_pages` (median and/or previous thresholds, median
  message wins when both apply), `many_pages` (median only), `mixed_widths` (most common width, smaller
  wins ties; `abs(w − W) > 0.05·W` counts), `duplicate_pages` (extra copies = pages − distinct hashes).
  `check_numbering` parses integer chapter numbers (decimals/unnumbered ignored) and reports each
  consecutive missing run as `chapter 5 is missing` / `chapters 5–7 are missing` (en dash). `verdict`:
  error → `failed`, else warn → `review`, else `ok`.
- `src/omniscan/acquire/plan.py` (new): `ACCEPTED_NAME = "accepted.json"`, `PlanItem`, `AcquirePlan`;
  `chapter_state` (done ⇔ accepted.json parses and `status` ∈ {ok, review}), `build_plan` (one item per
  source in order, `force` → all todo, credits `credit_cost(1, mode)` for todo / 0 for done, totals),
  `write_accepted` (atomic: `accepted.json.tmp` then replace; keys status/pages/source_url/accepted_at
  (UTC ISO-8601, seconds)/findings; indent 2, UTF-8, `ensure_ascii=False`, trailing newline),
  `read_accepted` (parsed dict or `None` for missing/corrupt/non-object), `to_json` (the GUI payload).

## Deviations

- `write_accepted` performs the atomic swap with `Path.replace(...)` instead of `os.replace(...)`
  (`Path.replace` is the same `os.replace` syscall; ruff's PTH105 flags the bare-`os` form, and card
  B33a established `Path.replace` for this exact tmp-then-replace pattern in `download.py`).
- `read_accepted` returns `None` not only for missing/invalid JSON but also when the file holds valid
  JSON that is not an object (e.g. a list) — the declared return type is `dict | None`, and such a file
  is not a usable acceptance record. `chapter_state` treats it as `todo` accordingly.
- The `unreadable` decode check catches `Exception` (Pillow raises several unrelated error types:
  `UnidentifiedImageError`, `DecompressionBombError`, truncated-data `OSError`, …); a narrower catch
  would let real-world corrupt files slip through as crashes instead of findings.
- `many_pages` message follows the `few_pages` shape: `"<n> pages; the series median is <m:g>"` (the
  card pins no message for it). `no_pages` message: `"no pages found"` (also unpinned).
- ruff format applied PEP 758 (`except OSError, ValueError:` without parentheses) in `plan.py` —
  Python 3.14 syntax, functionally identical to the parenthesised tuple I wrote.

## Questions

1. `check_pages` with `median_pages` given but the chapter also having duplicates/width outliers keeps
   the `few_pages`/`many_pages` count semantics on `len(pages)` (raw count, duplicates included).
   Confirm that duplicates are not meant to be de-duplicated before the count checks.
2. `select_chapters` evaluates tokens left to right and raises `nothing matches` for the first token
   that matches nothing (e.g. `"12,99"` raises, nothing is returned). The card does not say whether a
   failing token should abort the whole selection or be skipped with a warning; aborting (as specified
   for a single token) seemed the safer default for B33d's "choose which chapters to run" UI.

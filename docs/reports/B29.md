# B29 — Translation runner (candidate runs) + `omniscan translate`

## Changes

- `src/omniscan/llm/ollama.py` — added the keyword-only `think: bool | None = None` parameter to
  `OllamaClient.chat` (after `keep_alive`); when not `None` it lands as a top-level `"think"` key in
  the request body (never inside `options`); when `None` the key is absent.
- `src/omniscan/translate/` (new package):
  - `profiles.py` — `TranslationProfile` (pydantic, `extra="forbid"`, name regex, temperature 0–2,
    `chunk_regions >= 1`), `load_profiles` (later file replaces an earlier same-name profile
    entirely; missing files skipped; TOML/profile errors raise `ValueError` naming the file and
    profile; a `name = ...` key inside a table is rejected), `default_profile_paths` (repo file,
    then the user file from `omniscan.core.config`).
  - `prompts.py` — `CHAT_JSON_SYSTEM` (verbatim from the card, byte-verified),
    `TRANSLATIONS_SCHEMA`, `TRANSLATEGEMMA_TEMPLATE` (verbatim from `scripts/probe_translation.py`,
    byte-verified), `source_text`, `translatable`, `glossary_subset`, `chat_json_messages`,
    `substitute_binding`, `translategemma_prompt`.
  - `parse.py` — `extract_translations` (plain JSON → fenced blocks → raw-decode every `{`, first
    value that is a dict with a `translations` list wins, never raises) and `parse_translations`
    (tolerant item filtering, first usable text per id, `missing` in `expected_ids` order).
  - `run.py` — `ChatClient` protocol and `run_profile`: partial restore (same profile + model
    only), `chat_json` chunking + per-chunk repair rounds (only missing ids re-requested),
    `translategemma` one request per region with locked-term pre-substitution and the
    wrapping-quote unwrap rule, partial saved after every chunk / every 20 regions / on any
    exception, usage counters exactly as specified (all `float`), client exceptions propagate.
  - `chapter.py` — `translate_chapter`: skip when the output exists (unless `force`), `ocr.json`
    missing → `FileNotFoundError`, dot-prefixed partial file removed on `force` and after success.
- `config/translation_profiles.toml` (new) — the five shipped profiles from the card, all
  `endpoint = "local"`.
- `src/omniscan/cli.py` — `translate` removed from `_STUB_COMMANDS`, real `cmd_translate`
  registered: chapters × profiles loop, one line per outcome, unknown profile / no chapters /
  no enabled profile → exit 2, missing `ocr.json` per chapter → stderr + failure + continue,
  `OllamaRateLimitError` → stderr + exit 3 immediately, other `OllamaError` → failure + continue,
  exit 1 at the end if anything failed; glossary opened only when `series.db` already exists; one
  module-level `OllamaClient(cfg.ollama, get_secrets())` for the whole command.
- `README.md` — translate row in the status table now "working — `omniscan translate` (candidate
  runs only; needs ocr.json, which no stage produces yet)"; removed from the stub table.
- `docs/USER_GUIDE.md` — new `### omniscan translate` section; removed `translate` from the stub
  list; fixed the secrets comment that called `translate` a stub.
- Tests: `tests/unit/test_llm_ollama.py` (appended `think` tests), new
  `test_translate_profiles.py`, `test_translate_prompts.py`, `test_translate_parse.py`,
  `test_translate_run.py`, `test_translate_chapter.py`, `test_translate_cli.py`;
  `tests/unit/test_cli.py` STUB_COMMANDS no longer lists `translate`.

## Deviations

- Intermediate partial saves record `seconds = 0.0` (only the final run and the post-error partial
  carry the real clock delta). This keeps an injected test clock consumed by exactly two ticks
  (start/end) instead of one per chunk.
- On the final run object, `usage["missing"]` counts targets without a candidate, including ids that
  a partial restored — a restored id always has a candidate, so in practice this is identical.

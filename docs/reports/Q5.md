## Questions

1. **`model_status` crashes on a marker that is valid JSON but not an object** (`src/omniscan/models/store.py:70` hf branch and `store.py:95` zip branch). `json.loads("[1, 2]")` returns a list; `data.get("revision")` / `data.get("sha256")` then raise `AttributeError` instead of returning `"corrupt"`. A truncated/corrupt marker could plausibly contain such text. Minimal reproduction: `tests/unit/test_hw_hf_mutation_gaps.py::test_hf_marker_that_is_a_json_list_is_corrupt` (marked `xfail(strict=True)` — it fails on the original with `AttributeError`). Suggested fix (owner of `core`/`store`): after `json.loads`, return `"corrupt"` unless `isinstance(data, dict)` — in both the hf and the zip branch.
2. Minor, not a bug: `ModelEntry` declares `notes: str = ""` twice (`src/omniscan/models/catalog.py:61` and `catalog.py:81`); the second silently shadows the first. Same type and default, so behaviour is unaffected — worth deleting one of the two.

# P1 — Runner gates: step-by-step mode with a one-chapter preview

## Changes

- `src/omniscan/pipeline/runner.py` (modified): adds `type RunMode`, the frozen `GateEvent` dataclass
  and `type Gate = Callable[[GateEvent], bool]`; `run_pipeline` gains the keyword-only parameters
  `mode`, `preview_chapter` and `gate` after `report`. Step mode validates the gate
  (`ValueError("step mode needs a gate")`) and the preview chapter (default: first chapter of
  `active`; `ValueError(f"unknown preview chapter {name!r})"`) before the client check, then runs
  phase A (`_run_preview`: the preview chapter through every pass of `run_series(..., after_stage=...)`
  with a hook that counts `position` 1..`total` across passes and calls `gate` once per stage,
  including skipped and failed outcomes). Outcomes are stored/reported through the shared
  `_record_pass_results` helper exactly as the auto loop does. A gate that answers False raises
  `RunAbortedError` out of `run_series`; the runner stores `error.outcomes` (and reports them),
  sets `aborted = "stopped"` and returns. A failed preview stage sets `failed` as usual and
  `aborted = "preview failed"`; later passes do not run. On success phase B runs the normal auto
  loop over `[c for c in active if c != preview_chapter]` (no gate), so the preview chapter's
  outcomes stay in `result.outcomes` exactly once. `PipelineResult.aborted` documents the two new
  values. Auto mode is byte-for-byte the old code path (gate and preview_chapter ignored).
- `src/omniscan/pipeline/preview.py` (created): `Preview` (frozen dataclass: `stage`, `summary`,
  `details`) and `describe(stage, paths, cfg)`. Reads each stage's artifact via a never-raising
  `_load` (missing file, invalid JSON and schema violations all become
  `Preview(stage, "no <artifact> found", ())`). Exact summaries: ingest
  (`{N} file(s), strip {W}x{H} px`, files not `filtered`), slice
  (`{N} slice(s): {B} blank, {F} forced cut(s), {P} filtered`), detect
  (`{N} region(s): kind counts` in the order bubble_text, free_text, sfx, watermark, nonzero only;
  `0 regions` when empty), ocr (`{N} region(s) with text, {L} low-confidence (< {cfg.ocr.low_conf})`
  + first 5 region texts), translate (`{N} candidate run(s)` from `translations/*.json`, dot-prefixed
  partials ignored; details `<source> → <candidate>` over the first 3 candidates, sources from
  `ocr.json`), judge (`{N} final line(s)` + first 5 final texts), inpaint / inpaint_lama
  (`{N} item(s) inpainted` from `inpaint.json` / `inpaint_lama.json`), typeset
  (`{N} layout item(s), {U} unfitted`, unfitted = `LayoutItem.overflow`), export
  (`{N} file(s) written to {paths.output_dir}`). All detail/sample strings are clipped to 59
  characters + `…` (60 total).
- `src/omniscan/cli.py` (modified: `cmd_run` only): new options `--step` and `--preview-chapter`.
  `--preview-chapter` without `--step` → stderr message, exit 2. The gate prints
  `Preview [<position>/<total>] <chapter> <stage>: <status>` plus the summary and detail lines
  indented 4 spaces (and the error for a failed stage), then prompts
  `Continue? [y]es / [n]o stop / [a]ll (finish without asking)` (default `y`): `y`/empty → True,
  `n` → False, `a` → True now and every later gate passes without printing or asking, anything else
  re-asks (3 attempts, then `n`), EOF/`typer.Abort` → False. Exit codes: `aborted == "stopped"` →
  `run: stopped after <stage> of <chapter>`, exit 4; `"preview failed"` →
  `run: the preview chapter failed — nothing else was run`, exit 1; the rate-limit handling (exit 3)
  is unchanged and the final summary line is only printed on a non-gate-aborted run.
- `docs/USER_GUIDE.md`: documents `--step` / `--preview-chapter` (option table, behaviour paragraph,
  exit codes, example transcript) — `tests/unit/test_docs.py` validates the fenced commands.
- Tests: `tests/unit/test_pipeline_runner.py` extended (auto-ignores-gate, step order across passes,
  positions/total with `-s` + `--no-lama`, stop at position 4, preview-failure, gate validation,
  `preview_chapter="B"` selection, skipped stages still gate, `force` reaches phase A);
  `tests/unit/test_pipeline_preview.py` created (exact summaries per stage from hand-made artifacts
  saved with `Artifact.save` into a tmp `ChapterPaths` layout, plus missing/invalid artifacts for
  every stage); `tests/unit/test_pipeline_cli.py` extended (10 prompt runs, `n` stop exit 4,
  `a` answer single prompt, EOF exit 4, three invalid answers, failing preview stage exit 1,
  `--preview-chapter` honoured / without `--step` exit 2, no prompts without `--step`).

## Deviations

1. **`translate` missing-artifact message.** The translate stage's candidate runs live in the
   `translations/` directory (one `<profile>.json` per enabled profile — the card's
   "`translate*.json`" resolved through "how the translate stage names them"). A missing/empty
   directory, a run file that fails validation, or a chapter with only dot-prefixed partial files
   yields `Preview("translate", "no translations found", ())` — the card's `no <artifact> found`
   pattern applied to the artifact this stage actually produces.
2. **Rate limit inside phase A.** If the preview chapter's failing stage hit an Ollama rate limit,
   phase A still ends with `aborted = "preview failed"` (CLI exit 1, not the rate-limit exit 3):
   the card defines the preview-failure outcome unconditionally, and the preview chapter is also
   recorded in `result.failed`.
3. **Gate answer vocabulary.** Only `y`/empty, `n` and `a` (case-insensitive, trimmed) are accepted;
   `yes` / `no` / `all` count as invalid answers and re-ask, per the card's "anything else → ask
   again".
4. **"stopped" message source.** `PipelineResult` carries no stopped-at stage/chapter field, so
   `cmd_run` derives `<stage>`/`<chapter>` from the last recorded outcome of the (single) chapter in
   `result.outcomes` — always the preview chapter, since the gate only fires in phase A.
5. **Validation order.** Step-mode validation (`gate` missing, unknown preview chapter) runs before
   the chat-client check, so a step-mode misuse is reported even when no client was supplied.
6. **`ocr` "with text" count.** `N` counts regions of `ocr.json` with a non-empty `text` field; for
   real `ocr.json` artifacts this equals the region count (the stage drops regions without readable
   text via `ocr.drop_conf`).

## Questions

1. Rate limit during the preview phase: should it report `aborted = "rate limit"` (CLI exit 3, the
   message users already know) instead of `"preview failed"` (exit 1)? Currently the preview-failure
   outcome wins. Easy to special-case if the desktop app wants the distinction.
2. For `translate`, should a chapter that has candidate runs but no `ocr.json` (sources unavailable)
   say so explicitly instead of printing empty ` → <candidate>` detail lines? Currently the source
   side is clipped to `""` and the line prints as ` → <candidate text>`.

# E2 — `omniscan eval`: score detection, OCR and translation against the Pepper&Carrot text layers

## Summary

`omniscan eval` scores a chapter's `ocr.json` (and optional `final.json`) against the Inkscape text
layers in `translated-check/<series>/<chapter>/truth/<lang>/`: detection recall/precision (region
centre inside the smallest containing truth box), OCR CER (macro and micro) and translation chrF per
page, written as `eval.json` and printed as a compact block. All golden values from the card
reproduce.

## Changes

- `src/omniscan/eval/__init__.py` (new, empty), `eval/truth.py` (new): `TruthBox`/`TruthStats`,
  `parse_svg` (ElementTree; composes ancestor `<g>` transforms and the `flowRoot`'s own
  `matrix/translate/scale/rotate`, maps SVG → page → strip space with the top-crop rule
  `crop_top = max(0, round(svg_height·sx) − file_height)`, clamps, floors/ceils once in strip space),
  `load_truth`, `load_english_pages`.
- `src/omniscan/eval/metrics.py` (new): `normalize` (NFKC, lower, letters+digits only), `levenshtein`,
  `cer`, `chrf` (char n-grams 1..6, β=2, per the card's exact recipe).
- `src/omniscan/eval/score.py` (new): `BoxResult`, `EvalReport` (+`to_json`, bboxes as `[x0,y0,x1,y1]`,
  and `to_json_lines` for `--json`), `score_chapter` (ignoring of punctuation-only boxes, smallest
  containing box assignment with lowest-index ties, CER macro/micro, page-level chrF with empty-
  reference skip, missed/worst lists).
- `src/omniscan/cli.py`: only the new `eval` command plus its private printing helpers
  (`_eval_block`, `_ratio`, `_num`, `_short`, `_box_entry`, `_echo_text`). Nothing else touched.
- `README.md`: `eval` row in the status table. `docs/USER_GUIDE.md`: `### omniscan eval` section.
- Tests: `tests/unit/test_eval_truth.py`, `test_eval_metrics.py`, `test_eval_score.py`,
  `test_eval_cli.py` (no reads from `data/`).

## Deviations

1. **`ingest.json` missing message.** The card defines an exact message only for `ocr.json` missing.
   I treat a missing `ingest.json` the same way (`eval: <chapter>: ingest.json missing — run the
   ingest stage first`), same exit-1-after-the-other-chapters semantics. `ocr.json` cannot exist
   without ingest in practice, so this path is only a safety net (covered by a test).
2. **Truth-missing exits immediately.** "exit 2 for that chapter's turn" is read literally: the loop
   stops at the first chapter without `truth/<lang>` (unlike missing artifacts, which defer to the
   end). If the intent was "continue with the remaining chapters, exit 2 at the end", that is a
   two-line change in `cmd_eval`.
3. **`--json` output.** One compact JSON object per line (`json.dumps` without indent); `eval.json`
   on disk stays the indented `to_json()` form. The card allows this ("one object per line").
4. **UTF-8 guard for the console.** `cmd_eval` prints Korean truth text; on a Windows pipe whose
   stdout encoding is cp1252 (this Bash tool) `typer.echo` raised `UnicodeEncodeError` *after* the
   report was written. `_echo_text` reconfigures stdout to UTF-8 (`errors="replace"`) when its
   encoding is not UTF-8; `eval.json` is always written as UTF-8 regardless.
5. **`scripts/fetch_pepper_carrot.py` returned "0 kr pages" for Episode 06** when I tried to (re)fetch
   its truth SVGs (see Questions). The truth SVGs turned out to be already on disk, so nothing was
   downloaded and `eval` ran as specified.

## Questions

1. `scripts/fetch_pepper_carrot.py` printed `episode 06: 0 kr pages` twice in a row although the
   low-res listing and `lang/kr/*.svg` exist on the server (verified with a direct request using a
   browser User-Agent, which worked). The script's custom UA
   (`OmniScan-test-data-fetch/1.0 …`) seems to be rejected on sub-directory listings (404), while
   the top-level listing worked. Should the script fall back to a plain UA or handle the 404-with-
   existing-truth case? (No data was changed: every file I probed was already present.)
2. On the real chapter, per-box recall (0.357) is dominated by tiny SFX/credit truth boxes that the
   detector does not emit, and CER macro by tiny boxes receiving big reads (centre-in-smallest-box
   assignment). Should `eval` additionally report an area-weighted or min-area-filtered variant
   (e.g. ignore boxes < N px²) so tuning isn't driven by splat-SFX boxes? Not implemented — needs a
   decision first.
3. The card defines chrF per page of the English truth, so a chapter with many short boxes gets one
   chrF per page (11 pages → 11 scores). Region-level chrF was explicitly out of scope — confirming
   that is still the desired granularity after the first tuning round.

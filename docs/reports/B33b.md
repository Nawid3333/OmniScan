# B33b — extract.pics client and page-run selection

## Changes

Created exactly the four allowed files (no other file was touched):

- `src/omniscan/acquire/pagerun.py` — `PageSelection` and `select_pages(urls, *, min_run=3, min_share=0.5)`.
  Single pass computing a verdict per URL (duplicate → format suffix → `filters.url_looks_like_page` →
  thumbnail-in-name), then one run-detection pass over the survivors: candidates grouped by
  `(host, directory, pattern)` with `pattern = re.sub(r"\d+", "#", last_path_segment)`; the largest group
  (ties: earliest first member in document order) wins only when `len >= min_run` and
  `len / len(candidates) >= min_share`. `kept`/`dropped` are emitted by a final pass over the verdicts, so
  both lists are exact document order and every input URL appears exactly once.
- `src/omniscan/acquire/extractpics.py` — `ExtractPicsClient` implementing `Extractor`: DRM check before any
  traffic; `POST /v0/extractions` then `GET /v0/extractions/<id>` polling with `pending|running → done`;
  retries (5xx + transport errors with `0.5 * 2**attempt` back-off, 429 with capped `Retry-After` /
  `5 * (attempt + 1)` fallback) capped at `max_retries`; 401/402/422/404/other-4xx mapped per spec;
  client-side leaky-bucket rate limiter (`deque` of request times, `requests_per_minute` in any 60 s
  window); `__repr__` shows only the base URL; context manager closes only a client it created itself.
- `tests/unit/test_acquire_pagerun.py` — 9 tests: the golden fixture (43 URLs → exactly the 11
  `expected_pages`, dropped reasons 25 × `not a page format (.svg)`, 4 × `not part of the page run`,
  2 × `thumbnail size in name`, 1 × `url contains 'icon'`), duplicates, hashed names, `min_share` gate,
  tie-break, extensionless/query/upper-case suffix, thumbnail names, empty input, and a
  document-order/exactly-once property test.
- `tests/unit/test_acquire_extractpics.py` — 23 tests over `httpx.MockTransport` + fake clock advanced in
  the fake sleep, covering the card's list: happy path (raw `Authorization: test-key`, JSON body, paths,
  `2.5` poll sleeps), advanced mode (body, 2 credits, 301/181 timeout moments), duplicate/URL-less image
  dropping with `page_url` fallback, `failed`/unknown status with appended body message, 401/402 (single
  request), 422 exact message, 404-while-polling, 418 with body snippet, non-JSON/`{}` 2xx envelopes,
  5xx and `ConnectError` retry schedules `[0.5, 1.0]` and exhaustion after 4 requests, `Retry-After` 7 /
  900→60 / missing → 5, 10, 429-forever → `QuotaError` after 3 retries, DRM refusal with zero requests,

## Deviations

- Repo-wide `uv run ruff format .` also reflowed the code blocks inside `docs/tasks/B33b.md` and
  `docs/tasks/B33c.md`. Those files are off-limits for this card, so I restored both to their committed
  content; the repo-wide formatter still reports them as needing reformat (pre-existing state, owned by
  the director). My four files are format-clean.
- Timeout check placement: `clock() - start > timeout_s` is evaluated after each poll sleep and before the
  next GET. With `poll_interval_s=1.0` this raises at exactly t=181 (basic) / t=301 (advanced), which the
  card's tests pin down; the final poll GET past the deadline is never sent.
- `_throttle` sleeps and re-checks in a loop until a slot is free (rather than a single sleep) so the
  sleep-then-drop-expired-entries ordering can never spin; for the card's single-step case the behaviour
  is identical (one sleep of `60 - (now - oldest)`, then expired entries drop).
- The 429 fallback `5 * (attempt + 1)` applies only when `Retry-After` is missing or not an integer;
  parsed header values are capped at 60 (spec-literal reading).
- Extra test beyond the card's list: `test_polling_stops_at_the_timeout_moment` pins the exact fake-clock
  moment (181.0) at which the basic timeout fires.

## Module under review (production code — you must NOT change it)
`src/omniscan/slicer/strategies.py` (`fixed`, `simple_gutter`, the gutter-run finder, the strategy dispatcher,
blank/source-file post-processing) and `src/omniscan/slicer/compare.py`.
Their tests: `tests/unit/test_slicer_strategies.py`, `test_slicer_compare.py`, `test_slicer_compare_cli.py`.
Aim for about **25-35 mutants total**, spread across: cut-position arithmetic, the strategy-selection/dispatch
logic, merge rules for adjacent slices, tie-breaking between candidate cuts, gutter-run length thresholds, and any
median/mean calculation.

## Protocol (follow it exactly — a harness does the mechanical part; do NOT edit production files by hand)
1. Read the module and its tests (`Read` only; do not run anything yet). Create the directory
   `tests/mutants/slicer_strategies/` (mutant lists are kept in the repo: see `tests/mutants/README.md`).
2. Write **one mutants file**, `tests/mutants/slicer_strategies/strategies.py`, in a single `Write` call. It defines
   `MUTANTS = [(file, old, new, label), ...]` where `old` is a snippet that occurs **exactly once** in `file`
   (include neighbouring text if needed), `new` is the mutated snippet and `label` a few words (`"flip < to <="`).
   Spread the 25-35 mutants over these kinds: flip a comparison (`<` `<=` `>` `>=` `==` `!=`), off-by-one on a
   constant or index, `and` <-> `or`, remove a guard or an `if` branch, drop a `not`, swap `min`/`max`, change a
   constant (0/1, a threshold, a default), change a loop bound or slice end, swap two arguments, return the wrong
   variable, break tie-breaking/sorting, drop a `+ 1`/`- 1`, change rounding (`floor`/`ceil`/`round`). Prefer
   mutants that change behaviour a user would see; do not include mutants you already know are equivalent.
3. Validate, then run: `uv run python scripts/mutate.py check tests/mutants/slicer_strategies/strategies.py` (every
   `old` found exactly once, mutant compiles; fix invalid entries) and `uv run python scripts/mutate.py run
   tests/mutants/slicer_strategies/strategies.py -t tests/unit/test_slicer_strategies.py -t
   tests/unit/test_slicer_compare.py -t tests/unit/test_slicer_compare_cli.py`. It applies each mutant, runs the
   tests, restores the file and prints one `KILLED` / `SURVIVED` line per mutant. The harness restores every file
   itself; afterwards `git diff --stat -- src` must show nothing.
4. For every `SURVIVED` mutant decide: *equivalent* (no output can change — list it in the report) or a real gap.
   For each real gap write a test (append to the relevant existing test file, or a new
   `tests/unit/test_slicer_strategies_mutation_gaps.py`) that **fails with the mutation and passes on the
   original**; small hand-made inputs, exact expected values, no random data. Then prove it with `uv run python
   scripts/mutate.py run tests/mutants/slicer_strategies/strategies.py -t <the test files> --only <indices of the
   former survivors>`: they must now print `KILLED`. Add a second round of ~10 fresh mutants around the code you
   just looked at if time allows.
5. **Commit early:** once the first pass of mutants has been run and classified, append the rows to
   `docs/reports/Q6.md` and commit (`Q6: WIP slicer mutants`); you have a hard limit of 150 tool calls in total, and
   a run that ends without a commit is thrown away. At about 110 calls stop mutating and write the final report.
6. At the end: `git diff --stat -- src` **empty** (no production change), the mutants file committed under
   `tests/mutants/slicer_strategies/` (add a row for it to `tests/mutants/README.md`), `uv run pytest -q` all green
   (the full run includes GPU tests), `uv run ruff format . && uv run ruff check .` clean, `uv run pyright` clean.
   If you believe production code has a real bug (a test you wrote against the intended behaviour fails on the
   original), do NOT fix it: write the finding under Questions with a minimal reproduction and mark the test
   `@pytest.mark.xfail(strict=True, reason="<what is wrong>")`.

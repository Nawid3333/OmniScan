# B33 — Web viewer: on-demand run buttons + an editable in-place translation view

**Owner:** GLM builder · **Branch:** `B33` · **Worktree:** `V:\OmniScan-wt\B33` (sibling of the repo, created by `scripts/omni_builder.py`)
Read `CLAUDE.md` first. It overrides nothing below but applies everywhere.

## Why (context, not instructions)
The owner reviewed the web debug viewer live and asked for two things: (1) when a view has nothing
to show because a stage hasn't run yet, let them click a button right there to run it, instead of
switching to a terminal; (2) the Translation view's table-of-candidates is good for comparing runs,
but for just reading/fixing the final English text, seeing it laid out on the actual pages — in
place, at each bubble's real position — with click-to-edit is much more useful, "not in a grid."

The backend for both is already built and tested (director work, this session, not part of this
card): `POST /api/series/{series}/chapters/{chapter}/run` (body `{"through": "<stage>"}`, queues
every `omniscan.pipeline.stages.STAGE_ORDER` stage up to and including `through`; 202 with
`{"job_id", "stages"}`; 422 for an unknown stage, 404 for an unknown chapter, 415 for a non-JSON
content type), `GET /api/jobs/{job_id}` (200 with `{"id","series","chapters","stages","status",
"attempts","max_attempts","error"}`, `status` one of `"queued"|"running"|"paused"|"done"|"failed"|
"cancelled"`; 404 for an unknown id), and `PUT /api/series/{series}/chapters/{chapter}/final/{region_id}`
(body `{"text": "..."}`, overwrites that region's final line, sets `decision="manual"`; 200 with the
new `FinalLine`; 404 if final.json or the region is missing, 422/415 for a bad body/content-type).
`webui/src/api.ts` already has typed wrappers: `postRun(series, chapter, through) -> Promise<RunResult>`,
`getJob(jobId) -> Promise<Job>`, `putFinalLine(series, chapter, regionId, text) -> Promise<FinalLine>`
(read them — they're your contract, do not change their signatures). When `omniscan serve` runs for
real it also drains the queue in the background, so a real `POST run` actually executes; that's
already true today and nothing here changes it.

**The real Solo Leveling data is available for manual verification**: `uv run omniscan serve` then
`npm run dev` in `webui/`, series `SoloLeveling`, chapters `Chapter 1`/`Chapter 2` — every stage has
already run on both, so you'll need to delete an artifact file (e.g. `work/SoloLeveling/Chapter 1/
layout.json`) to see a "run this" button fire for real, the same way the director verified the
backend endpoints this session (see `docs/reports/B33.md`'s expected verification section below).

## Part A — `RunButton.svelte` (a "produce this" button with progress)

### Interfaces (exact — do not rename or change signatures)
```ts
// run.ts — pure, no DOM, no Svelte
export type RunPhase = "idle" | "queued" | "running" | "done" | "failed";

export interface RunState {
  phase: RunPhase;
  error: string | null; // set only when phase is "failed"
}

/** `Job.status` -> the `RunPhase` a poll of it should show. "paused"/"cancelled" both map to
 *  "failed" (from this button's point of view, the job did not produce the data — show the retry
 *  button either way; there is no owner-facing distinction worth making here). */
export function phaseOf(status: import("./api").JobStatus): RunPhase;

export const POLL_INTERVAL_MS = 1500;
```

`RunButton.svelte` props: `{ series: string; chapter: string; through: string; label?: string;
onDone: () => void }`. `label` defaults to `` `Run through ${through}` ``. Behaviour:
- Renders a `<button>` with the label when `phase` is `"idle"` or `"failed"` (on `"failed"`, also
  show `error` in a `<p style="color:#dc2626;">` right above the button, and change the button's own
  text to `"Retry"`).
- On click: call `postRun(series, chapter, through)`, set `phase` to `"queued"`, store the returned
  `job_id`, start polling `getJob(job_id)` every `POLL_INTERVAL_MS` (use `setInterval`, clear it with
  `clearInterval` both when the phase leaves `"queued"`/`"running"` and in the component's own
  cleanup via `$effect`'s teardown / `onDestroy` — do not leak a timer across a series/chapter change
  or unmount).
- Each poll: set `phase = phaseOf(job.status)`. On `"failed"`, set `error = job.error`. On `"done"`,
  stop polling and call the `onDone` prop once (this is what makes the parent view reload its data —
  e.g. `OcrView` passes `onDone={() => load(series, chapter)}`, reusing its own existing `load`).
- While `phase` is `"queued"` or `"running"`, render that word (not the button) plus the queued
  stage list, e.g. `"queued: ingest, slice, detect, ocr…"` / `"running: ingest, slice, detect, ocr…"`
  (`job.stages.join(", ")`from the `postRun`/`getJob` result — `postRun`'s own response already has
  `stages`, use that immediately after queuing so there's no flash of emptiness before the first poll
  resolves).
- A `series`/`chapter` prop change (the user picked a different chapter while a poll was in flight)
  resets to `"idle"` and stops any in-flight polling for the old chapter — mirror the existing
  `$effect(() => { const s = series; const c = chapter; ...; void load(s, c); })` reset pattern
  already used in every view in this folder.

### Where to place it (replaces the static message; the surrounding `{#if error}...{/if}` etc. stays,
only the exact `<p>` line already found via `grep -rn "no .*\.json yet\|no output yet" webui/src`
before this card was written is what you replace)
| View | Replace this line | `through` |
|---|---|---|
| `SlicerView.svelte` | `<p>{error} — no ingest.json/slices.json yet? run ingest and slice first.</p>` | `"slice"` |
| `OcrView.svelte` | `<p>{error} — no ocr.json yet — run ocr first.</p>` | `"ocr"` |
| `TranslationView.svelte` | `<p>no ocr.json yet — run ocr first</p>` | `"ocr"` |
| `InpaintView.svelte` | `<p>{error} — no inpaint.json yet — run inpaint first.</p>` | `"inpaint"` |
| `LayoutView.svelte` | `<p>{error} — no layout.json yet — run typeset first.</p>` | `"typeset"` |
| `ReaderView.svelte` | `<p>no output yet — the export stage has not produced images for this chapter</p>` | `"export"` |

Each replacement keeps the original text (still tells the reader what's missing) and adds the button
below it, e.g.:
```svelte
<p>{error} — no ocr.json yet.</p>
<RunButton {series} {chapter} through="ocr" onDone={() => load(series, chapter)} />
```
`translate`/`judge` are deliberately **not** wired to any button (they need a live Ollama/cloud
credential and a profile choice that a one-click button can't make responsibly) — do not add one for
them; if a view's missing-data message ever mentions those stages specifically, leave it as plain
text.

## Part B — `EditView.svelte`: the page, in place, with the final text overlaid and editable

### Interfaces (exact — do not rename or change signatures)
```ts
// edit.ts — pure, no DOM, no Svelte
import type { FinalLine, LayoutItem } from "./api";

/** region_id -> current final text, or "" when final.json has no line for that region (layout.json
 *  items should always have a matching final.json line in practice - editing then just fails with
 *  the server's 404, shown as a normal save-error, nothing special needed for it). */
export function textByRegion(lines: FinalLine[]): Record<string, string>;

/** A rough, readable (not pixel-exact) inline style for one overlay text box, from its LayoutItem:
 *  `font-size: {size_px}px; color: rgb({color}); text-align: {align}; ...`. Reuse
 *  `fontRoleColor`/`alignLabel` from `./layout` for anything they already cover — this function is
 *  only for the parts they don't (font-size, the color triple -> CSS rgb(), text-align mapping). */
export function overlayStyle(item: LayoutItem): string;
```

`EditView.svelte` props: `{ series: string; chapter: string }` (same shape as every other view).
Behaviour:
- Loads `getIngest`, `getLayout`, `getFinal` (like `LayoutView` already loads ingest+layout — copy
  that error/loading/empty-state structure exactly, including the `{error} — no layout.json yet —
  run typeset first.` line, now followed by `<RunButton through="typeset" .../>` per Part A). Missing
  final.json is not a separate error state: `textByRegion([])` (empty) just means every overlay shows
  blank text, still editable (an edit that 404s because final.json itself is missing shows the normal
  save-error path — do not special-case it further).
- Background: the same raw-pages-plus-patches "clean" composite `InpaintView` already builds
  (`getInpaint`, `inpaintPatchUrl`, `stripBoxToStackBox`, `cleanClipPath`/`hasStoredPatch`/`fillCss`
  from `./inpaint`) — copy that layering (raw `<img>` stack, then the patch/fill layer) verbatim, but
  **always fully clean** (no reveal slider — call `cleanClipPath(100)` for the clip layer's style, or
  inline the equivalent "no clip" style if that reads clearer; either way there is no slider in this
  view). If `getInpaint` itself fails (no inpaint.json yet), fall back to just the raw page stack, no
  clean layer, and show `<RunButton through="inpaint" .../>` above the pages (not blocking — the
  editable overlay still works over raw pages, just with the original foreign text still visible
  underneath, which is a legitimate, usable state, not an error).
- Overlay: for each `layout.json` item, at `stripBoxToStackBox(files, item.box)`, an absolutely
  positioned `<div>` sized to that box, background semi-opaque white (`rgba(255,255,255,0.85)`) so
  text reads over busy art, styled with `overlayStyle(item)`, showing `textByRegion(final.lines)
  [item.region_id] ?? ""`.
- Click-to-edit: clicking that div swaps it for a `<textarea>` of the same position/size, pre-filled
  with the current text, autofocused. `Enter` without Shift, or `blur`, commits: call
  `putFinalLine(series, chapter, item.region_id, newText)`; while it's in flight show a thin "saving…"
  label at the box's corner; on success update local state (so the div immediately reflects the saved
  text without a full reload) and swap back to the div; on failure, show the error next to the box
  (`<span style="color:#dc2626;">`) and keep the textarea open (with the attempted text still in it)
  so the edit isn't lost. `Escape` cancels without saving and reverts the textarea's value to the
  last-saved text.
- Add `EditView` to `App.svelte` as a 7th mode (`"edit"`), button label `"Edit"`, placed after
  `"Layout"` and before `"Filtered"` (which is series-only, not chapter-only, and stays last) — same
  wiring pattern as every other chapter view already there (`{#if view === "edit"}<EditView {series}
  {chapter} />{/if}`).

## Definitions (no interpretation needed)
- "Clean" background = every `InpaintItem` whose `method !== "none"` gets its patch/fill drawn on top
  of the raw page, exactly like `InpaintView` at `reveal=100` — there is no partial-reveal state in
  this view.
- A `RunButton` never appears more than once per view's missing-data message — one button per view,
  running the one stage that view itself needs (per the table), not every stage.
- `overlayStyle` need not reproduce the real font (`item.font` is a filename like
  `ComicNeue-Bold.ttf` — do not attempt to load/register real fonts here); a generic sans-serif at
  `item.size_px` is enough. Getting the reader to *the right piece of text at the right place, and
  letting them fix it*, is the goal — not a pixel-perfect typeset preview (that already exists as the
  real exported page in the Reader view).

## Acceptance tests (must exist and pass)
1. `phaseOf`: every `JobStatus` value maps to the documented `RunPhase` (table-driven test covering
   all six).
2. `RunButton` polling lifecycle — since this project's `.svelte` files aren't unit-tested directly
   (only their `.ts` helpers are, per this folder's existing convention: `reader.ts`/`strip.ts`/
   `layout.ts`/`inpaint.ts`/`translation.ts`/`ocr.ts`/`filtered.ts` each have a `.test.ts`, no
   `.svelte` file does), there is no `RunButton.test.ts` — verify its actual polling/reload behaviour
   manually against the real server (see the report's required verification below) instead.
3. `textByRegion`: empty list -> `{}`; two lines -> both keys present with their `text`; a duplicate
   `region_id` (should not happen from a real final.json, but the function must not crash) -> the
   last one wins (matches `Object.fromEntries`/`Map` "last write wins" semantics — do not special-case
   it further).
4. `overlayStyle`: a `LayoutItem` with `align="right"`, `color=[200,30,30]`, `size_px=32` produces a
   string containing `text-align: right`, `color: rgb(200, 30, 30)`, `font-size: 32px` (substring
   assertions, not a full-string equality — the exact property order doesn't matter, whether the
   values themselves are correct does).

## Out of scope
- `translate`/`judge`/`story`/`glossary`/`reference` run buttons (need live credentials/profile
  choices a button can't make) — leave their views' own missing-data messages as plain text.
- Real font rendering, pixel-accurate box fitting, multi-line wrapping inside the overlay (the real
  typeset preview already exists as the exported final page, viewable in Reader).
- Any change to `webui/src/api.ts` (already has everything this card needs) or to any
  `src/omniscan/**` Python file (the backend is already built and tested).
- A "run everything" button that queues the whole `STAGE_ORDER` regardless of which view is open —
  each view's button only ever requests what that one view itself needs.

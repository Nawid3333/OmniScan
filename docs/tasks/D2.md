# D2 — Detect: reject an implausibly oversized bubble when pairing text with its speech bubble

**Owner:** GLM builder · **Branch:** `D2` · **Worktree:** `V:\OmniScan-wt\D2` (created by `scripts/omni_builder.py`)
Read `CLAUDE.md` first. Then read `src/omniscan/detect/postprocess.py` in full, especially `_items` (the
bubble-pairing loop, `candidates = [(i, b) for i, b in enumerate(bubbles) if ioa(tb.box, b.box) >=
_TEXT_IN_BUBBLE_MIN_IOA]` and the `min(candidates, key=lambda c: area(c[1].box))` that follows), `area`, `ioa`,
and `tests/unit/test_detect_postprocess.py`'s existing bubble-pairing tests.

## Why (found by the director on real chapters, evidence gathered across two series)
Rendering a real chapter (Solo Leveling ch1) placed a caption ("A Double Dungeon!") in the wrong place on the
page — landed on top of the *previous* caption instead of its own location. Traced to the region's bubble
pairing: its own text is a tight 226,11896-539,12010 box (35682 px^2), but the detector's `bubble` class also
produced a box spanning almost the whole panel, 52,11488-710,12098 (401380 px^2) — 11.2x the text's own area.
`_items()` pairs a `text_bubble` box with the *smallest* bubble candidate whose `ioa(text, bubble) >=
_TEXT_IN_BUBBLE_MIN_IOA` (0.6) — correct when there are several candidates, but here this oversized box was
the *only* candidate clearing the threshold (a box 11x bigger than the text trivially contains 100% of it), so
it was accepted anyway. Typesetting then fits the caption inside the bubble's (wrong, huge) box, not the
text's own box, landing it far from where the text actually is.

**Evidence for where the real cutoff sits** — every `bubble`/`text_bubble` pairing's area ratio
(`bubble_area / text_area`), sorted, across six real chapters (225 pairings total):
- Solo Leveling ch1 (30 pairings): mostly 0.9-6.7, then a clean jump to **11.25 and 12.69** (the two bad ones).
- Solo Leveling ch2 (83 pairings): 1.15-7.9, nothing higher.
- Pepper&Carrot KR episodes 06/09/12/22 (112 pairings combined): 1.15-4.1, nothing higher.
There is a clear, wide gap between the highest legitimate ratio observed (7.9) and the two known-bad ones
(11.25, 12.69) — a threshold anywhere in [8, 11) separates them cleanly.

## The fix (design decided by the director — implement this shape, not a different one)
In `_items()`, add a new module constant next to `_TEXT_IN_BUBBLE_MIN_IOA`:
```python
_MAX_BUBBLE_TO_TEXT_AREA_RATIO = 8.0  # a bubble more than this much bigger than its own text is not a real fit
```
Change the `candidates` list comprehension to also require
`area(b.box) <= _MAX_BUBBLE_TO_TEXT_AREA_RATIO * area(tb.box)`, alongside the existing `ioa(...) >=
_TEXT_IN_BUBBLE_MIN_IOA` condition (both must hold). Nothing else about the candidate selection changes: when
one or more candidates remain, the smallest by area still wins (`min(candidates, key=lambda c:
area(c[1].box))`, unchanged); when *no* candidate remains (either because none met the IoA or, now, because
the only IoA-qualifying one is too big), the text box falls back to the existing no-bubble path
(`items.append(_Item("bubble_text", tb.box, None, tb.score))`) — the same path already used today when a
`text_bubble` box has no bubble detection near it at all. Do not change `_TEXT_IN_BUBBLE_MIN_IOA`,
`ioa`/`area`/`iou`, `merge_bubble_text`'s grouping logic, or anything in the cross-class-duplicate loop above
it (card D1, already merged — this is a separate, later stage of the same function).

## Definitions (no interpretation needed)
- `area(box)` (already defined, do not change it) — use it for both the bubble's and the text's area exactly
  as the candidate-selection code already does.
- The real pair above must be rejected under the new rule and must still find no other candidate (so it falls
  back to `bubble=None`): pin it as a regression test with the exact boxes given.
- A pairing at or below the ratio (e.g. the highest legitimate one observed, ~7.9) must be **unaffected** —
  write a test at a ratio comfortably under 8.0 (e.g. 5.0) that still pairs normally, so this fix cannot be
  mistaken for a general "always prefer a smaller bubble" change.
- If a text box's only candidate is rejected by the new area check, it still counts as unpaired the exact same
  way a text box with zero nearby bubbles does today — verify this by checking the existing "no candidates"
  test's assertions are the same shape you use for the new "rejected by area ratio" test.

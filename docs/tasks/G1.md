## Why
The owner asked (2026-09-19) that the director does not spend its own context on big or generated files (logs, JSON artifacts, long reports, huge modules): "if you have to look into one then let GLM do it for you". Today the only way to use GLM is a full builder run in a worktree. This card adds a **cheap, read-only question mode**: `omni_builder.py ask "QUESTION" [--file PATH …]` starts one short `claude -p` session on `glm-5.3-flash:cloud` in the main repo with **only read tools**, and prints **only the final answer** on stdout. The director then works with a 10–40 line answer instead of the raw file.

## Interface (exact)
```
uv run python scripts/omni_builder.py ask "QUESTION" [--file PATH ...] [--model MODEL] [--max-turns N] [--wait] [--cwd DIR]
```
- `QUESTION` (required, one argument); `--file` may repeat (paths relative to `--cwd`, default = the repo root); `--model` default flash (same aliases as the other commands); `--max-turns` default **25**; `--wait` = block until a builder slot is free (default: do not wait); `--cwd` default = `REPO`.
- **Exit codes:** `0` answer printed on stdout; `1` the session failed or produced no answer (message on stderr); `3` no free builder slot and `--wait` not given (message `omni-builder: no free slot (all N builders busy); use --wait or read the file yourself` on stderr); other errors as `die()` does (exit 1).
- **stdout contains only the answer text** (nothing else, no progress lines); everything else goes to stderr through `say()`.

New helpers in `omni_builder.py` (module-level, pure where possible, so they can be tested):
```python
ASK_SYSTEM = "..."                                             # constant, see below
def build_ask_prompt(question: str, files: Sequence[str]) -> str
def extract_answer(stream: bytes) -> str | None                # last {"type":"result",...} object's "result" text of a stream-json log, else None
def try_acquire_slot() -> IO[bytes] | None                     # one non-blocking pass over the slots (same lock files as acquire_slot); None when all are busy
```
- `try_acquire_slot` reuses `try_lock` and the lock-file naming of `acquire_slot` (refactor `acquire_slot` to use it, behaviour unchanged: it still loops with `time.sleep(30)` and the same `say(...)` messages).
- `ASK_SYSTEM` (passed as the first paragraph of the prompt): *You are a read-only research assistant for the OmniScan repository. Answer the question using only the Read, Grep and Glob tools. Be concise: at most 40 lines, plain text or short bullets, quote `path:line` for every claim about code, give exact numbers when asked for numbers. If the answer is not in the files, say so instead of guessing. Never print the content of secrets, API keys or `.env` files. Do not suggest changes unless asked.* `build_ask_prompt` returns `ASK_SYSTEM + "\n\nQuestion: " + question` and, when files are given, `"\n\nStart with these files (relative to the repo root): " + ", ".join(files)`.
- `extract_answer(stream)`: parse the stream line by line (`json.loads`, skip lines that are not JSON), remember the **last** object with `"type": "result"` and return its `"result"` string when it is non-empty (stripped), else `None`. If that object has `"is_error": true` return `None`.
- The session runs through the existing `run_claude(...)` with the extra arguments `--settings .builder/ask-settings.json` **instead of** the builder settings — so `run_claude` needs an optional keyword `settings: Path | None = None` (default `.builder/settings.json`, existing calls unchanged) and `permission_mode: str = "acceptEdits"` (the ask session uses `"default"`). The log goes to `LOG_DIR / f"ask-{UTC timestamp YYYYmmdd-HHMMSS}.jsonl"`; after the run `extract_answer` reads it. The working directory of the session is `--cwd`.
- `.builder/ask-settings.json`: `allow`: `Read`, `Glob`, `Grep`; `deny`: `Bash`, `Edit`, `Write`, `NotebookEdit`, `WebFetch`, `Read(~/.config/omniscan/**)`, `Read(**/.env*)`, `Read(**/secrets.env)`; `env`: `{"CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1"}`. (Reading `data/`, logs and models' JSON is allowed on purpose — that is what the director wants help with.)
- The ask session must **not** create a worktree, must not take a slot longer than the call (the handle is released on exit), and must not write to the repo.

## Acceptance tests (CPU, no Ollama, no network)
Load the script as a module with `importlib.util.spec_from_file_location("omni_builder", <path>)`; use a fake `claude` executable — a small Python script written to `tmp_path` and run through `CLAUDE_BIN` — that records its argv and stdin to a JSON file next to it and writes a canned `stream-json` transcript to stdout (the real `claude_bin()` may be replaced by monkeypatching, and `check_ollama` monkeypatched to a no-op; slots: point `LOCK_DIR` at a tmp dir by monkeypatching the module attribute).
1. `extract_answer`: a transcript with several assistant lines and a final `{"type":"result","is_error":false,"result":"  the answer\n"}` → `"the answer"`; two result objects → the last one; `is_error: true` → `None`; empty result → `None`; garbage/non-JSON lines are skipped; empty bytes → `None`.
2. `build_ask_prompt`: contains `ASK_SYSTEM`, the question, and the file list only when files are given (exact format above).
3. `try_acquire_slot`: with `SLOTS=2` returns handles for the first two calls (keep them open) and `None` for the third; after closing one handle a new call succeeds again; `acquire_slot` still works (patch `time.sleep` to raise if it is called when a slot is free).
4. `ask` end to end via `main()` with `sys.argv` patched and the fake claude: stdout (captured with `capsys`) is exactly the canned answer plus a newline and nothing else; the recorded argv contains `--settings` with a path ending `ask-settings.json`, `--model glm-5.3-flash:cloud`, `--max-turns 25`, `--permission-mode default` and does **not** contain `acceptEdits`; the recorded stdin contains the question and the `--file` names; the log file `ask-*.jsonl` exists in the (monkeypatched) `LOG_DIR`; the recorded working directory is `--cwd`.
5. All slots busy and no `--wait` → exit code 3, empty stdout, the message on stderr; with `--wait` and a slot that frees up (patch `time.sleep` to release a held handle) the call proceeds.
6. The fake claude returns an error result / no result → exit code 1 with a message on stderr and empty stdout.
7. `run` and `smoke` keep their argv (regression: the fake claude records `--settings … settings.json` and `--permission-mode acceptEdits` for `smoke`).
8. `.builder/ask-settings.json` parses as JSON and its `allow` list has exactly `Read`, `Glob`, `Grep` and `deny` contains `Bash`, `Edit` and `Write`.

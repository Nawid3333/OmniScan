## Why
CM1 (`omniscan match chapters`, merged) aligns the chapters of **two independently-sourced** chapter sets 1:1
by page art (dhash) — its whole design assumes the "same chapter" question is being asked *across* two
folders (e.g. a raw set against a `_reference_en` set). It has no way to answer a different, simpler question:
**within one chapter set, are any two chapter folders actually the same chapter** (an accidental duplicate
download, a reposted chapter re-imported under a different name, a copy-paste mistake)? `match_chapters`'s own
1:1 alignment (`align`, Needleman-Wunsch-style) is the wrong tool for this — it would only ever report one
first duplicate as "matched" and hide the other copies as unrelated "unmatched" chapters, since it forces a
bijection. What's actually needed is the raw pairwise quality matrix `_chapter_qualities` already computes
internally (and currently throws away except for the chosen 1:1 pairs), read directly: any pair of chapters
scoring very high page-coverage quality against each other is almost certainly the same underlying pages
imported twice.

## The fix (design decided by the director — implement this shape, not a different one)
1. **`src/omniscan/match/chapters.py`**: rename `_chapter_qualities` to `chapter_qualities` (drop the leading
   underscore — it becomes a public function of this module; no behaviour change, no signature change). Update
   its one existing call site inside `match_chapters` to the new name. Leave everything else in this file
   untouched (including `_read`, `_chapter_match`, `_add_runner_ups`, `_best_other` — still private).
2. New module `src/omniscan/match/duplicates.py`:
   ```python
   """Duplicate/near-duplicate chapter detection within one chapter-set directory.

   Reuses chapters.py's own page-coverage quality metric (chapter_qualities), comparing every chapter of
   `root` against every other chapter of the *same* `root` -- unlike match_chapters's 1:1 alignment across
   two independent sets, a chapter here may appear in more than one reported pair (e.g. three accidental
   copies of the same chapter each pair with the other two). A high quality normally means the same pages
   were imported twice, not "these are similar chapters of the same story" -- ordinary consecutive chapters
   of one series share very little page-level art in practice."""

   class DuplicateThresholds(Model):
       """The knobs of one duplicate-detection run; stored in the report so its numbers can be reproduced."""

       page_similarity: float = 0.75  # dhash similarity at/above which two pages may align
       page_gap: float = 0.25  # page-alignment penalty for leaving a page unmatched
       min_quality: float = 0.9  # page-coverage quality at/above which two chapters are flagged as duplicates

   class DuplicatePair(Model):
       """One pair of chapters flagged as likely duplicates of each other."""

       a: str  # chapter folder name (natural-sort earlier of the two)
       b: str  # chapter folder name (natural-sort later of the two)
       quality: float  # same page-coverage quality formula as chapters.ChapterMatch.quality

   class DuplicateReport(Artifact):
       """The result of one duplicate-detection run (`omniscan match duplicates`)."""

       root: str
       thresholds: DuplicateThresholds
       duplicates: list[DuplicatePair]  # sorted by descending quality, ties broken by (a, b)

   def find_duplicate_chapters(root: Path, thresholds: DuplicateThresholds | None = None) -> DuplicateReport:
       """Every pair of distinct chapters under `root` whose page-coverage quality is >= min_quality.

       Raises ValueError (same condition and message style as chapters.match_chapters) when `root` has no
       chapter folders at all. A chapter folder with no page images can never appear in a reported pair (its
       hashes list is empty, giving 0.0 quality against anything)."""
   ```
   Implementation shape for `find_duplicate_chapters` (follow exactly):
   ```python
   thresholds = DuplicateThresholds() if thresholds is None else thresholds
   chapter_dirs = list_chapters(root)
   if not chapter_dirs:
       raise ValueError(f"no chapter folders with page images under {root}")
   names = [p.name for p in chapter_dirs]
   chapters_arg = list(zip(names, [chapter_hashes(p) for p in chapter_dirs], strict=True))
   quality, _page_matches = chapter_qualities(
       chapters_arg,
       chapters_arg,
       Thresholds(
           page_similarity=thresholds.page_similarity,
           page_gap=thresholds.page_gap,
           min_quality=thresholds.min_quality,
       ),
   )
   pairs = [
       DuplicatePair(a=names[i], b=names[j], quality=round(float(quality[i, j]), 4))
       for i in range(len(names))
       for j in range(i + 1, len(names))
       if quality[i, j] >= thresholds.min_quality
   ]
   pairs.sort(key=lambda pair: (-pair.quality, pair.a, pair.b))
   return DuplicateReport(root=str(root), thresholds=thresholds, duplicates=pairs)
   ```
   The `Thresholds(...)` built here is `chapters.Thresholds` (imported), used purely as the parameter
   `chapter_qualities` expects — its `chapter_gap`/`review_quality` fields are irrelevant to
   `chapter_qualities` (confirm by reading the function: it only ever reads `.min_quality`, `.page_similarity`,
   `.page_gap`) and are left at their `chapters.Thresholds` defaults, unused. Only `i < j` pairs are considered
   (never `i == j`, a chapter is never "a duplicate of itself"; never both `(i,j)` and `(j,i)`, they're the
   same pair since the quality matrix is symmetric here).

## Definitions (no interpretation needed)
- `min_quality`'s default of **0.9** is a deliberately conservative director-picked starting point (no real
  duplicate-chapter incident exists yet to tune it against, unlike D2's 8x ratio) — much higher than
  `chapters.Thresholds.min_quality`'s own default of 0.3, which answers "is this plausibly the same chapter
  across two different sources with different compression/lettering" (a much looser bar) rather than "are
  these literally the same images imported twice."
- A pair is only ever reported once, with `a` the natural-sort-earlier folder name of the two (never both
  `(x, y)` and `(y, x)`).
- Sorting: `duplicates` is sorted by descending `quality` first, then ascending `(a, b)` folder name to break
  an exact tie (e.g. two unrelated duplicate pairs that both score `1.0`).
- A pinned exact-duplicate example (build with `write_raw_series` and `page_seeds`, same as
  `test_match_chapters.py`'s own style): a chapter set with `{"Chapter 001": page_seeds(1, 6), "Chapter 001
  copy": page_seeds(1, 6), "Chapter 002": page_seeds(500, 6)}` — the first two folders share **identical**
  page seeds, so their pages are pixel-identical and their dhashes are bit-identical, giving page similarity
  `1.0` for every page and therefore chapter quality exactly `1.0` (not just "high" — pin the exact float).
  `find_duplicate_chapters` on this set must report exactly one pair, `DuplicatePair(a="Chapter 001",
  b="Chapter 001 copy", quality=1.0)`, and "Chapter 002" must not appear in any pair.
- A pinned no-duplicates example: three chapters built with three well-separated `page_seeds` ranges (e.g.
  `page_seeds(1, 6)`, `page_seeds(500, 6)`, `page_seeds(9000, 6)`) must yield `duplicates == []` at the
  default `min_quality`.
- Empty `root` (no chapter folders at all): `find_duplicate_chapters` raises `ValueError` whose message
  matches `match_chapters`'s own wording shape (`f"no chapter folders with page images under {root}"`).

# B5 — Web debug tool v0 (chapter browser + slicer view)

**Owner:** GLM builder · **Branch:** `B5` · **Worktree:** `~/projects/omniscan-wt/B5`
Read `CLAUDE.md` and `docs/ARCHITECTURE.md` first.

## Goal
A local web app that lets the user (and scanlation groups) actually **see** what the pipeline has done so
far: pick a series/chapter and view the raw pages stacked as the chapter strip, with the slicer's bands, cut
lines (forced cuts in red), and original file boundaries (dashed) drawn on top — the "slicer view" the plan
calls for, satisfying the "raw ↔ slices view with synced scroll" requirement by drawing both on one scrollable
surface rather than two separate panes (a true side-by-side compare view can be a later card). This is v0:
read-only, no auth, local-only. Two independently runnable pieces: a FastAPI backend serving existing pipeline
JSON artifacts and raw images, and a Svelte+TS frontend (Vite) that renders them.

## Part 1 — Backend (`src/omniscan/web/app.py`)

```python
def create_app(cfg: Config) -> FastAPI: ...
```

Five read-only JSON/file endpoints, all under `/api`:

1. `GET /api/series` → `200 [str, ...]` — subdirectory names of `cfg.paths.library_root` that don't start
   with `_` or `.`, sorted via `natural_key`. `cfg.paths.library_root` not existing → `200 []` (not an error).
2. `GET /api/series/{series}/chapters` → `200 [str, ...]` via `SeriesPaths.from_config(cfg,
   series).chapters()`. Unknown series (no such library dir) → `200 []`.
3. `GET /api/series/{series}/chapters/{chapter}/ingest` → the **exact bytes** of `ingest.json` for that
   chapter (`Response(content=path.read_bytes(), media_type="application/json")` — do not round-trip through
   the pydantic model, serve the file as-is). Missing file → `404 {"detail": "ingest.json not found"}`.
4. `GET /api/series/{series}/chapters/{chapter}/slices` → same pattern as #3 for `slices.json`, 404 with
   `{"detail": "slices.json not found"}` if absent.
5. `GET /api/series/{series}/chapters/{chapter}/pages/{index}` → the raw image **file bytes** of the
   `SourceFile` at that `index` in the chapter's `ingest.json` (`FileResponse` or an equivalent byte response
   with the correct `Content-Type` guessed from the file's suffix via `mimetypes.guess_type`). 404 with a
   clear `detail` message if `ingest.json` is missing, or if `index` is out of range for `ingest.json.files`.

All path parameters (`series`, `chapter`) are used only to build `SeriesPaths`/`ChapterPaths` — never
concatenated into a raw filesystem path string (use the existing `ChapterPaths`/`SeriesPaths` methods so
traversal outside `library_root`/`work_root` is impossible by construction).

`create_app` mounts CORS middleware allowing `http://localhost:5173` (Vite's default dev port) so the two dev
servers can talk to each other; make the allowed origin list a keyword argument
`create_app(cfg: Config, *, cors_origins: Sequence[str] = ("http://localhost:5173",)) -> FastAPI` so tests can
override it if needed (they don't have to).

## Part 3 — Frontend (`webui/`, Vite + Svelte + TypeScript)

`webui/package.json`: name `"omniscan-webui"`, `"private": true`, `"type": "module"`, scripts `"dev": "vite"`,
`"build": "vite build"`, `"check": "svelte-check --tsconfig ./tsconfig.json"`, `"test": "vitest run"`.
devDependencies: `vite`, `@sveltejs/vite-plugin-svelte`, `svelte`, `typescript`, `svelte-check`, `vitest` —
pin major versions loosely (`^5` for vite, `^4` or current for svelte — whatever `npm create vite@latest` with
the `svelte-ts` template would currently produce; if unsure of exact current versions, run
`npm create vite@latest webui -- --template svelte-ts` to scaffold it and then edit the generated files to
match everything specified below, rather than guessing version numbers by hand).

`webui/vite.config.ts`: the svelte plugin, plus `server: { proxy: { "/api": "http://localhost:8000" } }` so
`npm run dev` forwards API calls to the backend without CORS ever mattering in dev.

`webui/src/api.ts` — typed fetch wrappers, one per backend endpoint:
```typescript
export interface SourceFile { index: number; name: string; width: number; height: number; y0: number; y1: number; scale: number; }
export interface IngestArtifact { strip_width: number; strip_height: number; files: SourceFile[]; }
export interface Band { y0: number; y1: number; color: [number, number, number]; is_gradient: boolean; }
export interface Slice { index: number; y0: number; y1: number; blank: boolean; forced_cut: boolean; filtered: boolean; source_files: number[]; }
export interface SlicesArtifact { strip_width: number; strip_height: number; bands: Band[]; slices: Slice[]; }

export async function listSeries(): Promise<string[]>;
export async function listChapters(series: string): Promise<string[]>;
export async function getIngest(series: string, chapter: string): Promise<IngestArtifact>;   // throws on 404
export async function getSlices(series: string, chapter: string): Promise<SlicesArtifact>;   // throws on 404
export function pageImageUrl(series: string, chapter: string, index: number): string;  // just builds the URL, no fetch
```
Every fetch call URL-encodes `series`/`chapter` with `encodeURIComponent`.

`webui/src/strip.ts` — the pure coordinate-mapping function (this is the part that must be exactly right;
everything else in the frontend is presentation):
```typescript
/** Convert a strip-space y-coordinate (as used in ingest.json/slices.json) into a y-offset in the DOM
 * where each file's raw image is stacked at its own NATURAL (unscaled) height, in file order, with no gaps.
 * Finds the file whose [y0, y1) strip-space range contains yStrip (last file whose y0 <= yStrip if yStrip
 * is beyond every file's y1, e.g. exactly at strip_height); maps proportionally within that file:
 *   stackTop(file) = sum of every earlier file's natural `height`
 *   fraction = (yStrip - file.y0) / (file.y1 - file.y0)   // guard divide-by-zero: fraction = 0 if y1 == y0
 *   result = stackTop(file) + fraction * file.height
 */
export function stripYToStackY(files: SourceFile[], yStrip: number): number;

/** Total stacked height: sum of every file's natural `height`. */
export function stackTotalHeight(files: SourceFile[]): number;

/** The natural (unscaled) width to use for the stack container: the maximum `width` across `files`. */
export function stackWidth(files: SourceFile[]): number;
```

`webui/src/App.svelte` — root component: two `<select>` elements (series, chapter) populated via `listSeries`/
`listChapters` on mount/on series change; renders `<SlicerView {series} {chapter} />` once both are chosen.
Loading and error states (e.g. "no ingest.json yet — run ingest first") are shown as plain text, not styled
elaborately — this is a debug tool, not a product UI.

`webui/src/SlicerView.svelte` — given `series`/`chapter` props: fetches `getIngest` and `getSlices` on
mount/on prop change (a fetch failure, e.g. 404, shows an inline error message instead of throwing
uncaught). Renders:
- A container `div` of width `stackWidth(files)` and height `stackTotalHeight(files)`.
- Inside it, each file's raw image (`<img src={pageImageUrl(...)}>`) positioned with `position: absolute; top:
  <cumulative stackTop>px` at its natural width/height (no CSS scaling — `width`/`height` attributes set to
  the file's own `width`/`height`).
- An absolutely-positioned `<svg>` overlay, same width/height as the container, `pointer-events: none`,
  drawing:
  - one translucent green `<rect>` per `Band`, full width, from `stripYToStackY(files, band.y0)` to
    `stripYToStackY(files, band.y1)`;
  - one horizontal `<line>` per slice boundary (at every `slice.y0`, plus the final `slice.y1` of the last
    slice), full width, colored **red** if the slice starting at that boundary has `forced_cut === true`,
    otherwise a dark blue/black, with a small `<text>` label near the line showing that slice's height in
    strip-space px (`slice.y1 - slice.y0`);
  - one **dashed** gray horizontal `<line>` at `stripYToStackY(files, file.y0)` for every file after the
    first (the original raw-file boundaries), visually distinct from the slice cut lines above.
The whole thing sits inside a normally-scrolling block (no virtualization needed for v0 — chapters are at
most a few dozen images).

## Acceptance tests

**Backend** (`tests/unit/test_web_app.py`, using `fastapi.testclient.TestClient` against a `tmp_path` library/
work root wired through a `Config` built with overridden `paths`):
1. `GET /api/series` on an empty/missing library root → `200 []`.
2. `GET /api/series` with 2 series directories (one prefixed `_`) → only the non-`_` one listed.
3. `GET /api/series/{s}/chapters` returns chapter names in reading order for a series with "Chapter 2",
   "Chapter 10", "Chapter 1" directories → `["Chapter 1", "Chapter 2", "Chapter 10"]`.
4. `GET /api/.../ingest` on a chapter with a real `ingest.json` written to its work dir → `200`, body bytes
   equal the file's own bytes exactly.
5. `GET /api/.../ingest` with no `ingest.json` → `404`.
6. `GET /api/.../slices` — same two cases as ingest (present/absent).
7. `GET /api/.../pages/{index}` serves the correct raw file's bytes with a `image/jpeg` (or matching)
   content-type, for an `index` present in a real `ingest.json`.
8. `GET /api/.../pages/{index}` with `index` out of range, or no `ingest.json` at all → `404`.
9. A `series`/`chapter` value containing `../` segments cannot escape `library_root`/`work_root` (assert the
   response is a clean 404, not a file from outside the configured roots, and does not raise an unhandled
   exception).

**Frontend** (`webui/src/strip.test.ts`, vitest, no DOM/browser needed — pure functions only):
10. `stripYToStackY`/`stackTotalHeight`/`stackWidth` on 3 files with `scale=1.0` reproduce their own
    strip-space coordinates as stack coordinates (no scaling, no gaps) — pick concrete numbers and assert
    exact results.
11. A file with `scale=0.5` (its strip-space span is half its natural height): a `yStrip` at the file's
    midpoint maps to the file's natural-height midpoint in stack space (proportional mapping, not a raw
    subtraction).
12. `yStrip` exactly at `strip_height` (one past the last file's `y1`) maps to `stackTotalHeight(files)`
    (the boundary case, using the "last file whose `y0 <= yStrip`" rule).
13. `stackWidth` returns the maximum `width` across files, not the first or the sum.
14. A degenerate file with `y1 === y0` does not throw (fraction guarded to `0`).

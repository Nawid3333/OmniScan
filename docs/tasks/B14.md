# B14 — Page-mode passthrough in the slicer

**Owner:** GLM builder · **Branch:** `B14` · **Worktree:** `~/projects/omniscan-wt/B14`
Read `CLAUDE.md` and `docs/ARCHITECTURE.md` first.

## Goal
Long-strip webtoons get cut into slices by the uniform-band logic in `slicer/bands.py`/`cuts.py`. Page-based
manga (the eventual Japanese pack, card C10) shouldn't be cut at all — each raw page **is** the unit, 1:1. This
card adds a second, much simpler slicer entry point that turns a chapter's already-known page boundaries
(`SourceFile.y0`/`y1`, computed by ingest) directly into a `SlicesArtifact` with no band-finding, no DP cut
search and no forced cuts — a "passthrough." It does not decide *when* page mode applies (that's a later
orchestration/config card); it only provides the function.

## Interfaces (exact — do not rename or change signatures)
```python
def slice_by_pages(source_files: list[SourceFile], strip_width: int, strip_height: int) -> SlicesArtifact:
    """One Slice per SourceFile, in source_files order, boundaries exactly at that file's [y0, y1). No
    uniform-band detection, no cut planning: bands is always []. blank is always False (a full manga page is
    never treated as a blank/skippable slice, unlike a webtoon gutter). forced_cut is always False (nothing
    was forced — page mode never invents a cut). Each Slice.source_files is exactly [file.index] for the
    corresponding file (never empty, never more than one — page mode is strictly 1:1). params is
    {"mode": "page"} (a plain dict, not a SlicerConfig dump — page mode has no tunable parameters).

    Validates that source_files fully and exactly tile [0, strip_height) with no gaps or overlaps:
      - source_files may be given in any order internally re-sorted by y0 for the tiling check, but the
        OUTPUT slices/bookkeeping preserve the input list's given order (do not silently reorder the caller's
        list — if it isn't already sorted by y0 ascending, that itself is a gap/overlap-style inconsistency
        worth rejecting, see Definitions).
      - Raises ValueError if source_files is empty and strip_height != 0.
      - Raises ValueError (naming the two offending file names/indices and the gap or overlap size) if any
        adjacent pair doesn't satisfy files[i].y1 == files[i+1].y0.
      - Raises ValueError if files[0].y0 != 0.
      - Raises ValueError if files[-1].y1 != strip_height.
    An empty source_files list with strip_height == 0 is valid and returns an empty SlicesArtifact
    (slices=[], bands=[]).
    """
```

## Definitions (no interpretation needed)
- "In source_files order" for the tiling/contiguity check means: the list **as given** must already be sorted
  by `y0` ascending (this matches how `ingest_chapter` naturally produces `IngestArtifact.files` — in file
  order, which is strip order). Do not sort internally before validating; if the given order isn't already
  ascending by `y0`, treat that exactly like a gap/overlap — raise `ValueError` naming the first
  out-of-order pair. (There is deliberately only one validation pass, not a "sort first, then check" — a
  caller handing in files out of order is itself a bug worth surfacing, not silently fixing.)
- `Slice.index` is the position in the output list (0-based), independent of `SourceFile.index` (which may
  not start at 0 if, hypothetically, a caller ever passes a filtered subset — this card doesn't filter
  anything itself, but the function must not assume `source_files[i].index == i`).
- Output `Slice.y0`/`y1` are copied directly from the corresponding `SourceFile.y0`/`y1` — no recomputation.

## Acceptance tests (`tests/unit/test_slicer_page_mode.py`)
Build `SourceFile` fixtures inline in the test file (small helper, no need to touch shared fixtures).
1. Three contiguous files (`y0/y1` = `[0,1000), [1000,2200), [2200,3000)`, `strip_height=3000`) → 3 slices
   with matching `y0`/`y1`, `index` 0/1/2, `blank=False`, `forced_cut=False` on every slice,
   `source_files == [file.index]` for the matching file on each slice.
2. `bands == []` always, `params == {"mode": "page"}`.
3. `strip_width`/`strip_height` on the returned artifact equal the arguments passed in.
4. A gap between two files (`file0.y1=1000`, `file1.y0=1005`) raises `ValueError` whose message names both
   files and the gap size.
5. Overlapping files (`file1.y0 < file0.y1`) raises `ValueError` naming both files.
6. `source_files[0].y0 != 0` raises `ValueError`.
7. `source_files[-1].y1 != strip_height` raises `ValueError`.
8. Files given out of `y0` order (even if they'd tile correctly once sorted) raises `ValueError` — do not
   silently sort.
9. Empty `source_files` with `strip_height=0` → `SlicesArtifact(slices=[], bands=[], strip_width=W,
   strip_height=0, params={"mode": "page"})`, no error.
10. Empty `source_files` with `strip_height > 0` raises `ValueError`.
11. A single file spanning the whole strip (`y0=0, y1=strip_height`) → exactly one slice.
12. `SourceFile.index` values that don't start at 0 (e.g. `[3, 4, 5]`, still contiguous in `y0`/`y1` and
    already given in that order) still work correctly — each `Slice.source_files` is `[3]`, `[4]`, `[5]`
    respectively, and `Slice.index` is still `0, 1, 2`.

## Why
Owner spec 2026-09-20: a run can be **automatic** (today's behaviour) or **step-by-step**: after every stage the user sees a preview of **one chapter** and decides to continue or stop — before hours of GPU and LLM time are spent on a whole series with wrong settings. The same events will drive the desktop app's run view. The pipeline runs in three passes (vision, text, render) over *all* chapters per pass (models stay loaded per pass); to give a preview of the translation before OCR-ing 200 chapters, step mode runs **the preview chapter through all passes first**, then the remaining chapters automatically.

## Interfaces (exact)
```python
# pipeline/runner.py (additions)
type RunMode = Literal["auto", "step"]

@dataclass(frozen=True, slots=True)
class GateEvent:
    series: str
    chapter: str            # the preview chapter
    stage: str              # the stage that just finished for it
    outcome: StageOutcome   # done | skipped | failed
    position: int           # 1-based number of this stage among the selected stages
    total: int              # number of selected stages (after --no-lama filtering)

type Gate = Callable[[GateEvent], bool]        # True = continue, False = stop the run

def run_pipeline(..., mode: RunMode = "auto", preview_chapter: str | None = None, gate: Gate | None = None) -> PipelineResult   # new keyword-only parameters after `report`

# PipelineResult.aborted gains two values: "stopped" (the gate returned False) and "preview failed"

# pipeline/preview.py
@dataclass(frozen=True, slots=True)
class Preview:
    stage: str
    summary: str                   # one line
    details: tuple[str, ...]       # up to 6 short lines (samples), possibly empty
def describe(stage: str, paths: ChapterPaths, cfg: Config) -> Preview: ...
```

## Definitions (no interpretation needed)
- `mode="auto"`: exactly today's behaviour (`gate` and `preview_chapter` are ignored). Existing tests must pass unchanged.
- `mode="step"`: `gate` is required (`ValueError("step mode needs a gate")` otherwise); `preview_chapter` defaults to the first chapter of `active` and must be one of `active` (`ValueError(f"unknown preview chapter {name!r}")`).
- **Phase A — preview chapter through all passes.** For every pass (same `plan_passes`/`build_stage` logic as auto mode) call `run_series(stage_objects, cfg, series, [preview_chapter], gpu=gpu, force=force, after_stage=hook)` where `hook(ctx, outcome)` increments a counter `position` (starting at 1 for the first stage of the first pass and continuing across passes) and returns `gate(GateEvent(series, ctx.paths.chapter, outcome.stage, outcome, position, total))`. Outcomes of a finished pass are reported through `report` and stored in `result.outcomes` exactly as in auto mode. If any stage of the preview chapter **failed**, the hook has still been called for it; afterwards the run stops with `result.aborted = "preview failed"` and `result.failed[preview_chapter]` set as usual.
- A gate that returns False raises `RunAbortedError` out of `run_series`; the runner catches it, stores `error.outcomes` (and reports them) for the preview chapter, sets `result.aborted = "stopped"` and returns; no later stage or chapter runs.
- **Phase B — everything else.** When phase A completed (every gate answered True and no failure), run the normal auto loop over `[c for c in active if c != preview_chapter]` (all passes, no gate). The preview chapter's outcomes from phase A stay in `result.outcomes`. If there are no other chapters, phase B is empty.
- `total` = number of stage names after the `lama` filter and the `stages` selection.
- **`describe(stage, paths, cfg)`** reads the finished stage's artifact(s) from the chapter's work dir with the schema classes (a missing or invalid artifact → `Preview(stage, "no <artifact> found", ())`, never an exception). Exact summaries (`N` = count):
  - `ingest`: `f"{N} file(s), strip {W}x{H} px"` (files not `filtered`; `IngestArtifact`)
  - `slice`: `f"{N} slice(s): {B} blank, {F} forced cut(s), {P} filtered"` (`SlicesArtifact`)
  - `detect`: `f"{N} region(s): " + ", ".join(f"{kind} {count}" ...)` kinds in the order `bubble_text, free_text, sfx, watermark`, only kinds with count > 0; zero regions → `"0 regions"` (`RegionsArtifact` from `regions.json`)
  - `ocr`: `f"{N} region(s) with text, {L} low-confidence (< {cfg.ocr.low_conf})"` (`ocr.json`; use `RegionsArtifact` and the region's OCR confidence field — read `schemas.py` for the exact names); details: the first 5 regions' texts, each cut to 60 characters with `…`
  - `translate`: `f"{N} candidate run(s)"` — count the `translate*.json` candidate files that exist for the chapter (see `CandidateRun` and how `pipeline/stages.py`/the translate stage names them); details: the first 3 lines as `"<source> → <candidate text>"` (60 chars each side)
  - `judge`: `f"{N} final line(s)"` (`final.json`, `FinalArtifact`); details: the first 5 final texts
  - `inpaint`, `inpaint_lama`: `f"{N} item(s) inpainted"` (`InpaintArtifact`; for `inpaint_lama` the same artifact class from its own file — read how the stages name their outputs)
  - `typeset`: `f"{N} layout item(s), {U} unfitted"` (`LayoutArtifact`; "unfitted" = items the layout marks as not fitting — read the schema)
  - `export`: `f"{N} file(s) written to {paths.output_dir}"` (`ExportArtifact`)
  If a field you need does not exist in the schema, use the closest true statement and list the deviation in the report — do not invent fields.
- **CLI `omniscan run SERIES [-c CH]... [-s STAGE]... --step [--preview-chapter NAME]`**: `--step` implies `mode="step"`; the gate prints `Preview` (`[<position>/<total>] <chapter> <stage>: <status>` then the summary and detail lines, indented by 4 spaces), and for a failed stage its error, then asks `typer.prompt("Continue? [y]es / [n]o stop / [a]ll (finish without asking)", default="y")`: `y`/empty → True; `n` → False; `a` → True now and **every later gate call returns True without printing or asking** (the run continues automatically); anything else → ask again (max 3 times, then treat as `n`); an aborted prompt (EOF / `typer.Abort`) → False. Without `--step` nothing changes (no prompts). `--preview-chapter` without `--step` → message on stderr, exit 2. When the run ends with `aborted == "stopped"` print `run: stopped after <stage> of <chapter>` and exit 4; `"preview failed"` → `run: the preview chapter failed — nothing else was run` and exit 1; the existing `"rate limit"` handling stays (exit 3). The final summary line is printed only when the run was not aborted by the gate.

## Acceptance tests (CPU, fake stages, no GPU)
Follow `tests/unit/test_pipeline_runner.py` for faking `build_stage`.
1. **Auto unchanged**: all existing runner/CLI tests pass; `mode="auto"` with a gate supplied never calls it.
2. **Step order**: 3 chapters `A, B, C`, stages spanning the three passes (fake stages recording `(chapter, stage)` in a list): with a gate that always returns True the executed order is **all stages of A across all passes first** (pass 1, 2, 3), then B and C in normal pass order; `GateEvent`s are exactly one per stage of A with `position` 1…total and `total` correct (also with `-s` subset and `lama=False`); `result.outcomes["A"]` has every stage once (not duplicated by phase B, where A's stages are not re-run).
3. **Stop**: the gate returns False at position 4 → `result.aborted == "stopped"`, chapters B and C have no outcomes, A's outcomes contain exactly the 4 stages run so far, `report` was called for them, no later stage ran (fake stage call log).
4. **Failure**: the fake stage at position 3 fails for A → the gate is still called for it (outcome `failed`), then `aborted == "preview failed"`, `failed["A"]` set, nothing for B/C ran.
5. **Validation**: `mode="step"` without a gate → `ValueError`; unknown `preview_chapter` → `ValueError`; `preview_chapter="B"` runs B first, then A and C; `force=True` reaches phase A; up-to-date stages (status `skipped`) still trigger the gate.
6. **Preview text**: for every stage in the list above build the artifact with the schema classes (a few hand-made objects; save them with `Artifact.save` into a tmp chapter work dir laid out like `ChapterPaths`) and assert the **exact** `summary` strings (and the first `details` lines for `ocr`, `translate`, `judge`); missing artifact → `Preview(stage, "no <name> found", ())`; an invalid JSON file → the same, no exception; texts longer than 60 characters are cut to 59 + `…`.
7. **CLI**: `omniscan run S --step` with fake stages (monkeypatch as the existing pipeline CLI tests do) and `input="y\ny\n…"` → prints one preview block per stage and finishes with the normal summary; `input="y\nn\n"` → stops after the second stage, exit 4, message; `input="a\n"` → one prompt only, the rest runs silently, exit 0; `input=""` (EOF) → stops, exit 4; three invalid answers → treated as `n`; a failing preview stage → exit 1 with the message; `--preview-chapter Chapter 2` honoured; `--preview-chapter` without `--step` → exit 2; without `--step` no prompt appears; `tests/unit/test_docs.py` stays green.
8. Whole suite `uv run --frozen pytest -q -m "not gpu"` green.

## Goal
The simplest correct `JpegCodec` backend: decode/encode on the CPU with Pillow (which on this machine is built
against libjpeg-turbo already — no system packages needed), upload to the GPU. This is the **benchmark baseline**
that card C2's `hybrid` backend must beat; it is not meant to be fast, only correct and simple. Also build the
benchmark script that will compare backends later (it only has `turbo` to measure for now).

## Existing contract (read, do not modify) — `src/omniscan/gpu/codec/base.py`
`JpegCodec` protocol: `name: str`, `device: torch.device`, `available() -> bool`, `info(data: bytes) -> JpegInfo`,
`decode(data: bytes) -> torch.Tensor` (`uint8 [3,H,W]` on `device`), `decode_into(datas, out, y_offsets) -> None`,
`encode(image: torch.Tensor, quality=92, subsampling="420") -> bytes`. `JpegInfo(width, height, components,
subsampling, progressive)`.

## Interface (exact)
```python
class TurboCodec:
    name = "turbo"

    def __init__(self, device: str | torch.device = "cuda:0", max_workers: int | None = None) -> None: ...

    # device falls back to "cpu" if CUDA isn't available (torch.cuda.is_available()); max_workers defaults to
    # os.cpu_count(); stores a concurrent.futures.ThreadPoolExecutor(max_workers) as self._pool.

    def available(self) -> bool: ...  # always True (Pillow is a hard dependency of this project)

    def info(self, data: bytes) -> JpegInfo: ...
    def decode(self, data: bytes) -> torch.Tensor: ...
    def decode_into(self, datas: Sequence[bytes], out: torch.Tensor, y_offsets: Sequence[int]) -> None: ...
    def encode(self, image: torch.Tensor, quality: int = 92, subsampling: Subsampling = "420") -> bytes: ...

    def close(self) -> None: ...  # shuts down the thread pool; safe to call more than once
```

## Definitions (implement exactly)
1. **`info`**: `PIL.Image.open(io.BytesIO(data))` (do not call `.load()`). `width, height = img.size`.
   `components = len(img.getbands())`. `subsampling`: use `PIL.JpegImagePlugin` —
   `PIL.JpegImagePlugin.get_sampling(img)` returns 0/1/2 for 4:4:4/4:2:2/4:2:0 in newer Pillow;
   if unavailable, fall back to reading `img.layer` (list of `(id, h, v, q)`) and map luma `(h, v)` of `(1,1)->"444"`,
   `(2,1)->"422"`, `(2,2)->"420"`; if it cannot be determined, `"420"`. `progressive`: `"progressive"` in
   `img.info` and truthy, or `bool(img.info.get("progression"))`. For a single-component (grayscale) image,
   `subsampling = "400"`.
2. **`decode`**: `Image.open(io.BytesIO(data))`, apply `PIL.ImageOps.exif_transpose` only if EXIF orientation is
   present (mirrors card B3's convention but this module must not import from `omniscan.ingest` — duplicate the
   one-liner), `.convert("RGB")` if not already RGB, `np.asarray(img)` (`H, W, 3` uint8), `torch.from_numpy(arr)`,
   `.permute(2, 0, 1).contiguous()`, `.to(self.device, non_blocking=True)`. Non-blocking upload requires pinned
   memory: allocate a pinned `torch.empty` of the right shape and `copy_` the numpy-backed tensor into it first
   when `self.device.type == "cuda"`, otherwise just move directly.
3. **`decode_into`**: decode every item in `datas` **in parallel** via `self._pool.map` (or
   `list(self._pool.map(self._decode_cpu, datas))` where `_decode_cpu` returns the `(H, W, 3)` numpy array without
   any GPU work), producing plain numpy arrays on separate threads (releases the GIL during JPEG decode). Then,
   sequentially, `torch.from_numpy(arr).permute(2,0,1)` and copy each into `out[:, y:y+h, :]` where `y =
   y_offsets[i]`, `h = arr.shape[0]`. Raise `ValueError` with a message naming the index if `arr.shape[1] !=
   out.shape[2]` (width mismatch — decode_into requires equal widths per card B4's contract). Use one pinned
   staging buffer sized to the largest image in the batch, reused across the loop, with `non_blocking=True` copies.
4. **`encode`**: move `image` to CPU (`.cpu()` if not already), `.permute(1, 2, 0).numpy()`, `Image.fromarray(...,
   "RGB")`, `.save(buf, format="JPEG", quality=quality, subsampling={"444": 0, "422": 1, "420": 2}[subsampling],
   optimize=False)` (optimize off — this is the speed baseline), return `buf.getvalue()`.
5. Every public method must work correctly when `self.device.type == "cpu"` too (tests may run without a GPU),
   just without the pinned-memory staging step.

## `scripts/bench_codec.py`
CLI (argparse, no new dependency): `--chapter DIR` (a folder of JPEGs; if omitted, generate `N` synthetic JPEGs
in a temp dir), `--n 200` (synthetic image count when no `--chapter`), `--width 800 --height 1400` (synthetic
size), `--backend turbo` (repeatable; for now only `turbo` is implemented — unknown names print a one-line notice
and are skipped, so this script keeps working once C2 adds more backends later), `--warmup 1 --repeats 3`.
For each backend: build a strip tensor of the right total size on the codec's device, call `decode_into` on the
full file list, time it (`time.perf_counter`, GPU: `torch.cuda.synchronize()` before/after if applicable),
report: wall seconds, megapixels/second, peak `torch.cuda.max_memory_allocated()` delta (0 on CPU), and — on Linux
— process CPU percent during the run via `resource.getrusage(resource.RUSAGE_SELF)` ru_utime/ru_stime delta over
wall time, printed as a percentage. Print one row per backend as a markdown table to stdout **and** write/append
the same table to `docs/benchmarks/codec.md` (create the file with a one-line header if it doesn't exist).

## Acceptance tests (`tests/unit/test_codec_turbo.py`; GPU-dependent parts marked `pytest.mark.gpu`)
Use `tests/fixtures/images.py`'s `plain_jpeg` writer if it already exists (from card B3); if not, add a minimal
local `_write_plain_jpeg(path, size, color)` helper in the test file instead of touching that fixtures module.
1. `info()` on a plain 400x300 baseline JPEG → `width=400, height=300, components=3, subsampling in
   {"444","422","420"}, progressive=False`.
2. `decode()` returns `uint8` tensor shape `[3, 300, 400]`; the mean color per channel is within 3 of the source
   fill color (JPEG lossiness tolerance).
3. `decode_into` with 3 same-width images stacks them at the right `y_offsets` (spot-check a pixel row inside each
   segment matches that image's fill color within tolerance).
4. `decode_into` raises `ValueError` mentioning the offending index when one image's width differs.
5. `encode` → `decode` round trip: mean color within 3, and `info(encoded).subsampling == "420"` when
   `subsampling="420"` was requested.
6. `available()` is True; `TurboCodec("cpu")` works fully without CUDA (run this test unconditionally, not
   `gpu`-marked).
7. `@pytest.mark.gpu`: `TurboCodec("cuda:0")` decodes a 40-image batch (same width) via `decode_into` into a
   preallocated strip and every pixel-row spot check (as in test 3) still passes with data actually on the GPU
   (`out.is_cuda` True, values read back via `.cpu()` for comparison).
8. `close()` can be called twice without raising, and after `close()` a fresh call to `decode()` still works if
   the instance lazily recreates its pool, OR raises a clear `RuntimeError` — pick one behaviour, document it in
   a docstring, and test that exact behaviour (don't leave it undefined).

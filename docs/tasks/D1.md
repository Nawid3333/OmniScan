# D1 — Detect: catch a cross-class duplicate when one box is contained in the other, not just near-identical

**Owner:** GLM builder · **Branch:** `D1` · **Worktree:** `V:\OmniScan-wt\D1` (created by `scripts/omni_builder.py`)
Read `CLAUDE.md` first. Then read `src/omniscan/detect/postprocess.py` in full (`iou`, `ioa`, `_items`,
`_CROSS_CLASS_DUP_IOU`) and `tests/unit/test_detect_postprocess.py`'s existing cross-class tests
(`test_merge_detections_never_suppresses_across_classes`, `test_build_regions_text_without_bubble_and_cross_class_duplicate`).

## Why (found by the director on a real chapter, not a synthetic case)
Rendering a real commercial webtoon chapter (Solo Leveling ch1) produced two overlapping typeset text
boxes on one page — visually, two independently-translated captions stacked on top of each other. Traced
to two detections for the same underlying text, one classified `text_bubble` and one `text_free`:
```
text_bubble: x0=140 y0=11622 x1=605 y1=12018   (465 x 396, area 184140)
text_free:   x0=140 y0=11626 x1=603 y1=11845   (463 x 219, area 101397)
```
`text_free`'s box is **fully contained** inside `text_bubble`'s box (their intersection equals `text_free`'s
whole area). `_items()`'s existing cross-class dedup (`postprocess.py`, the loop building `dropped_free`/
`dropped_bubble`) only compares `iou(free.box, tb.box) >= _CROSS_CLASS_DUP_IOU` (0.6). Here
`iou = 101397 / 184140 ≈ 0.551` — just under the threshold — so neither box is dropped, and `build_regions`
turns both into separate regions that get OCR'd, translated and typeset independently, landing on top of
each other. The existing test only covers the identical-box case (IoU 1.0); nothing exercises "one box is a
subset of the other but much smaller than it, so IoU alone reads low."

## The fix (design decided by the director — implement this shape, not a different one)
In `_items()`, widen the condition that currently reads `iou(free.box, tb.box) < _CROSS_CLASS_DUP_IOU` (the
`continue` guard) so a pair is *also* treated as a duplicate when one box lies mostly inside the other, using
the `ioa()` helper that already exists in this file (used elsewhere for `_TEXT_IN_BUBBLE_MIN_IOA`). Add a new
module constant next to `_CROSS_CLASS_DUP_IOU`:
```python
_CROSS_CLASS_CONTAIN_IOA = 0.85  # a box this much inside the other (either direction) is the same text, even if IoU reads low
```
The pair counts as a duplicate when **any** of these hold: `iou(free.box, tb.box) >= _CROSS_CLASS_DUP_IOU`,
`ioa(free.box, tb.box) >= _CROSS_CLASS_CONTAIN_IOA` (free mostly inside tb), or
`ioa(tb.box, free.box) >= _CROSS_CLASS_CONTAIN_IOA` (tb mostly inside free). Keep the existing tie-break
unchanged (the higher-scored of the pair survives; `free.score > tb.score` drops the bubble one, else drops
the free one) — only the *trigger* condition changes, not what happens once triggered.

## Definitions (no interpretation needed)
- `ioa(inner, outer)` (already defined, do not change it) = `intersection(inner, outer) / area(inner)`: the
  share of `inner`'s own area that lies inside `outer`. Call it both ways (`ioa(free.box, tb.box)` and
  `ioa(tb.box, free.box)`) since either box could be the smaller one.
- The real numbers above must produce a duplicate under the new rule: `ioa(free.box, tb.box) = 101397/101397
  = 1.0 >= 0.85` → triggers. Pin this exact pair (or an equivalent one) as a regression test.
- A pair that is genuinely two separate, non-overlapping captions (the common case) must be unaffected: if
  neither IoU nor either IoA crosses its threshold, nothing changes. Do not lower `_CROSS_CLASS_DUP_IOU` or
  change what it does — only add the new IoA checks alongside it.

   IoA well under 0.85 both ways (a realistic "two separate nearby captions" shape) still produce two

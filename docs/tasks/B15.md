# B15 — Watermark fixed-position mask per series

**Owner:** GLM builder · **Branch:** `B15` · **Worktree:** `~/projects/omniscan-wt/B15`
Read `CLAUDE.md` and `docs/ARCHITECTURE.md` first.

## Goal
Many scanlation groups stamp an identical watermark/logo at the same relative position on every raw page
(e.g. "bottom-right corner, last 8% of width and 5% of height"). This card lets the user record that region
**once per series**, as a fraction of each raw page's own width/height (not the chapter strip, which has a
different width per chapter), and resolves it into strip-space bounding boxes for a specific chapter so a
later stage (C6 inpaint, or C3/C4 to exclude it from OCR) can treat it as a watermark region. This card is a
standalone, fully tested module + CLI — it does not require inpainting or detection to exist yet, same spirit
as B6 (promo filter) being built ahead of the full pipeline wiring.

## Interfaces (exact — do not rename or change signatures)
`src/omniscan/watermark/store.py`:
```python
class WatermarkRegion(BaseModel):
    """A watermark's position as a fraction of EVERY raw page's own width/height (pydantic v2, extra='forbid')."""

    model_config = ConfigDict(extra="forbid")

    index: int  # position in the series' list, assigned by the store (0-based, stable until removal)
    x0_frac: float  # 0.0..1.0, x0_frac < x1_frac
    y0_frac: float  # 0.0..1.0, y0_frac < y1_frac
    x1_frac: float
    y1_frac: float
    note: str | None = None


class WatermarkStore:
    def __init__(self, series_work_dir: Path) -> None: ...

    # File lives at series_work_dir / "watermarks.json": {"regions": [...]}. Missing file == empty list.
    # Never write invalid JSON; atomic save (tmp + os.replace, same pattern as core.schemas.Artifact.save).

    def list(self) -> list[WatermarkRegion]: ...  # ordered by index

    def add(
        self, x0_frac: float, y0_frac: float, x1_frac: float, y1_frac: float, note: str | None = None
    ) -> WatermarkRegion:
        """Validates 0.0 <= x0_frac < x1_frac <= 1.0 and 0.0 <= y0_frac < y1_frac <= 1.0 (raise ValueError
        with a message naming which bound failed, otherwise). Assigns the next unused index (max existing + 1,
        or 0 if empty — indices are never reused after removal). Persists immediately. Returns the new region."""

    def remove(self, index: int) -> None:
        """Raises KeyError(index) if no region has that index. Persists immediately. Does not renumber the
        remaining regions."""
```

`src/omniscan/watermark/resolve.py`:
```python
def resolve_watermark_regions(regions: Sequence[WatermarkRegion], ingest: IngestArtifact) -> list[BBox]:
    """For every (region, source_file) pair in `ingest.files` (outer loop over regions in list order, inner
    loop over ingest.files in their existing order), compute one strip-space BBox:

        x0 = round(region.x0_frac * source_file.width * source_file.scale)
        x1 = round(region.x1_frac * source_file.width * source_file.scale)
        y0 = source_file.y0 + round(region.y0_frac * (source_file.y1 - source_file.y0))
        y1 = source_file.y0 + round(region.y1_frac * (source_file.y1 - source_file.y0))

    (x is scaled by source_file.scale because BBox x-coordinates are in strip space, whose width is the
    chapter's common strip_width; y is interpolated directly across the file's own [y0, y1) strip-space span,
    which already accounts for scale — do not multiply the y fraction by scale again.)

    Skip (do not emit) any pair whose resulting BBox would be degenerate (x1<=x0 or y1<=y0 after rounding) —
    this can happen for a very thin source_file span; log nothing, just omit it. Returns BBoxes in the same
    (region, then file) nested order as the loop, with degenerate ones removed but relative order preserved.
    """
```

## Definitions (no interpretation needed)
- Fractions are validated at `add()` time only; `resolve_watermark_regions` trusts its input and does not
  re-validate (regions loaded from disk via `list()` were already validated when added).
- `round()` uses Python's banker's rounding (built-in `round`); do not implement custom rounding.
- An empty `regions` sequence or an `ingest.files` with zero files both return `[]` — not an error.
- `WatermarkStore` never creates `series_work_dir` itself if it doesn't exist yet — `add()` should
  `series_work_dir.mkdir(parents=True, exist_ok=True)` before writing (the series may not have been ingested
  yet when the user first configures a watermark), but `list()` on a missing directory/file just returns `[]`
  without creating anything.

## CLI (`src/omniscan/cli.py`)
A new Typer sub-app, same pattern as `filter_app`/`glossary_app`:
```python
watermark_app = typer.Typer(no_args_is_help=True, help="Per-series fixed-position watermark regions.")
```
mounted via `app.add_typer(watermark_app, name="watermark")`:
- `omniscan watermark add <series> --x0 0.0 --y0 0.0 --x1 1.0 --y1 1.0 [--note TEXT]`: fractions as
  `typer.Option(..., min=0.0, max=1.0)` (Typer/click range validation), calls `WatermarkStore.add`, prints
  `f"watermark: added region {region.index} to {series}"`. A `ValueError` from `add()` → print
  `f"watermark: {exc}"` to stderr, exit 2.
- `omniscan watermark list <series>`: rich table (index, x0-x1, y0-y1 as fractions to 3 decimals, note).
- `omniscan watermark remove <series> <index>`: calls `remove()`; a `KeyError` → print
  `f"watermark: no region {index} for {series}"` to stderr, exit 2; otherwise
  `f"watermark: removed region {index} from {series}"`.
`SeriesPaths.from_config(get_config(), series).work_dir` is the `series_work_dir` passed to `WatermarkStore`.

## Acceptance tests
`tests/unit/test_watermark_store.py` (use `tmp_path`):
1. `list()` on a fresh directory (no `watermarks.json`) returns `[]`, and does not create the file or directory.
2. `add()` on a fresh store creates the directory + file, assigns `index=0`, persists it (a new `WatermarkStore`
   instance on the same path sees it via `list()`).
3. Adding 3 regions assigns indices `0, 1, 2`; `list()` returns them in that order.
4. `remove(1)` removes only that region; `list()` afterward has indices `0, 2` (not renumbered); adding a new
   region after that assigns index `3` (max existing + 1), not `1`.
5. `remove()` on an unknown index raises `KeyError`.
6. `add(x0_frac=0.5, x1_frac=0.5, ...)` (equal, not `<`) raises `ValueError`; same for `y0_frac >= y1_frac`.
7. `add()` with a fraction outside `[0.0, 1.0]` (e.g. `x0_frac=-0.1` or `x1_frac=1.5`) raises `ValueError`.
8. `note` round-trips through save/reload, including `None`.

`tests/unit/test_watermark_resolve.py`:
9. Single region, single `SourceFile` with `scale=1.0`, `width=1000`, `y0=0`, `y1=1400`: region
   `(0.9, 0.0, 1.0, 0.05)` (top-right corner strip) resolves to exactly
   `BBox(x0=900, y0=0, x1=1000, y1=70)`.
10. `scale=0.5` (the file was downscaled to fit the strip width): same region on a `width=1000` file →
    `x0`/`x1` are halved relative to test 9 (`x0=450, x1=500`), `y0`/`y1` unaffected by scale (computed from
    the file's own strip-space `y0`/`y1` span directly).
11. A `SourceFile` whose strip-space span is offset (`y0=1400, y1=2800`, i.e. the second file in the chapter):
    the same `y0_frac`/`y1_frac` fractions land inside `[1400, 2800)`, not `[0, 1400)`.
12. Two regions × two files → 4 BBoxes, in (region 0/file 0, region 0/file 1, region 1/file 0, region 1/file 1)
    order.
13. A region that resolves to a degenerate BBox for one particular file (construct a file with `y1 - y0 = 1`
    and a fractional span that rounds to zero height) is silently omitted from the result, while other
    (region, file) pairs in the same call still appear.
14. Empty `regions` → `[]`. `ingest.files == []` → `[]`.
15. `resolve_watermark_regions` does not mutate `regions` or `ingest`.

## Out of scope
- Random/detected watermark positions (card C11) — this card is fixed-position only, user-configured.
- Actually inpainting/blanking the watermark region — that's C6, which will consume these BBoxes later.
- Excluding watermark regions from OCR — that's C3/C4's integration to make, not this card's.

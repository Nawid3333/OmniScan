# B23 — Job queue (persistent, resumable, with notifications)

## Goal
Running one series at a time from the shell does not scale once a library has many series/chapters. Add a **persistent
job queue** (SQLite) with priorities, pause/resume/cancel/retry, crash recovery and completion notifications, plus a
`queue` CLI group. A job is "run these pipeline stages over this series (optionally only some chapters)". A single
`omniscan queue run` worker drains the queue. Only the stages that exist today (`ingest`, `slice`) can execute; jobs for
the other stage names are accepted but fail permanently with a clear message, so the queue does not need to change when
those stages land (they only need to be added to the executor's stage table).

### `src/omniscan/queue/store.py`

```python
JobStatus = Literal["queued", "running", "paused", "done", "failed", "cancelled"]
KNOWN_STAGES: tuple[str, ...] = ("ingest", "slice", "detect", "ocr", "translate", "judge", "inpaint", "typeset", "export")

@dataclass(frozen=True, slots=True)
class Job:
    id: int
    series: str
    chapters: tuple[str, ...] | None      # None = every chapter of the series
    stages: tuple[str, ...]               # non-empty, executed in this order
    force: bool
    priority: int                         # higher runs first
    status: JobStatus
    attempts: int                         # number of times the job has been claimed
    max_attempts: int
    error: str | None                     # last error message
    created_at: datetime                  # timezone-aware UTC
    started_at: datetime | None           # set on every claim
    finished_at: datetime | None          # set when status becomes done / failed / cancelled

def queue_db_path(cfg: Config) -> Path:   # cfg.paths.work_root / "queue.db"

class QueueStore:
    def __init__(self, db_path: Path) -> None:      # creates parent dirs + the table (WAL mode), like GlossaryStore
    def add(self, series: str, stages: Sequence[str], *, chapters: Sequence[str] | None = None,
            priority: int = 0, max_attempts: int = 2, force: bool = False) -> Job
    def get(self, job_id: int) -> Job | None
    def list(self, status: JobStatus | None = None) -> list[Job]          # ordered by id ascending
    def claim_next(self) -> Job | None
    def complete(self, job_id: int) -> Job
    def fail(self, job_id: int, error: str, *, retry: bool = True) -> Job
    def pause(self, job_id: int) -> Job
    def resume(self, job_id: int) -> Job
    def cancel(self, job_id: int) -> Job
    def retry(self, job_id: int) -> Job
    def requeue_running(self) -> int
    def clear_finished(self) -> int
    def close(self) -> None
    def __enter__(self) -> QueueStore: ...
    def __exit__(self, *exc: object) -> None: ...
```

## Definitions (no interpretation needed)

**Store**
- `add` validation → `ValueError`: `series` empty/whitespace-only; `stages` empty; any stage not in `KNOWN_STAGES`;
  `chapters` given but empty; `max_attempts < 1`. Stage names are stored exactly as given (no dedupe/reorder).
  `chapters` and `stages` are stored as JSON arrays; `chapters=None` is stored as SQL NULL. New job: `status="queued"`,
  `attempts=0`, `error=None`, `created_at=now(UTC)`, `started_at=None`, `finished_at=None`.
- Timestamps are stored as ISO-8601 UTC text and returned as timezone-aware `datetime`s.
- `claim_next`: in ONE transaction started with `BEGIN IMMEDIATE`, pick the `queued` job with the highest `priority`
  (ties: lowest `id`), set `status="running"`, `attempts += 1`, `started_at=now`, `finished_at=None`, and return it.
  Returns `None` when no job is queued (paused/running/finished jobs are never claimed). Two `QueueStore` objects on
  the same file must never claim the same job.
- `complete(id)`: only from `running` → `done`, `error=None`, `finished_at=now`.
- `fail(id, error, retry=True)`: only from `running`. Stores `error`. If `retry` and `attempts < max_attempts` → status
  goes back to `queued` (`finished_at` stays None, attempts unchanged). Otherwise → `failed`, `finished_at=now`.
- `pause`: `queued` → `paused`. `resume`: `paused` → `queued`. `cancel`: `queued` or `paused` → `cancelled`
  (`finished_at=now`; a `running` job cannot be cancelled). `retry`: `failed` or `cancelled` → `queued` with
  `attempts=0`, `error=None`, `started_at=None`, `finished_at=None`.
- A transition from any other state raises `ValueError(f"job {id} is {status}, cannot {action}")` where `action` is the
  method name (`complete`, `fail`, `pause`, `resume`, `cancel`, `retry`). An unknown id raises `KeyError(job_id)`.
- `requeue_running()`: every `running` job becomes `queued` and `attempts = max(attempts - 1, 0)` (the interrupted
  attempt does not count); returns how many were changed.
- `clear_finished()`: deletes `done` and `cancelled` jobs (NOT `failed`), returns the number deleted.

**Worker** (`run_queue`) — exactly one worker per `queue.db` is supported; document that in the docstring.
1. Call `store.requeue_running()` first (recovers jobs a crashed worker left `running`).
2. Loop until `max_jobs` executed jobs (if given) or `claim_next()` returns `None`:
   - `job = store.claim_next()`; call `executor(job)`.
   - No exception → `store.complete`, event `"job_done"`.
   - `PermanentJobError` → `store.fail(retry=False)`, event `"job_failed"`.
   - Any other `Exception` → `store.fail(job.id, f"{type(exc).__name__}: {exc}")`; event `"job_retry"` if the returned
     job is `queued` again, else `"job_failed"`.
   - `KeyboardInterrupt` (or any `BaseException` that is not an `Exception`): `store.requeue_running()` then re-raise
     (the interrupted job goes back to `queued` with its attempt refunded).
   - Every executed job is appended to `finished` in the state returned by `complete`/`fail`.
3. After the loop, if it ended because `claim_next()` returned `None` AND at least one job was executed → event
   `"queue_empty"` with `job=None`. (Not fired when `max_jobs` stopped the loop, nor when nothing ran.)
4. Every notifier call is wrapped in `try/except Exception` → `logging.getLogger("omniscan.queue").warning(...)`; a
   broken notifier never fails a job or the run.
5. `QueueSummary.done` = jobs that finished `done`; `failed` = jobs that ended `failed`; `retried` = executions that
   put the job back to `queued`.

**Notifiers**
- `log_notifier`: `logging.getLogger("omniscan.queue").info(...)` with a one-line message containing the event and, if
  present, `job.id`, `job.series`, `job.status` and `job.error`.
- `webhook_notifier(url, timeout, client)`: returns a notifier that POSTs JSON
  `{"event": event, "job": null | {"id", "series", "chapters", "stages", "status", "attempts", "max_attempts", "error"}}`
  to `url` (`chapters`/`stages` as lists; `chapters` may be null). Uses `client` if given, else a short-lived
  `httpx.Client(timeout=timeout)`. Any `httpx.HTTPError`, and any non-2xx response, is logged at WARNING and swallowed
  — it must never raise.
- `combine(*notifiers)`: returns a notifier that calls each one in order; an exception in one is logged (WARNING) and
  does not stop the rest.

**Executor** (`stage_executor(cfg)`)
- Stage table (module-level dict, name → list of stage instances to run, mirroring the CLI):
  `"ingest"` → `[IngestStage()]`, `"slice"` → `[IngestStage(), SliceStage()]` (import both lazily inside the
  function, as `cli.py` does, to keep `--help` fast).
- Before running anything: any stage in `job.stages` that is not in the table →
  `raise PermanentJobError(f"stage {name!r} is not implemented yet")` (the first such stage in job order).
  If `job.chapters is None` and `SeriesPaths.from_config(cfg, job.series).chapters()` is empty →
  `raise PermanentJobError(f"no chapters found for series {job.series!r}")`.
- Then for each stage name in `job.stages`, in order, call
  `run_series(stages_for_that_name, cfg, job.series, list(job.chapters) if job.chapters is not None else None, force=job.force)`
  (import `run_series` at module top level as `from omniscan.core.stage import run_series` so tests can monkeypatch
  `omniscan.queue.executor.run_series`). Because the manifest makes a repeated ingest a `skipped`, `("ingest","slice")`
  is fine.
- If any returned `StageOutcome` has `status == "failed"` → after finishing that `run_series` call raise
  `RuntimeError("; ".join(f"{chapter}/{outcome.stage}: {outcome.error}" for each failed outcome))` (do not run later
  stage names).

**CLI** (a `queue_app = typer.Typer(...)` registered with `app.add_typer(queue_app, name="queue")`, same style as
`glossary_app`; every command resolves the config with `get_config()` from `omniscan.cli`'s own namespace so tests can
monkeypatch `omniscan.cli.get_config`; DB = `queue_db_path(cfg)`):
- `queue add SERIES [--stage/-s STAGE]... [--chapter/-c CHAPTER]... [--priority/-p INT=0] [--max-attempts INT=2] [--force]`
  — `--stage` repeatable, default `["slice"]`. Typer cannot register `list[Literal[...]]`, so take `list[str]` and
  validate against `KNOWN_STAGES` yourself: unknown stage → message on stderr + exit 2. Prints
  `queued job {id}: {series} stages={a,b} chapters={c1,c2|all} priority={p}`.
- `queue list [--status STATUS]` — `STATUS` a plain `str` validated against the six statuses (bad value → exit 2).
  One line per job: `{id:>4}  {status:<9} pri={priority} try={attempts}/{max_attempts}  {series}  {stages,joined}  {chapters|all}` plus
  `  !! {error first 80 chars}` when there is an error. Empty → prints `queue is empty`.
- `queue run [--webhook URL] [--max-jobs N]` — `--webhook` has `envvar="OMNISCAN_NOTIFY_WEBHOOK"`. Notifier =
  `combine(log_notifier, webhook_notifier(url))` when a URL is set, else `log_notifier`. Calls
  `run_queue(store, stage_executor(cfg), notifier, max_jobs=N)`. Prints one line per element of `finished`:
  `job {id} {status}` (append `: {error}` when set), then a summary line `done={n} failed={n} retried={n}`.
  Exit 1 if `failed > 0`, else 0. Nothing queued → `queue is empty`, exit 0.
- `queue pause|resume|cancel|retry JOB_ID` — prints `job {id}: {new status}`. `ValueError` → message on stderr,
  exit 2. `KeyError` → `no such job {id}` on stderr, exit 2.
- `queue clear` — prints `removed {n} finished job(s)`.

## Acceptance tests (must exist and pass; CPU only, never mark `gpu`)

**Store (`test_queue_store.py`)**
1. `add`/`get` round-trip: defaults, `chapters=None` vs a list, tz-aware `created_at`, JSON round-trip of stages with
   unicode series names.
2. `add` validation errors (empty series, empty stages, unknown stage, empty chapters list, `max_attempts=0`).
3. Claim order: priorities 0, 5, 5, -1 added in that order → claimed 2nd-added, 3rd-added, 1st-added, 4th-added.
   Claim sets `running`, `attempts=1`, `started_at`.
4. `claim_next` on an empty queue → `None`; paused / done / failed / running jobs are never claimed.
5. `fail` semantics: `max_attempts=2` → first `fail` requeues (error stored, attempts 1), second claim then `fail` →
   `failed` with `finished_at`; `fail(retry=False)` → `failed` immediately; `complete` clears the error.
6. Every legal transition (`pause`, `resume`, `cancel`, `retry`) and a representative illegal one for each
   (e.g. `pause` on a done job, `cancel` on a running job, `complete` on a queued job) → `ValueError` with the exact
   message format above; unknown id → `KeyError`.
7. `requeue_running` (attempts refunded, returns count) and `clear_finished` (removes done + cancelled only).
8. Persistence: close and reopen the file → jobs and their states survive.
9. Two `QueueStore` instances on the same file, alternating `claim_next` over 10 queued jobs → every job claimed
   exactly once.

**Worker (`test_queue_worker.py`)** — use a real `QueueStore` on `tmp_path` and fake executors/notifiers:
1. Two jobs, executor succeeds → executed in queue order; `QueueSummary(done=2, failed=0, retried=0, ...)`; notifier
   events exactly `["job_done", "job_done", "queue_empty"]`.
2. Executor raises `RuntimeError("boom")` on the first call then succeeds → events `["job_retry", "job_done",
   "queue_empty"]`, final job `done` with `attempts == 2`, summary `done=1, retried=1`.
3. Executor always raises → `max_attempts=2` gives events `["job_retry", "job_failed", "queue_empty"]`, final job
   `failed`, `error == "RuntimeError: boom"`.
4. `PermanentJobError` → no retry: `failed` after 1 attempt, event `"job_failed"`.
5. `max_jobs=1` with 3 queued jobs → 1 executed, 2 still queued, no `queue_empty` event.
6. Crash recovery: claim a job with `store.claim_next()` and never finish it (simulating a crashed worker), then call
   `run_queue` → it is executed and ends `done` with `attempts == 1`.
7. `KeyboardInterrupt` raised by the executor propagates out of `run_queue`; afterwards the job is `queued` with
   `attempts == 0`.
8. A notifier that always raises does not stop the run or change job outcomes.
9. Empty queue → `QueueSummary(0, 0, 0, ())` and no events.

**Notify (`test_queue_notify.py`)** — use `httpx.MockTransport` through `client=`:
1. The webhook receives one POST with the documented JSON for a job event and for `("queue_empty", None)`
   (`"job": null`).
2. A 500 response → no exception; a transport that raises `httpx.ConnectError` → no exception.
3. `combine` calls all notifiers in order even when the first raises; `log_notifier` emits an INFO record (`caplog`).

**Executor (`test_queue_executor.py`)** — monkeypatch `omniscan.queue.executor.run_series` with a recorder that returns
`StageOutcome`s (from `omniscan.core.stage`):

   instances (`[s.name for s in stages] == ["ingest", "slice"]`), `chapters == ["Chapter 1"]`, `force=True`.
2. `stages=("ingest","slice")` → two `run_series` calls, in that order.
3. `stages=("slice","detect")` → `PermanentJobError` mentioning `'detect'` and `run_series` was NOT called at all.
4. A returned `failed` outcome → `RuntimeError` whose message contains `Chapter 1/slice` and the outcome's error, and
   later stage names are not run.
5. `chapters=None` on a series with no chapter folders (tmp config) → `PermanentJobError` "no chapters found".

**CLI (`test_queue_cli.py`)** — `typer.testing.CliRunner`, and
`monkeypatch.setattr(omniscan.cli, "get_config", lambda: cfg)` with a CPU config exactly like

1. `add` then `list` shows the job; `list --status done` shows `queue is empty`; bad `--status` → exit 2; unknown
   `--stage` → exit 2.
2. Real end to end: write 2 tiny JPEG pages under a series' `Chapter 1`, `queue add S -s slice`, `queue run` → exit 0,
   output contains `job 1 done` and `done=1 failed=0 retried=0`, and `slices.json` exists in the work dir; a second
   `queue add S -s slice` + `queue run` → still exit 0 (skipped stages).
3. `queue add S -s detect` + `queue run` → exit 1, `job N failed: stage 'detect' is not implemented yet`, and `list`

## Out of scope
- Running more than one job at a time; more than one worker; cron-style scheduling; a desktop toast (arrives with the
  M13 app); a web UI for the queue.
- Executing stages that do not exist yet (they fail permanently until added to the executor table).
- Any change to how `ingest`/`slice` themselves work.

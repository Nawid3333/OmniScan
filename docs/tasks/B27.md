## The generator (`tests/fixtures/strip_layouts.py`)
```python
@dataclass(frozen=True)
class Segment:
    kind: Literal["art", "solid", "gradient"]
    y0: int
    y1: int


def random_strip(seed: int, width: int = 48, max_rows: int = 6000) -> tuple[torch.Tensor, list[Segment]]:
    """Deterministic for a given seed. Returns (uint8 [3, H, width] strip, segments in top-to-bottom order)."""
```
Rules (implement exactly; use `random.Random(seed)` for layout decisions and `torch.Generator().manual_seed(seed)`
for pixel noise):
- Segments strictly **alternate** between "art" and a non-art kind (`"solid"` or `"gradient"`, chosen 65% / 35%);
  the first segment is art or non-art with equal probability. Keep adding segments until the next one would push the
  total past `max_rows`, then stop (the final segment is truncated to fit exactly `max_rows` only if it is still
  at least 10 rows tall, otherwise it is dropped). H = sum of segment heights, at least 200.
- Heights: art in `[20, 900]`; solid in `[10, 400]` (so some are shorter than `band_min_px` and must NOT become
  bands); gradient in `[60, 400]`.
- **art** rows: every pixel of every channel is `torch.randint(0, 256, ...)` (full-range noise, so no art row can be
  uniform).
- **solid**: one random RGB colour `c`; each pixel = `c` plus per-pixel integer noise drawn from
  `{-amp..+amp}` with `amp` chosen from `{0, 2}` per segment, clamped to `[0, 255]`.
- **gradient**: height `h`; start colour `c0` random; end colour `c1 = clamp(c0 + delta)` where each channel of
  `delta` is a random integer in `[-h//2, +h//2]`; row `i` (0-based) is a single solid colour
  `round(c0 + (c1 - c0) * i / (h - 1))` per channel (no per-pixel noise). Consecutive rows therefore differ by at most
  1 per channel, well under `max_drift`.
Also export a second helper `art_strip(rows: int, width: int, seed: int) -> torch.Tensor` (pure full-range noise).

## Properties to test (`tests/unit/test_slicer_properties.py`)
Write one helper `run_case(seed)` (decorate with `functools.lru_cache`) that builds `random_strip(seed)`, runs
`row_stats`, `find_uniform_bands`, `plan_cuts` and `slice_strip` with `SMALL` and returns everything the properties
need. Then parametrise **150 seeds** (`range(150)`) per property below (one test function per property, so a failure
names the property and the seed).

**P1 — band recall/precision.** The set of `(band.y0, band.y1)` returned by `find_uniform_bands` equals exactly the
set of `(seg.y0, seg.y1)` of every `"solid"`/`"gradient"` segment whose height is `>= 50`. (So a solid gutter shorter
than 50 rows never becomes a band, and every long gutter is found exactly, edges included.)
**P2 — band metadata.** For a band that equals a `"solid"` segment: `is_gradient` is `False`. Every band has
`y1 - y0 >= 50`. Bands are sorted by `y0` and do not overlap.
**P3 — cuts well-formed.** Cut `y` values are strictly increasing and all in `(0, H)`.
**P4 — non-forced cuts are inside a band.** For every non-forced cut `c`: some band satisfies
`band.y0 <= c.y < band.y1`. Consequently the row at `c.y` is uniform (assert this explicitly using `row_stats`'s
`uniform` tensor as well). A non-forced cut therefore never lies inside an art segment.
**P5 — slices tile the strip.** `slices[0].y0 == 0`, `slices[-1].y1 == H`, `slices[i].y1 == slices[i+1].y0`, every
slice has `y0 < y1`, `Slice.index == position`, and `SlicesArtifact.strip_height == H`,
`strip_width == width`.
**P6 — flags.** `Slice.blank` is `True` exactly when every row of the slice is uniform (recompute from
`row_stats(...).uniform`). `Slice.forced_cut` of slice `i` equals `cuts[i].forced` for `i < len(cuts)`, and the last
slice's `forced_cut` is `False`.
**P7 — size ceiling.** No slice is taller than `SMALL.hard_max_height`.
**P8 — DP optimality consequence.** Recompute the candidate centres exactly as `plan_cuts` does:
`centres = {(b.y0 + b.y1)//2 for b in bands if b.y1 - b.y0 < min_height + band_min_px}` restricted to `0 < p < H`,
minus the "edge" positions (`{b.y0 + band_min_px//2, b.y1 - band_min_px//2 for b in bands if
b.y1 - b.y0 >= min_height + band_min_px}`, restricted to `0 < p < H`). For every slice taller than
`SMALL.max_height`: there is **no** centre `p` with `slice.y0 < p < slice.y1`, `p - slice.y0 <= max_height` and
`slice.y1 - p <= max_height` (splitting there would strictly lower the DP cost, so an optimal plan cannot leave it).
**P9 — forced cuts only when needed.** If any cut is forced, then there exist two adjacent positions in
`sorted({0, H} | centres | edges)` whose gap exceeds `SMALL.hard_max_height`. (With `SMALL` and `max_rows=6000` this
will rarely trigger; that is fine — the property must still hold vacuously. The deterministic tests below cover the
forced-cut path.)
**P10 — determinism.** Calling `slice_strip` twice on the same strip yields equal `SlicesArtifact`s
(`model_dump()` equality).

Two more (not parametrised by the random generator):
**P11 — chunk independence.** For 40 seeds, take `random_strip(seed, max_rows=1200)` and assert that
`row_stats(strip, 10, chunk_rows=k)` returns identical `median`, `uniform` and `detail` tensors for
`k in (1, 7, 97, 8192)`. (Catches chunk-boundary bugs; the real slicer chunks at 8192 rows.)
**P12 — tall strips (deterministic, `DEFAULT` config).**
 (a) `art_strip(16000, width=8, seed=1)` (no uniform rows at all): expect exactly `ceil(16000/6000) - 1 == 2`
 cuts, both `forced`, every slice `<= DEFAULT.hard_max_height`, tiling holds, no slice `blank`.
 (b) An 18000-row strip built as: 4000 rows art, a 200-row solid gutter, 7000 rows art, a 60-row solid gutter,
 6740 rows art (width 8): tiling holds; both gutter centres are cut candidates (each gutter is shorter than
 `min_height + band_min_px`); every non-forced cut lies inside one of the two gutters; every slice
 `<= DEFAULT.hard_max_height`. (This crosses the 8192-row chunk boundary.)

   bug in **your test's own assumptions** is not a finding — fix your test instead, and say in the report which
   property you had to correct and why.

## Protocol (follow it exactly — a harness does the mechanical part; do NOT edit production files by hand)
1. Read each module and its tests (`Read` only; do not run anything yet). Create the directory `tests/mutants/hw_hf/` (the mutant lists are kept in the repo: see `tests/mutants/README.md`).
2. **One mutants file per module group** (e.g. `tests/mutants/hw_hf/<group>.py`), written in a single `Write` call. It defines `MUTANTS = [(file, old, new, label), ...]` where `old` is a snippet that occurs **exactly once** in `file`
   (include neighbouring text if needed), `new` is the mutated snippet and `label` a few words (`"flip < to <="`). Write **25–35 mutants per group**, spread over these kinds: flip a comparison (`<` `<=` `>` `>=` `==` `!=`),
   off-by-one on a constant or index, `and` <-> `or`, remove a guard or an `if` branch, drop a `not`, swap `min`/`max`, change a constant (0/1, a threshold, a default), change a loop bound or slice end, swap two arguments,
   return the wrong variable, break tie-breaking/sorting, drop a `+ 1`/`- 1`, change rounding (`floor`/`ceil`/`round`). Prefer mutants that change behaviour a user would see; do not include mutants you already know are equivalent.
3. Validate, then run: `uv run python scripts/mutate.py check tests/mutants/hw_hf/<group>.py` (every `old` found exactly once, mutant compiles; fix invalid entries) and
   `uv run python scripts/mutate.py run tests/mutants/hw_hf/<group>.py -t <test file> -t <test file> ...` (the test files of that group, listed below). It applies each mutant, runs the tests, restores the file and prints one `KILLED` / `SURVIVED` line per mutant.
   A run of 30 mutants takes a minute or two: one tool call. The harness restores every file itself; afterwards `git diff --stat -- src` must show nothing.
4. For every `SURVIVED` mutant decide: *equivalent* (no output can change — list it in the report) or a real gap. For each real gap write a test (append to the module's existing test file, or in the gaps file named under "Files you may create")
   that **fails with the mutation and passes on the original**; small hand-made inputs, exact expected values, no random data. Then prove it with `uv run python scripts/mutate.py run tests/mutants/hw_hf/<group>.py -t <the test files> --only <indices of the former survivors>`:
   they must now print `KILLED`. Add a second round of ~10 fresh mutants around the code you just looked at if time allows.
5. **Commit early:** after each module group, append its rows to `docs/reports/Q5.md` and commit (`Q5: WIP <group>`); you have a hard limit of 150 tool calls in total, and a run that ends without a commit is thrown away. At about 110 calls stop mutating and write the final report.
6. At the end: `git diff --stat -- src` **empty** (no production change), the mutants files committed under `tests/mutants/hw_hf/` (add a row for them to `tests/mutants/README.md`), `uv run pytest -q` all green (the full run includes GPU tests), `uv run ruff format . && uv run ruff check .` clean, `uv run pyright` clean.
   If you believe production code has a real bug (a test you wrote against the intended behaviour fails on the original), do NOT fix it: write the finding under Questions with a minimal reproduction and mark the test `@pytest.mark.xfail(strict=True, reason="<what is wrong>")`.

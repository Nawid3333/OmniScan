## Goal
Pure library functions that take a chapter strip already in VRAM and decide where to cut it into slices:
cuts happen **only inside horizontal bands of uniform colour ≥ `band_min_px` tall** (never through art or speech
bubbles), slices end up near a target height, fully uniform slices are flagged `blank`, and when no band exists for
too long a "forced" cut is placed at the least-detailed row and flagged. No file IO, no Stage class (that comes later).

## Interfaces (exact)
```python
# bands.py
@dataclass(frozen=True, slots=True)
class RowStats:
    median: torch.Tensor    # uint8 [3, H] per-row per-channel median (lower median, like torch.median)
    uniform: torch.Tensor   # bool [H]
    detail: torch.Tensor    # uint8 [H] = max over channels and pixels of |pixel - row median|

def row_stats(strip: torch.Tensor, tol: int, chunk_rows: int = 8192) -> RowStats: ...
def find_uniform_bands(stats: RowStats, min_band: int, tol: int, max_drift: float) -> list[Band]: ...

# cuts.py
@dataclass(frozen=True, slots=True)
class Cut:
    y: int
    forced: bool

def plan_cuts(height: int, bands: list[Band], detail: torch.Tensor, cfg: SlicerConfig) -> list[Cut]: ...

# slice.py
def slice_strip(strip: torch.Tensor, cfg: SlicerConfig, source_files: list[SourceFile] | None = None) -> SlicesArtifact: ...
```

## Definitions (implement exactly)
**Input:** `strip` is a uint8 tensor `[3, H, W]` on any device (tests use CUDA when available, else CPU). All heavy
work runs on `strip.device`; only small per-band/per-cut data may go to the CPU. No Python loops over rows.

1. **row_stats** — process rows in chunks of `chunk_rows` (a loop over chunks is allowed, not over rows):
   `med = torch.median(chunk, dim=2).values` (uint8 `[3, h]`).
   `lo = clamp(med - tol, 0, 255)`, `hi = clamp(med + tol, 0, 255)` computed in int16 then cast to uint8
   (uint8 subtraction wraps — never subtract in uint8). A row is **uniform** iff every pixel of every channel satisfies
   `lo <= p <= hi`. `detail` = max over channels and columns of `|p - med|` (compute in int16, store uint8).
2. **find_uniform_bands** — link rows y and y+1 iff `uniform[y] and uniform[y+1] and
   mean_over_channels(|med[:, y+1] - med[:, y]|) <= max_drift` (compute in float32). A band is a maximal run of
   uniform rows where every consecutive pair is linked; keep runs with length `>= min_band`.
   `color` = per-channel lower median of the band's row medians (`torch.median` over the band rows).
   `is_gradient` = any channel with `|med[:, y1-1] - med[:, y0]| > tol`. Return bands sorted by `y0`.
   A Python loop **over bands** (not rows) is fine for colours.
3. **plan_cuts**:
   a. Candidate positions: for every band, its centre `(y0 + y1) // 2`. Additionally, a band at least
      `min_height + min_band` tall gets two **mandatory edge cuts** `y0 + min_band // 2` and `y1 - min_band // 2`
      (`Cut(forced=False)`), so a long uniform stretch always becomes its own blank slice; such a band does not add
      its centre. Drop positions `<= 0` or `>= height`; dedupe; sort.
   b. Mandatory forced cuts: walk the sorted positions `[0, *candidates, *edge_cuts, height]`; for every gap `g = b - a` with
      `g > hard_max_height`, insert `k = ceil(g / max_height) - 1` forced cuts. Forced cut `i` (1..k) targets
      `t = a + round(i * g / (k + 1))`; choose the row with minimum `detail` in `[t - 256, t + 256]` clipped to
      `(a, b)` (ties → the row closest to `t`, then the smaller y). These are `Cut(y, forced=True)` and are always kept.
   c. Between consecutive mandatory points (0, edge cuts, forced cuts, height) run a dynamic programme choosing a
      subset of the centre candidates: `cost(len) = ((len - target) / target) ** 2 + (4.0 if len < min_height else 0.0)
      + (100.0 if len > max_height else 0.0)`; a segment longer than `hard_max_height` is not allowed.
      Minimise total cost; ties → fewer cuts, then lexicographically smaller cut list. Complexity O(n²) in the
      number of candidates per sub-range is fine.
   d. Return all cuts (chosen centre cuts + edge cuts, `forced=False`, plus forced cuts) sorted by `y`,
      excluding 0 and `height`.
4. **slice_strip** — `stats = row_stats(...)`, `bands = find_uniform_bands(...)`, `cuts = plan_cuts(...)`.
   Slices are the ranges between `[0, *cut_ys, H]`. `Slice.forced_cut` is True when the cut at the slice's `y1`
   is forced. `Slice.blank` = all rows in `[y0, y1)` uniform. `source_files` = indices of `SourceFile`s whose
   `[y0, y1)` overlaps the slice (empty list if `source_files` is None). `params` = all `SlicerConfig` values.
   `strip_width = W`, `strip_height = H`.

## Synthetic fixtures (`tests/fixtures/strips.py`)
Deterministic generators (use `torch.Generator().manual_seed(...)`), each returning uint8 `[3, H, W]` on CPU:
- `art(h, w, seed)`: random uint8 noise (every row non-uniform).
- `solid(h, w, rgb)`, `noisy_solid(h, w, rgb, amp, seed)`: solid colour plus uniform integer noise in `[-amp, amp]`,
  clamped to 0..255.
- `gradient(h, w, rgb_top, rgb_bottom)`: each row a solid colour linearly interpolated (rounded).
- `bubble(h, w, seed)`: white background, black ellipse outline (2 px) spanning ~80 % of the width, a few black
  "text" bars inside — the white rows *above and below* the ellipse inside the block are fewer than 10.
- `stack(*blocks)`: `torch.cat` along H.

## Acceptance tests (must exist and pass; GPU tests use `pytest.mark.gpu`)
Bands (`test_slicer_bands.py`, W = 720):
1. art(300) + solid white 49 + art(300) → no band. Same with 50 → exactly one band `[300, 350)`, colour (255,255,255).
2. art + white 200 + art → one band of length 200, `is_gradient` False.
3. art + noisy_solid(white, amp=6, 150) + art → one band of length 150.
4. art + gradient(black→white, 300 rows) + art → one band of length 300, `is_gradient` True
   (step ≈ 0.85/row < max_drift).
5. art + solid(200,200,200, 100) + solid(40,40,40, 100) + art → two bands (hard jump splits), each length 100.
6. `row_stats` with `chunk_rows=7` gives identical results to `chunk_rows=8192` on a 500-row strip.
Cuts (`test_slicer_cuts.py`):
7. H = 30000, a 100-px white band every 1000 px of art → every slice height within [1500, 6000]; mean within ±20 % of 3000;
   every non-forced cut lies strictly inside a band.
8. H = 40000 of pure art (no bands) → forced cuts exist, all flagged `forced`, no slice taller than `hard_max_height`.
9. art(2000) + black(4000) + art(2000) → cuts at 2025 and 5975 (edge cuts), the middle slice is fully black.
10. Determinism: same input twice → identical cuts.
Slices (`test_slicer_slice.py`):
11. `bubble` blocks separated by 60-px white gaps, total ~12000 px: no cut `y` falls inside any bubble block's row range.
12. `blank` is True exactly for slices fully inside uniform rows; `forced_cut` matches the cut list.
13. `source_files` overlap mapping correct for 3 synthetic SourceFiles covering the strip.
14. `@pytest.mark.gpu` performance: H = 150_000, W = 720 strip (art with a white 80-px band every 2500 px) on CUDA:
    `slice_strip` completes in < 3.0 s after one warm-up call, and `torch.cuda.max_memory_allocated()` growth < 2.5 GiB.

## Protocol (follow it exactly)
1. Read each module and its tests. Create the untracked scratch directory `tmp_mut/` in the worktree (delete it at the end).
2. For **each mutant**: (a) copy the module to `tmp_mut/<name>.orig`; (b) make ONE small change with the Edit tool; (c) run only the module's test files: `uv run pytest tests/unit/test_filter_decide.py tests/unit/test_filter_hashing.py tests/unit/test_glossary_match.py tests/unit/test_glossary_store.py tests/unit/test_glossary_yaml_io.py tests/unit/test_importer_plan.py tests/unit/test_importer_execute.py -x -q -p no:warnings`;
   (d) record `KILLED` (a test failed) or `SURVIVED` (all passed); (e) restore the module with `cp tmp_mut/<name>.orig <original path>` and check `git diff --stat -- src` shows nothing.
   Never leave a mutation in place while doing anything else.
3. Aim for **at least 30 mutants per module file group** (about 70 in total), spread over these kinds: flip a comparison (`<` `<=` `>` `>=` `==` `!=`), off-by-one on a constant or index, `and` <-> `or`, remove a guard or an `if` branch,
   drop a `not`, swap `min`/`max`, change a constant (0/1, a threshold, a default), change a loop bound or slice end, swap two arguments, return the wrong variable, break tie-breaking/sorting, drop a `+ 1`/`- 1`, change rounding (`floor`/`ceil`/`round`).
   Prefer mutants that change behaviour a user would see. A mutant that cannot change any output (dead code, same result) is *equivalent*: do not count it, list it in the report.
4. For every **surviving non-equivalent** mutant write a test that **fails with the mutation applied and passes on the original**. Put it in the module's existing test file (append) or in `tests/unit/test_filter_glossary_importer_mutation_gaps.py`.
   Prove it: re-apply the mutant once, run the new test (it must fail), restore. Use small hand-made inputs with exact expected values, not random data.
5. At the end: `git diff --stat -- src` must be **empty** (no production change), `tmp_mut/` deleted, `uv run pytest -q` all green (the full run includes GPU tests), `uv run ruff format . && uv run ruff check .` clean, `uv run pyright` clean.
   If you believe production code has a real bug (a test you wrote against the intended behaviour fails on the original), do NOT fix it: write the finding under Questions with a minimal reproduction and mark the test `@pytest.mark.xfail(strict=True, reason="<what is wrong>")`.

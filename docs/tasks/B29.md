## Goal
Given a chapter's `ocr.json`, run a **translation profile** (a model + prompt style) over its regions and write one
**candidate run** `work/<Series>/<Chapter>/translations/<profile>.json` (a `CandidateRun`). Two prompt styles:
`chat_json` (many regions per request, glossary in the prompt, JSON answer) and `translategemma` (one request per
region, locked glossary terms pre-substituted). Runs are resumable per chunk, tolerate the malformed answers cloud
models produce, record token usage, and never swallow Ollama rate-limit errors. The judge, story memory and
post-check/repair are **not** in this card (C5 does those later); this card only produces candidates. The OCR stage
does not exist yet: everything is tested with hand-built `RegionsArtifact`s and a fake chat client.

## Part 1 — `OllamaClient.chat(..., think: bool | None = None)`
Add a keyword-only parameter `think: bool | None = None` after `keep_alive`. When it is not `None`, the request body
gets the top-level key `"think": think` (NOT inside `options`). When `None`, the key is absent (translategemma
rejects `think: true` and some models misbehave if it is sent). Tests: body has `"think": false` / `true` when given,
no `think` key when omitted.

## Part 2 — Profiles (`profiles.py`, `config/translation_profiles.toml`)
```python
class TranslationProfile(BaseModel):  # extra="forbid"
    name: str  # file stem of the run; must match ^[A-Za-z0-9][A-Za-z0-9._-]*$
    enabled: bool = True  # default set of `omniscan translate` without --profile
    endpoint: Literal["local", "cloud"]
    model: str
    style: Literal["chat_json", "translategemma"]
    temperature: float = 0.3  # 0.0 <= t <= 2.0
    think: bool | None = None  # None = do not send the parameter
    chunk_regions: int = 30  # chat_json only: max regions per request, >= 1


def load_profiles(paths: Sequence[Path]) -> dict[str, TranslationProfile]: ...
def default_profile_paths() -> list[Path]: ...
```
- TOML layout: one table per profile, `[profiles.<name>]`, the key IS the profile name (the model's `name` field is set
  from it; a `name = ...` key inside the table is an error). `load_profiles` reads the existing files in order; a later
  file replaces an earlier profile of the same name entirely (no field-level merge) and may add new ones. Missing
  files are skipped; an unreadable/invalid TOML or an invalid profile raises `ValueError` naming the file and profile.
- `default_profile_paths()` = `[DEFAULT_TOML.parent / "translation_profiles.toml", USER_TOML.parent / "translation_profiles.toml"]`
  (`DEFAULT_TOML` / `USER_TOML` are the existing constants in `omniscan.core.config`; import them, do not edit that file).
- `endpoint = "local"` means the Windows Ollama daemon at `[ollama].local_url` — it also proxies the `*-cloud` models
  (verified in the probe), so **all shipped profiles use `endpoint = "local"`**. `"cloud"` means ollama.com directly with
  `OLLAMA_API_KEY` (names without the `-cloud` suffix); it is supported but not exercised yet.
- Shipped `config/translation_profiles.toml` (exactly these five):
  `translategemma-12b-local` (local, `translategemma:12b`, style `translategemma`, no `think`),
  `gemma4-12b-local` (local, `gemma4:12b`, `chat_json`, `think = false`),
  `gemma4-31b-cloud` (local endpoint, model `gemma4:31b-cloud`, `chat_json`, `think = false`),
  `glm-5-3-flash-cloud` (`enabled = false`, local endpoint, model `glm-5.3-flash:cloud`, `chat_json`, `think = false`),
  `kimi-k3-cloud` (`enabled = false`, local endpoint, model `kimi-k3:cloud`, `chat_json`, `think = false`).

## Part 3 — Prompts (`prompts.py`)
```python
CHAT_JSON_SYSTEM: str            # the exact string below
TRANSLATIONS_SCHEMA: dict[str, Any]
TRANSLATEGEMMA_TEMPLATE: str

def source_text(region: Region) -> str
def translatable(regions: Sequence[Region]) -> list[Region]
def glossary_subset(regions: Sequence[Region], entries: Sequence[GlossaryEntry]) -> list[GlossaryEntry]
def chat_json_messages(regions: Sequence[Region], entries: Sequence[GlossaryEntry]) -> list[dict[str, str]]
def substitute_binding(text: str, entries: Sequence[GlossaryEntry]) -> str
def translategemma_prompt(text: str) -> str
```
Definitions (exact):
- `source_text(region)`: `" ".join(region.text.split())` (collapses every run of whitespace, including newlines, to one
  space and strips).
- `translatable(regions)`: the regions with `kind != "watermark"` and a non-empty `source_text`, sorted by
  `(slice_index, reading_order, natural_key(id))` (`natural_key` from `omniscan.core.paths`). Does not mutate the input.
- `glossary_subset(regions, entries)`: entries with `status` in `("locked", "proposed")` (never `"rejected"`) that have at
  least one `find_terms` hit in the `source_text` of any of `regions`, in the input order of `entries`. All `entries`
  must have ids (they come from the store).
- `CHAT_JSON_SYSTEM` (copy verbatim, one Python string; the two quoted words `"sfx"` use plain double quotes):
  ```
  You are the translator for an official English release of a Korean manhwa. Translate every numbered region from Korean into natural, idiomatic English suited to comic lettering: concise, in the character's voice, with no translator notes. Write each translation as one continuous line without manual line breaks (the letterer re-wraps it). Keep Korean honorific suffixes and titles romanized when they address a person (-nim, -ssi, hyung, noona, sunbae) unless that reads badly in English. For a region of kind "sfx" give a short English onomatopoeia. Entries under "Glossary (binding)" are mandatory: whenever a source term appears (with or without a particle such as 이/가/은/는/을/를/의), its target must appear in your English exactly as written. Entries under "Glossary (suggested)" are preferred spellings but not mandatory. Answer with JSON only, in exactly this shape: {"translations":[{"id":"r0001","text":"..."}]} — one entry for every input id, no extra ids, no commentary.
  ```
- `TRANSLATIONS_SCHEMA` = `{"type":"object","properties":{"translations":{"type":"array","items":{"type":"object","properties":{"id":{"type":"string"},"text":{"type":"string"}},"required":["id","text"]}}},"required":["translations"]}`.
- `chat_json_messages(regions, entries)` returns `[{"role":"system","content":CHAT_JSON_SYSTEM}, {"role":"user","content":U}]` where
  `U` is built from these parts joined by a blank line (`"\n\n"`), omitting a part whose list is empty:
  1. `"Glossary (binding):\n" + "\n".join(f"- {e.source} -> {e.target} ({e.type})" for locked entries in the subset)`
  2. `"Glossary (suggested):\n" + the same line format for proposed entries in the subset`
  3. `"Regions (reading order):\n" + json.dumps([{"id": r.id, "kind": r.kind, "text": source_text(r)} for r in regions], ensure_ascii=False, indent=1)`
  (`entries` passed in are the full glossary; the function calls `glossary_subset(regions, entries)` itself; `regions` are
  used in the order given — the caller sorts.)
- `substitute_binding(text, entries)`: only `status == "locked"` entries; run `find_terms(text, locked)` and, for every
  match from the LAST to the first, replace `text[m.start : m.start + len(m.source)]` with that entry's `target` (the
  entry whose `id == m.entry_id`); the particle and everything else stay untouched. Example:
  `"성진이가 게이트에 들어간 지"` with locked 성진→Seong-jin and 게이트→Gate → `"Seong-jin이가 Gate에 들어간 지"`.
- `TRANSLATEGEMMA_TEMPLATE` = the string in `scripts/probe_translation.py` (the `prompt = (...) + text` in `tg_style`, up to
  and including the three newlines `\n\n\n` before the text); `translategemma_prompt(text)` = `TRANSLATEGEMMA_TEMPLATE + text`.

## Part 4 — Tolerant parsing (`parse.py`)
```python
@dataclass(frozen=True, slots=True)
class ParseResult:
    texts: dict[str, str]          # id -> stripped non-empty text, only ids from `expected_ids`
    missing: list[str]             # expected ids without a usable text, in `expected_ids` order

def extract_translations(content: str) -> list[Any] | None
def parse_translations(content: str, expected_ids: Sequence[str]) -> ParseResult
```
- `extract_translations(content)`: try, in order, (1) `json.loads(content.strip())`, (2) each fenced block
  ```` ```json ... ``` ```` / ```` ``` ... ``` ```` in order, (3) `json.JSONDecoder().raw_decode` starting at every `{` in
  the text from left to right. The first decoded value that is a `dict` whose `"translations"` is a `list` wins; return
  that list. If nothing qualifies return `None`. Never raises.
- `parse_translations`: items that are not dicts, or whose `id`/`text` is not a `str`, are ignored; ids not in
  `expected_ids` are ignored; for a duplicated id the first usable one wins; `text` is `.strip()`ped and an empty result
  counts as missing. `content` with no extractable list → `texts == {}` and every expected id missing.

## Part 5 — The run (`run.py`)
```python
class ChatClient(Protocol):
    def chat(self, model: str, messages: list[dict[str, Any]], *, cloud: bool = False,
             format: dict[str, Any] | Literal["json"] | None = None, options: dict[str, Any] | None = None,
             keep_alive: str | int | None = None, think: bool | None = None, max_retries: int = 5) -> ChatResponse: ...

def run_profile(client: ChatClient, profile: TranslationProfile, regions: Sequence[Region],
                entries: Sequence[GlossaryEntry], *, partial_path: Path | None = None,
                max_repair_rounds: int = 2, clock: Callable[[], float] = time.perf_counter) -> CandidateRun
```
Behaviour (exact):
1. `targets = translatable(regions)`. If `partial_path` exists and loads as a `CandidateRun` with the same `profile.name`
   and `model`, its candidates whose `region_id` is still in `targets` are kept and those regions are not requested
   again; a partial that cannot be loaded or belongs to another profile/model is ignored.
2. **`chat_json`**: split the remaining targets (in sorted order) into chunks of `profile.chunk_regions`. Per chunk:
   `client.chat(profile.model, chat_json_messages(chunk, entries), cloud=(profile.endpoint == "cloud"),
   format=TRANSLATIONS_SCHEMA, options={"temperature": profile.temperature}, think=profile.think)`; parse with
   `parse_translations`. While ids are missing and fewer than `max_repair_rounds` repair rounds were used for this
   chunk: send another request with ONLY the still-missing regions (same builder, same arguments) and merge the results
   (each such request counts as a repair request). Ids still missing after that get no candidate. After every chunk save
   the partial (see 4).
3. **`translategemma`**: one request per remaining target, in order: messages
   `[{"role":"user","content": translategemma_prompt(substitute_binding(source_text(r), entries))}]`, same
   `cloud`/`options`/`think` arguments, **no** `format`. The candidate text is `response.content.strip()`; if that starts
   and ends with a straight `"` (length >= 2) and `source_text(r)` does not start with any of `"`, `“`, `「`, `『`, remove
   exactly that one outer pair and strip again. An empty reply means no candidate. Save the partial every 20 regions.
4. Saving the partial: `CandidateRun(...).save(partial_path)` with the candidates so far (if `partial_path` is not None).
5. Result: `CandidateRun(run_id=profile.name, profile=profile.name, model=profile.model, candidates=[...], usage={...})`;
   candidates in target order (one `Candidate(region_id=..., text=..., notes=None)` per translated region, including those
   restored from a partial). `usage` keys exactly, all `float`: `prompt_tokens` and `completion_tokens` (sums of
   `prompt_eval_count` / `eval_count`, `None` counted as 0, over the requests made in THIS call), `requests`,
   `repair_requests`, `regions` (number of targets), `missing` (targets without a candidate), `seconds` (`clock()` delta
   over the call).
6. Any exception from `client.chat` (including `OllamaRateLimitError`, `OllamaError`) propagates unchanged, after the
   partial for everything completed so far has been saved. Do not catch it.

## Part 6 — Chapter level (`chapter.py`)
```python
def translate_chapter(client: ChatClient, paths: ChapterPaths, profile: TranslationProfile,
                      entries: Sequence[GlossaryEntry], *, force: bool = False) -> tuple[Literal["done", "skipped"], CandidateRun | None]
```
- Output file `paths.artifact(f"translations/{profile.name}.json")`; partial file
  `paths.artifact(f"translations/.{profile.name}.partial.json")` (dot-prefixed so the web listing ignores it).
- If the output exists and `force` is false → `("skipped", None)` without any request.
- `ocr.json` missing → raise `FileNotFoundError("ocr.json missing — run the ocr stage first")`.
- Otherwise `RegionsArtifact.load`, `run_profile(..., partial_path=partial)`, save the run to the output file
  (`CandidateRun.save`), delete the partial (ignore if absent) and return `("done", run)`. With `force`, an existing
  partial is ignored and removed before the run starts.

## CLI
Replace the `translate` stub (remove `"translate"` from `_STUB_COMMANDS`, delete `cmd_translate`, register the new
command with `app.command("translate")`):
`omniscan translate SERIES [--chapter/-c CHAPTER]... [--profile/-p NAME]... [--force]`
- Chapters: the given ones, else all chapters of the series (`SeriesPaths.chapters()`); none found → `translate: no
  chapters found for series 'X'` on stderr, exit 2.
- Profiles: `load_profiles(default_profile_paths())`; the given names, else every profile with `enabled = true`. An unknown
  name → `translate: unknown profile 'x' (known: a, b, c)` on stderr, exit 2. No enabled profile → message, exit 2.
- Glossary: `GlossaryStore(paths.db)` only if `paths.db.is_file()` (never create it), else no entries; use all entries.
- Client: one `OllamaClient(cfg.ollama, get_secrets())` for the whole command (use `get_config()` / `get_secrets()` from the
  `omniscan.cli` namespace so tests can monkeypatch them; import `OllamaClient` at module level for the same reason).
- Loop chapters (reading order) × profiles (given/default order); one line each:
  `{series}/{chapter} {profile}: done ({n} regions, {m} missing, {s:.1f}s)` or `... skipped`. A chapter without `ocr.json`
  prints `{series}/{chapter}: ocr.json missing — run the ocr stage first` on stderr, counts as a failure and the loop
  continues with the next chapter. `OllamaRateLimitError` → stderr message
  `translate: Ollama rate limit reached — partial results are kept; re-run later` and **exit 3 immediately**. Any other
  `OllamaError` → message on stderr, count as a failure, continue. Exit 1 at the end if any failure occurred, else 0.

## Why
The owner hears coil whine from the GPU: the load is not steady. Measured causes (`docs/GPU_NOTES.md`): every process pays a **9–14 s stall at its first convolution** (MIOpen loads a 311 MB library), plus 1–3 s each for the first FFT, GEMM and transposed convolution, while the GPU idles; and the typeset stage keeps the GPU idle for ~5 s per chapter because its font-fit loop calls `ImageFont.getlength` 33 000 times (96 % of the stage). This card (1) starts a **warm-up on a background thread** so those stalls overlap with ingest, JPEG decoding and model loading, and (2) makes the typeset fit loop several times cheaper **without changing a single layout result**. The measured facts are a fixed part of the spec: a background thread does hide the stall (the main thread stays free and its own first convolution then takes 0.01 s).

## Part 1 — `gpu/warmup.py`
```python
class GpuWarmup:
    """Initialises the GPU libraries once per process on a daemon thread; never raises."""
    def __init__(self, device: torch.device) -> None: ...
    def start(self) -> None: ...                       # spawn the thread (no-op if already started or the device is not "cuda")
    def wait(self, timeout: float | None = None) -> bool: ...   # True when finished (also True at once when there is nothing to do)
    @property
    def done(self) -> bool: ...
    @property
    def seconds(self) -> float | None: ...             # wall time of the warm-up, None until done
    @property
    def error(self) -> str | None: ...                 # "<ExceptionType>: <message>" of the first failure, else None

def start_warmup(device: torch.device) -> GpuWarmup: ...   # one shared instance per (process, str(device)); starts it; later calls return the same object
```
The thread body (exact list, all fp32, inside `torch.inference_mode()`, after `torch.cuda.set_device(device)` — MIOpen launches against the *current* device):
1. `F.conv2d` 3×3 on `[8, 32, 320, 320]` with a `[64, 32, 3, 3]` weight (padding 1) — the call that loads the Composable-Kernel library;
2. `F.conv2d` 1×1 on the same input; 3. `F.conv_transpose2d` (`[1, 64, 64, 64]`, weight `[64, 32, 4, 4]`, stride 2, padding 1);
4. `torch.fft.rfft2` and `torch.fft.irfft2` on `[1, 64, 256, 256]` **and** on `[1, 64, 512, 512]` (`s=(512, 512)` for the inverse) — LaMa's window;
5. `torch.bmm` on `[4, 128, 128]` × `[4, 128, 128]`; 6. `F.interpolate(..., mode="bilinear", antialias=True)`; 7. `torch.cuda.synchronize(device)`.
Every step runs inside its own `try/except Exception`: a failing step is logged at WARNING (`"GPU warm-up step %s failed: %s"`), recorded in `error` (first failure only) and the remaining steps still run. On success/finish log at INFO `"GPU warm-up finished in %.1f s"`. A non-CUDA device (`cpu`, `mps`) → `start()` does nothing and `done` is True immediately with `seconds == 0.0`.
`groups.build_vram_manager(cfg)`: when `cfg.gpu.warmup` is true and the resolved device (`resolve_device(cfg.gpu.device)`, the same call `VramManager` uses — read how it resolves) is CUDA, call `start_warmup(device)` **before returning the manager** and keep the handle as `manager.warmup` (add a plain attribute; if `VramManager` uses `__slots__`, store it in a module-level variable instead and say so in the report). It must not block: the caller continues at once. `cfg.gpu.warmup = False` → nothing starts. Building the manager on a machine without CUDA must not raise and must not import anything heavy at module import time.

## Part 2 — faster typeset fit loop (results must be identical)
`fit_text` scans sizes from `max_px` down to `min_px`; for each size it wraps the whole text (`wrap_words`) and measures every candidate line, so the same strings are measured again and again (33 017 `getlength` calls for 67 regions in a real chapter). Implement these three savings **inside `fit_text`/`wrap_words`, keeping their signatures, return values and behaviour for every input** (`Measurable`/`FontFactory` stay as they are, so fake fonts in tests keep working):
1. **Per-call measurement memo**: within one `fit_text` call, a `dict[str, float]` in front of `font.getlength` for each size (the same string is measured by `wrap_words` and again for the widest-line computation).
2. **Early exit per size**: for a size that is not `min_px`, as soon as one word alone is wider than `max_w` the size cannot be chosen (`too_wide`) — return to the next size without finishing the wrap and without the widest-line computation. (At `min_px` the full result is still needed as the fallback.)
3. **Lower bound on the line count**: for a size that is not `min_px`, measure each word once (`sum_words = Σ getlength(word)`); the wrapped text needs at least `ceil(sum_words / max_w)` lines (every line is at most `max_w` wide and the words are all on some line); if `ceil(sum_words / max_w) * line_height(size, line_spacing) > max_h` the size cannot fit — skip it. Use exact float arithmetic exactly as written (do not round the sum).
4. **Cross-call cache for the default font path only**: when `font_factory is load_font`, cache the loaded font per `(font_path, size)` and the measurements per `(font_path, size, text)` in module-level bounded dicts (max 200 000 measurement entries, cleared when full; max 512 fonts). Fakes (any other factory) get only the per-call memo. The cache key must include the font file's `resolve()`d path so two different fonts never share entries.
`wrap_words(text, font, max_width)` keeps its exact current outputs for any `Measurable` (property test below).

## Definitions
- "Identical result" = equal `Fit` dataclasses (`size_px`, `lines`, `width`, `height`, `overflow`), compared with `==`.
- A spy font is a fake with `getlength(text) = 7.0 * len(text)` (or a table) that counts calls.

## Acceptance tests (CPU only)
1. **Warm-up (`test_gpu_warmup.py`)** with the torch ops monkeypatched by recorders (never touch a real GPU in these tests; make the "CUDA" device a `torch.device("cuda", 0)` object and patch `torch.cuda.set_device`, `torch.cuda.synchronize` and the op functions): the exact op sequence above runs on a **different thread** than the caller (record `threading.get_ident()`), `wait()` returns True, `done`/`seconds` set, `error is None`; a step that raises is logged, recorded in `error` (first failure only), and the later steps still ran; `start()` twice runs the sequence once; `cpu` and `mps` devices → no thread started, `wait()` True, `seconds == 0.0`; `start_warmup` returns the same object for the same device and a different one for another device string; `wait(timeout=0.01)` returns False while a step is blocked on an event and True after it is released.
2. **Groups**: `build_vram_manager(cfg)` with `cfg.gpu.warmup=True` and a monkeypatched CUDA device resolution calls `start_warmup` exactly once and exposes the handle; with `warmup=False` or a cpu device it does not; existing `test_gpu_groups.py` tests pass unchanged.
3. **Identical layouts (`test_typeset_fit_speed.py`)**: a reference implementation of the **old** `fit_text`/`wrap_words` (copy of the pre-change code, inside the test module) is compared with the new one on ≥ 300 random cases with a table-based fake font (word widths from a seeded RNG, sizes scale the widths linearly, boxes from 40×30 to 600×400, texts of 0–40 words including words wider than the box, one-word texts, repeated words, `min_px == max_px`, `line_spacing` 0.9…1.6): `==` on every case. Include hand-made cases: nothing fits (fallback at `min_px` with `overflow=True`), exactly fits, fits only at `min_px`, empty text.
4. **Fewer measurements**: with the counting spy font on a synthetic "chapter" of 60 regions (seeded random 8–30 words each, boxes 120×80…400×250) the total number of `getlength` calls of the new code is **at most 40 %** of the old reference's (assert the ratio and print both numbers in the report); the results stay identical.
5. **Cross-call cache**: two `fit_text` calls with `font_factory=load_font` on the same text/font (use a real bundled font from `fonts/`, e.g. `ComicNeue-Regular.ttf`) return equal results and the second makes no `ImageFont.FreeTypeFont.getlength` calls (spy via monkeypatching `ImageFont.FreeTypeFont.getlength` with a counting wrapper); a different font file with the same text/size does **not** reuse entries; the caches are bounded (fill past 200 000 entries with a fake font path → the dict is cleared and the next call still returns the right result).
6. The whole CPU suite `uv run --frozen pytest -q -m "not gpu"` stays green, including the typeset stage/render tests and the golden E2E test if it is not GPU-marked. Run `uv run --frozen pytest tests/unit/test_e2e_synthetic.py -q` at the end if it runs on this machine and put the result in the report (it is a GPU test; the director re-runs it anyway).

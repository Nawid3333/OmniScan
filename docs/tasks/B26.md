`filter`, `glossary`, `watermark`, `pack`, `serve`) and the web viewer exists. Write documentation a new user (or a

invent a flag, and never describe a stub as working.

## Acceptance tests (`tests/unit/test_docs.py`)
Use `typer.main.get_command(omniscan.cli.app)` to get the click command tree.
1. **Every documented command exists.** Parse `README.md` and `docs/USER_GUIDE.md`; in every fenced code block whose
   info string is `bash`, `sh` or `console`, for each line that (after stripping a leading `$ ` and any leading
   `uv run `) starts with `omniscan `, take the tokens after `omniscan`, skip tokens starting with `-` and their
   obvious values only until the first bare word — simplest rule: the first token not starting with `-` is the
   command name and MUST be a name in the top-level click group's `commands`; if that command is itself a group
   (`filter`, `glossary`, `watermark`), the next non-option token MUST be one of its `commands`. Lines inside the
   "Not implemented yet" table are markdown, not code, so they are not checked.
2. **No stub is documented as working.** No fenced-code `omniscan <name>` line may use a command whose click
   `help` text starts with `Not implemented yet`.
3. **Relative links resolve.** Every markdown link `[text](target)` in both files whose target does not start with
   `http://`, `https://`, `mailto:` or `#` points (after stripping a trailing `#anchor`, resolved relative to the
   file containing it) to an existing file or directory.
4. **Sanity:** both docs files exist, are non-empty, and README.md is at most 150 lines.
5. A meta-test proving test 1 can fail: call the extraction/validation helper on the literal string
   ```` "```bash\nomniscan definitely-not-a-command\n```" ```` and assert it reports that command as unknown.

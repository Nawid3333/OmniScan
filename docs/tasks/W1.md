## Why
Owner requirement: when an upstream model changes (a new PP-OCR release, PaddleOCR-VL 1.7, a new manga-ocr), the program must not silently fall behind — a scheduled GitHub Action reports what changed, so that the qualification suite (card O1c) can be run on the new candidate and the catalog updated **only if it improves results**. The job **never changes the catalog and never downloads weights**; it only compares metadata and opens (or updates) an issue.

## Interfaces (exact)
```python
@dataclass(frozen=True, slots=True)
class Change:
    kind: Literal["updated", "new", "missing"]
    repo: str
    catalog_id: str | None           # for "updated"/"missing"
    old_revision: str | None; new_revision: str | None
    last_modified: str | None        # ISO string from the API
    downloads: int | None
    note: str                        # one human sentence

def load_watch_config(path: Path) -> WatchConfig: ...           # orgs -> patterns, ignore list; ValueError with the field on bad input
def check_entries(entries: Sequence[ModelEntry], fetch: Fetch) -> list[Change]: ...        # "updated" when the head sha differs from upstream_revision, "missing" when the repo answers 404
def find_new(entries: Sequence[ModelEntry], cfg: WatchConfig, fetch: Fetch) -> list[Change]: ...   # "new": repos of the watched orgs matching a pattern that are neither in the catalog nor ignored
def render_report(changes: Sequence[Change], *, generated: str) -> str: ...     # markdown; empty changes -> a one-line "no changes" report
def main(argv: Sequence[str] | None = None, *, fetch: Fetch | None = None) -> int: ...
```
`Fetch = Callable[[str, Mapping[str, str] | None], tuple[int, Any]]` (`(url, params) -> (status_code, parsed JSON or None)`); the default implementation uses `httpx` with a 30 s timeout, `User-Agent: OmniScan-model-watch`, an optional `HF_TOKEN` environment variable as bearer token (never printed), 2 retries on `5xx`/transport errors with `0.5 * 2**attempt` s back-off.

## Definitions (exact)
- **Model API**: `GET https://huggingface.co/api/models/<repo>` → JSON with `sha` (head commit, 40 hex) and `lastModified`; status 404 → repo gone. **Listing API**: `GET https://huggingface.co/api/models` with params `author=<org>`, `search=<term>`, `limit=100`, `sort=lastModified`, `direction=-1` → a JSON list of `{"id": "<org>/<name>", "lastModified": …, "downloads": …}`.
- **`config/model_watch.toml`** (ship it): `[orgs."PaddlePaddle"]` with `search = ["OCR"]` and `patterns = ["PP-OCRv*", "*PP-OCRv*_rec*", "PaddleOCR-VL*"]`; `[orgs."kha-white"]` `search = ["manga-ocr"]` `patterns = ["manga-ocr*"]`; `[orgs."jzhang533"]` `search = ["manga-ocr"]` `patterns = ["manga-ocr*"]`; `[orgs."ogkalu"]` `search = ["comic"]` `patterns = ["comic-text*"]`; `ignore = []` (repo ids that must not be reported again). Patterns are `fnmatch` patterns (case-insensitive) matched against the repo name **without** the org.
- **`check_entries`**: only entries with `format == "hf"` (and the zip entries that have `upstream_repo` + `upstream_revision`); one request per distinct repo; `sha != upstream_revision` → `Change("updated", …, old_revision=<catalog>, new_revision=<sha>, note=f"{catalog_id}: upstream has a newer commit")`; 404 → `Change("missing", …, note="repo not found (renamed or removed?)")`; any other failure → the entry is skipped with a `warnings` line on stderr (never a crash, never a "change").
- **`find_new`**: for every org and every `search` term call the listing API (dedupe repos across terms), keep repos whose name matches at least one pattern, that are not the `upstream_repo` of any catalog entry and not in `ignore`; each becomes `Change("new", repo, catalog_id=None, …, note="not in the catalog")`, sorted by `last_modified` descending. Listing failures → warning, no change.
- **`render_report`**: markdown starting with `# Model watch report` and the generated timestamp, then a section per kind that has entries (`## Updated upstream`, `## New upstream models`, `## Missing upstream`), each a table `repo | catalog id | old → new | last modified | downloads | note` (`new` has no old/new), then a closing block `## What to do` with three bullet lines (`run scripts/qualify_ocr.py --only <candidate> on a GPU machine`, `update config/models.toml only if the qualification improves`, `add the repo to the ignore list in config/model_watch.toml to silence it`). Deterministic output.
- **`main`**: `--catalog PATH` (default `config/models.toml`), `--config PATH` (default `config/model_watch.toml`), `--markdown OUT.md` (also written when there are no changes), `--json OUT.json` (list of changes as dicts), `--fail-on-change` (exit code 3 when any change), `--offline` (no network: only validate both files and print `ok`), exit codes 0 / 3 / 2 (bad arguments or unreadable config). Report goes to stdout too.
- **Workflow `.github/workflows/model-watch.yml`**: `on: schedule: cron "0 6 * * 1"` (Mondays 06:00 UTC) and `workflow_dispatch`; `permissions: contents: read, issues: write`; one job on `ubuntu-latest`: checkout, `astral-sh/setup-uv`, `uv run --no-project --with httpx python scripts/model_watch.py --markdown model-watch.md --json model-watch.json --fail-on-change` with `continue-on-error`-free handling of the exit code (capture it: `set +e; …; code=$?; set -e`), then **if the exit code is 3**: look for an open issue labelled `model-watch` (`gh issue list --label model-watch --state open --json number --jq '.[0].number'`); if one exists `gh issue comment <n> --body-file model-watch.md`, else `gh issue create --title "Model watch: upstream changes" --label model-watch --body-file model-watch.md` (create the label with `gh label create model-watch --color 5319e7 --force` first); exit code 2 fails the job; upload `model-watch.md` and `.json` as artifacts. `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}` is the only secret used; `HF_TOKEN` is optional (`${{ secrets.HF_TOKEN }}`, may be empty).

## Acceptance tests (CPU, fake `Fetch`, tmp files; no network)
1. `load_watch_config` on the shipped file: 4 orgs, patterns lists, empty ignore; bad input (missing `patterns`, wrong types, empty org name) → `ValueError` naming the field.
2. `check_entries` with a catalog of: an hf entry whose fake head equals the pinned revision (no change), one with a different head (`updated`, notes/revisions right), a 404 repo (`missing`), a repo answering 500 (skipped + warning), a zip entry with `upstream_repo`/`upstream_revision`, an ollama/cloud entry (ignored), two entries sharing a repo (one request, two changes when it changed).
3. `find_new`: listing pages for two orgs and two search terms (duplicates across terms), name patterns (case-insensitive, org prefix not matched), repos already in the catalog and in `ignore` excluded, sorted newest first, a failing listing → warning only.
4. `render_report`: golden markdown for one of each kind; the no-change report; deterministic ordering.
5. `main`: `--fail-on-change` exit codes 0/3, `--offline` validates and exits 0 without calling fetch, `--markdown`/`--json` written (also without changes), bad `--config` → 2, `HF_TOKEN` is sent as a bearer header when set and **never appears in stdout/stderr or the report**; the default fetch retries a 503 then succeeds (MockTransport + fake sleep) and gives up after 2 retries.
6. The workflow file parses as YAML (`yaml.safe_load`), triggers include `schedule` and `workflow_dispatch`, `permissions` are exactly `contents: read` and `issues: write`, the steps mention `scripts/model_watch.py`, `gh issue create` and `gh issue comment`; `tests/unit/test_docs.py` and the CPU suite stay green.

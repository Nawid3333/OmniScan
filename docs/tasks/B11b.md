## Why
`inpaint.json`+`patches.npz` and `layout.json` are pipeline artifacts nobody can currently see without opening a
`.npz` file by hand. This card adds two web views: one to check inpainting quality (did the text actually get
removed cleanly? was the right patch used?) and one to check typeset placement before lettering renders. Coordinate
spaces: `InpaintItem.box`/`LayoutItem.box` are in **strip space** (same space as OCR regions — `stripBoxToStackBox`
already maps that to the stacked-raw-pages view OcrView uses); `patches.npz` pixel arrays are small per-region crops
in that same strip space, cropped to `box`. There is **no existing full "clean strip" image anywhere** — building
one server-side would need the torch-based `export/composite.py` machinery the web app deliberately does not
depend on. Instead: serve each patch as its own small PNG and let the browser position it over the raw pages at
`box`'s mapped location (exactly how OcrView already positions SVG rects) — a `<div>`/`<img>` stack, not a new
image-decoding pipeline.

## Part 1 — three new API routes in `web/app.py`

```python
@app.get("/api/series/{series}/chapters/{chapter}/inpaint")
def get_inpaint(series: str, chapter: str) -> Response:
    """The chapter's inpaint.json, byte-for-byte as written by the inpaint stage."""
    return artifact_bytes(chapter_paths(series, chapter), "inpaint.json")

@app.get("/api/series/{series}/chapters/{chapter}/layout")
def get_layout(series: str, chapter: str) -> Response:
    """The chapter's layout.json, byte-for-byte as written by the typeset stage."""
    return artifact_bytes(chapter_paths(series, chapter), "layout.json")

@app.get("/api/series/{series}/chapters/{chapter}/inpaint/patches/{region_id}.png")
def get_inpaint_patch(series: str, chapter: str, region_id: str) -> Response:
    """One region's inpaint patch as an RGBA PNG (alpha = the patch's mask, scaled 0/255)."""
```
`get_inpaint_patch` (implement exactly this order):
1. `paths = chapter_paths(series, chapter)`. Load `inpaint.json` via `InpaintArtifact.load(paths.artifact("inpaint.json"))`;
   missing file → 404 `"inpaint.json not found"`.
2. `region_id` must equal the `region_id` of one of the artifact's `items`; unknown → 404 `"region not found"`
   (this is the traversal guard for this route — `region_id` is never used to build a filesystem path, only as a
   lookup key, so validating it against the known list is what replaces the usual `_under`/`..` check here — say so
   in a one-line comment).
3. `patches_path = paths.artifact("patches.npz")`; missing → 404 `"patches.npz not found"`.
4. `load_patches(patches_path)` (import from `omniscan.inpaint.patches`); `region_id` not a key → 404
   `"no patch stored for this region"` (this is the normal case for a `method="flat"` item — flat fills have no
   npz entry, only a solid `fill` colour, which the frontend renders without ever calling this endpoint — see
   Part 3).
5. Build the image with **PIL and numpy only, no torch**: `pixels` is `uint8 [h, w, 3]`, `mask` is `bool [h, w]`.
   `img = Image.fromarray(pixels, mode="RGB").convert("RGBA")`; `alpha = Image.fromarray((mask.astype(np.uint8) *
   255), mode="L")`; `img.putalpha(alpha)`. Encode to PNG in memory (`io.BytesIO`, `img.save(buf, format="PNG")`),
   return `Response(content=buf.getvalue(), media_type="image/png")`.

## Part 3 — `webui/src/inpaint.ts` + `InpaintView.svelte` (clone `ocr.ts`/`OcrView.svelte`'s structure)

`inpaint.ts` (pure functions, no DOM, mirror `ocr.ts`'s style — check its exact exports/helpers such as `kindColor`
and match that pattern):
```ts
export function methodColor(method: InpaintMethod): string { /* three fixed, distinct colors, e.g. flat/lama/none */ }
export function fillCss(fill: [number, number, number] | null): string { /* "rgb(r, g, b)" or "transparent" when null */ }
export function cleanClipPath(revealPercent: number): string { /* CSS clip-path revealing the LEFT `revealPercent`% of the clean layer, e.g. `inset(0 ${100 - revealPercent}% 0 0)`; clamp input to [0, 100] */ }
export function hasStoredPatch(item: InpaintItem, patchRegionIds: ReadonlySet<string>): boolean { /* item.region_id is in the set */ }
```
`InpaintView.svelte` (`{ series, chapter }` props, same `$effect`-driven load pattern as `OcrView.svelte`):
- Loads `getIngest` + `getInpaint` in parallel (`Promise.all`, same error handling as `OcrView`'s `load`).
- One `<input type="range" min="0" max="100">` bound to a `$state<number>` `reveal` (default `50`), labelled
  "raw ↔ clean".
- The stack container (`position: relative`, `stackWidth`/`stackTotalHeight` sized, exactly like `OcrView`):
  1. **Bottom layer:** the raw page `<img>` elements, positioned exactly as in `OcrView.svelte` (always fully
     visible — this is "raw").
  2. **Clean layer:** a child `<div>` covering the same area, `style="position: absolute; inset: 0; clip-path:
     {cleanClipPath(reveal)};"`. Inside it, for every `InpaintItem`, positioned via `stripBoxToStackBox(files,
     item.box)`: if `hasStoredPatch(item, patchIds)` (a `$derived` `Set` of the ids actually reachable — see below),
     an `<img>` at that position/size with `src={inpaintPatchUrl(series, chapter, item.region_id)}`; else (a
     `method === "flat"` item with no patch) a `<div>` at that position/size with `style="background:
     {fillCss(item.fill)};"`. `method === "none"` items render nothing in this layer (nothing to reveal — no
     inpainting was done).
     `patchIds`: since there is no "list patch ids" endpoint, treat every item whose `method !== "none"` as
     *attempted to have* a patch and just let the `<img>` 404 gracefully — **simpler and correct**: don't try to
     predict which ids truly have a stored patch; instead render an `<img>` for every `method !== "none"` item and
     use an `onerror` handler to swap it for the flat-fill `<div>` behaviour on that one item only (a per-item
     `$state<boolean>` "patch failed to load" flag, or a Svelte `{#key}`-scoped local variable — pick whichever is
     idiomatic for Svelte 5 runes; do not do a separate existence-check request per item).
  3. **Overlay layer:** an SVG the same size as the stack, `pointer-events: none` on the `<svg>` itself but
     `pointer-events: all` on each `<rect>` (exactly like `OcrView`), toggled by one checkbox "show patch outlines"
     (default on). One `<rect>` per item at `stripBoxToStackBox(files, item.box)`, `stroke={methodColor(item.method)}`,
     `fill-opacity` low, click sets `selectedId` (toggle-off on re-click, exactly like `OcrView`).
- Click-to-select `<aside>` (clone `OcrView`'s, same fixed positioning/styling): shows `region_id`, `method`
  (colored dot via `methodColor`), `needs_lama`, `mask_px`, and a `fill` colour swatch (a small `<div>` using
  `fillCss`) when not null; when the item has a patch, also show it enlarged (`<img src={inpaintPatchUrl(...)}
  style="max-width: 300px;">` — reuses the exact same URL, so no new fetch logic).
- Empty/error states identical in wording style to `OcrView`'s (`"no ocr.json yet"` → `"no inpaint.json yet — run
  inpaint first"`).

## Goal
The promo filter (card B6) moves ad/credit pages and slices out of the pipeline but leaves a false positive
unrecoverable except through the CLI. Add a series-wide **Filtered** view: every file/slice the filter ever marked
`filtered`, per chapter, with score and matched example, a thumbnail for file-level items, and a **Restore** button.
This is the web tool's **first write action**, so the security rules below are part of the acceptance criteria.
Restore is exactly what `omniscan filter restore` does: it appends a `restored` decision to `filter.json` and never
touches files already copied into `_filtered/`.

## Part 1 — Backend (`src/omniscan/web/app.py`)

1. **CORS:** `allow_methods=["GET", "POST"]` (origins unchanged: only the dev origin(s) passed to `create_app`).
2. `GET /api/series/{series}/filtered` → JSON `list[FilteredChapter]`, in `SeriesPaths.chapters()` order, including only
   chapters that have a `filter.json` AND at least one item (below); uses `series_paths` / `chapter_paths` validation.
   ```json
   [{"chapter": "Chapter 1", "items": [
      {"target": "file",  "index": 3, "state": "filtered", "score": 0.97, "matched_example": "global/end_card.jpg",
       "method": "phash", "name": "004.jpg", "y0": null, "y1": null},
      {"target": "slice", "index": 7, "state": "restored", "score": 0.93, "matched_example": "global/ad.jpg",
       "method": "phash", "name": null, "y0": 20100, "y1": 23000}]}]
   ```
   - An **item** exists for every distinct `(target, index)` that has at least one decision with
     `decision == "filtered"` in `filter.json`. `state` = `effective_decision(artifact, target, index)` (so `"filtered"` or
     `"restored"`); `score`, `matched_example`, `method` come from the **last** `"filtered"` decision of that pair.
   - `name`: for `target == "file"`, the `name` of the `SourceFile` with `.index == index` in `ingest.json`, else `null`
     (also when `ingest.json` is missing/invalid). `y0`/`y1`: for `target == "slice"`, from the `Slice` with
     `.index == index` in `slices.json`, else `null`.
   - Items sorted `file` before `slice`, then by `index`. An invalid/unreadable `filter.json` skips that chapter (never a 500).
3. `POST /api/series/{series}/chapters/{chapter}/filter/restore` with JSON body `{"target": "file" | "slice", "index": int}`
   (a pydantic model with `Literal["file", "slice"]` and `index: int` with `ge=0`; extra fields forbidden):
   - **Content-type guard (CSRF):** the request's `Content-Type` must start with `application/json` (case-insensitive),
     otherwise `415` and nothing is written. (A cross-site page can send `text/plain` POSTs without a CORS preflight; this
     guard closes that hole.)
   - `chapter_paths(series, chapter)` validation (404 on `..` escapes as for every route).
   - `filter.json` missing → `404` (`"filter.json not found"`). The pair `(target, index)` must currently have effective
     decision `"filtered"`; otherwise `409` with `{"detail": "item is not currently filtered"}` and nothing is written.
   - Otherwise call `omniscan.filter.decide.restore(paths, target, index)` and return the new decision as JSON
     (`decision.model_dump(mode="json")`, status 200).

## Part 2 — Frontend

`webui/src/api.ts` — add types `FilteredItem`, `FilteredChapter` matching the JSON above, a generic
`postJson<T>(path, body)` helper (sets `Content-Type: application/json`, throws on non-2xx like `getJson`, and includes the
response `detail` text in the error message when the body has one), and:
```typescript
export async function listFiltered(series: string): Promise<FilteredChapter[]>;
export async function restoreFiltered(series: string, chapter: string, target: "file" | "slice", index: number): Promise<void>;
```
(every path segment `encodeURIComponent`-ed.)

`webui/src/filtered.ts` — pure helpers, exact signatures:
```typescript
export function itemKey(chapter: string, item: FilteredItem): string;            // `${chapter}|${item.target}|${item.index}`
export function summarizeFiltered(chapters: FilteredChapter[]): { chapters: number; filtered: number; restored: number };
export function describeItem(item: FilteredItem): string;
//   file  : `file ${index}` + (name ? ` (${name})` : "")
//   slice : `slice ${index}` + (y0 !== null && y1 !== null ? ` (y ${y0}–${y1})` : "")      // en dash between the numbers
export function scoreText(item: FilteredItem): string;   // `${score.toFixed(2)} · ${matched_example ?? "no example"} · ${method}`
export function markRestored(chapters: FilteredChapter[], chapter: string, target: "file" | "slice", index: number): FilteredChapter[];
//   returns a NEW array/objects with that item's state set to "restored"; every other item and the input are untouched;
//   an unknown chapter/item returns an equal copy.
```

`webui/src/FilteredView.svelte` — props `{ series: string }`. On mount / series change `listFiltered(series)`; failure →
inline error text; empty result → `nothing was filtered in this series`. Show a one-line summary from `summarizeFiltered`
(`2 chapters · 5 filtered · 1 restored`). Then, per chapter, a heading and a list of items (`describeItem`, `scoreText`,
a state badge `filtered` (red) / `restored` (green)). For a `file` item show a thumbnail
`<img src={pageImageUrl(series, chapter, item.index)} loading="lazy" style="max-width: 160px; max-height: 220px">`
(the raw page is still in the library even when filtered). A `Restore` button on items whose state is `filtered`: it calls
`restoreFiltered`, and on success updates the local list with `markRestored` (no refetch), on failure shows the error
next to the button; the button is disabled while its request is in flight. Restored items show no button.
Slice items get no thumbnail (out of scope).

## Acceptance tests

**Backend** (append to `tests/unit/test_web_app.py`; reuse its helpers; write real `filter.json` / `ingest.json` /
`slices.json` with the schema classes):
1. `filtered` lists items in the documented shape and order: two chapters, one without `filter.json` (excluded), one with a
   `keep` decision only (excluded), items for a file and a slice, the `name` from `ingest.json` and `y0`/`y1` from
   `slices.json`; with `ingest.json` absent → `name: null`; an item that was `filtered` then `restored` appears with
   `state: "restored"` and the `score` of the last `filtered` decision; unknown series → `[]`; `..` series → 404;
   an invalid `filter.json` → that chapter is skipped, status 200.
2. `restore` success: appends exactly one `restored` decision (`method == "manual"`) to `filter.json`, returns it, and a
   following `filtered` request shows `state: "restored"`; the files under `_filtered/` are untouched (byte-identical,
   same mtime not required).
3. `restore` on an item that is not filtered (never filtered, or already restored) → `409` and `filter.json` byte-identical
   to before; missing `filter.json` → 404; body with `target: "page"`, negative `index`, or an extra field → `422`.
4. **CSRF guard:** POST with `Content-Type: text/plain` (body a valid JSON string), with `application/x-www-form-urlencoded`,
   and with no content type → `415`, `filter.json` unchanged; `application/json; charset=utf-8` works.
5. CORS: a preflight `OPTIONS` from the allowed origin for the restore route allows `POST`; from another origin
   (`http://evil.example`) does not return an `access-control-allow-origin` header.
6. `..` in the series or chapter value on the restore route → clean 404, nothing written.

**Frontend** (vitest, pure functions only):
7. `itemKey`, `describeItem` (file with/without name, slice with/without range, the en dash), `scoreText` (with and without
   `matched_example`).
8. `summarizeFiltered` on a hand-built list (chapters counts only chapters given; filtered/restored counts by state).
9. `markRestored`: only the addressed item changes, input not mutated, unknown chapter/index returns an equal copy.

## Goal
Add a third view, **Translation**, to the web debug tool: one table row per OCR region in reading order, with the
source text (glossary terms highlighted), every candidate translation run side by side, the judge's final line with
its decision, flags and rationale, and the glossary hits with a red mark where a *locked* term's target is missing from
the final line. The translation stages (C5) do not exist yet, so this card is built against the schemas in
`core/schemas.py` and hand-written JSON artifacts, exactly like B5/B7 were. Read-only, no editing.

## Existing contracts you build on (read, do not modify)
- `core/schemas.py`: `RegionsArtifact` (`ocr.json`, see B7), `CandidateRun`, `Candidate`, `FinalArtifact`, `FinalLine`,
  `GlossaryEntry`. JSON shapes (what `model_dump_json()` produces):
  - `CandidateRun {schema_version, run_id, profile, model, created_at (ISO string), candidates: Candidate[], usage: {string: number}}`
    with `Candidate {region_id, text, notes: string | null}`.

    `FinalLine {region_id, text, decision: "pick" | "merge" | "rewrite" | "manual", sources: string[], rationale: string, flags: string[]}`.
  - `GlossaryEntry {id: number | null, source, target, type: string, gender: string, pronouns: string | null, aliases: string[], notes: string | null, status: "proposed" | "locked" | "rejected", origin: "llm" | "reference" | "user", first_seen_chapter: number | null, count: number}`.
- `omniscan.glossary.store.GlossaryStore(db_path)` (`.list(status=None) -> list[GlossaryEntry]`, context manager) and
  `omniscan.glossary.match.find_terms(text, entries) -> list[Match]` / `term_present(text, entry) -> bool`.
  **Careful:** `GlossaryStore(...)` creates the sqlite file if it does not exist, so never construct it unless
  `SeriesPaths.db.is_file()`.
- On disk, per chapter work dir: `ocr.json`, `translations/<run_id>.json` (the file stem is the run identifier used in
  URLs below), `final.json`. Per series work dir: `series.db`.

## Part 1 — Backend (`src/omniscan/web/app.py`)
All read-only GET routes, all reusing the existing `series_paths` / `chapter_paths` / `artifact_bytes` helpers
(so `..` traversal in series/chapter → 404 as today):

1. `GET /api/series/{series}/chapters/{chapter}/translations` → JSON `list[str]`: the stems of
   `<work_dir>/translations/*.json` sorted with `natural_key`; `[]` if the directory does not exist. Skip any file
   whose stem starts with `.`.
2. `GET /api/series/{series}/chapters/{chapter}/translations/{run_id}` → the file `translations/<run_id>.json`
   byte-for-byte (`media_type="application/json"`). `404` if it is missing, or if `run_id` contains `/` or `\` or
   equals/contains `..`, or if the resolved path is not inside `translations/` (use the existing `_under`).
3. `GET /api/series/{series}/chapters/{chapter}/final` → `final.json` byte-for-byte via `artifact_bytes`.
4. `GET /api/series/{series}/glossary` → JSON list of every glossary entry (`entry.model_dump(mode="json")`, all
   statuses) in store order; `[]` if `series.db` does not exist (do NOT open the store in that case).
5. `GET /api/series/{series}/chapters/{chapter}/glossary-hits` → JSON `{"regions": {<region_id>: GlossaryHit[]}}`.
   - Load `ocr.json` via `RegionsArtifact.load`; `404` (`"ocr.json not found"`) if absent.
   - Entries = store entries whose status is `"proposed"` or `"locked"` (skip `"rejected"`); no entries if the db is
     missing.
   - For **every** region id in `ocr.json` the map has a key (empty list if no hit). For a region, hits are
     `find_terms(region.text, entries)` in order. Each `GlossaryHit` is a JSON object
     `{entry_id: int, source: str, target: str, status: str, start: int, end: int, particle: str | null,
       target_in_final: bool | null}` where `source`/`start`/`end`/`particle` come from the `Match`,
     `target`/`status` from the entry with that `entry_id`, and
     `target_in_final = term_present(final_line.text, entry)` when `final.json` exists AND has a line whose
     `region_id` equals this region's id, else `null`.
   - If `final.json` exists but is invalid JSON/schema → treat as absent (all `null`), do not 500.

`webui/src/translation.ts` — pure helpers (no DOM, no Svelte), exact signatures:
```typescript
export interface ReviewRow {
  region: Region;
  candidates: Record<string, string | null>;   // run_id -> candidate text for this region (null = that run has none)
  final: FinalLine | null;
  hits: GlossaryHit[];
  violations: GlossaryHit[];                   // hits with status "locked" && target_in_final === false
  disagree: boolean;                           // see candidatesDisagree
  needsAttention: boolean;
}

/** Sort key order: slice_index asc, then reading_order asc, then id by numeric-aware comparison. Does not mutate. */
export function sortRegions(regions: Region[]): Region[];

/** True when at least 2 runs have a non-null candidate AND their texts differ after trim() + toLowerCase(). */
export function candidatesDisagree(candidates: Record<string, string | null>): boolean;

/** One row per region of `ocr`, in sortRegions order. `runs` may be empty, `final` and `hits` may be null.
 *  needsAttention = (final !== null && final.flags.length > 0) || violations.length > 0 || disagree
 *                   || (final === null && runs.length > 0 && every candidate value is null).
 *  A region with no entry in `hits.regions` (or hits === null) has hits = []. */
export function buildRows(
  ocr: RegionsArtifact, runs: CandidateRun[], final: FinalArtifact | null, hits: GlossaryHits | null,
): ReviewRow[];

export interface Segment { text: string; hit: GlossaryHit | null; }
/** Split `text` into consecutive segments so that each hit's [start, end) becomes one segment carrying that hit
 *  and the gaps become segments with hit === null. Hits are sorted by start; any hit that overlaps an earlier one or
 *  lies outside [0, text.length] is ignored; end is clamped to text.length. Concatenating all segment texts always
 *  reproduces `text` exactly. Empty text -> []. */
export function highlightSource(text: string, hits: GlossaryHit[]): Segment[];

export function summarizeReview(rows: ReviewRow[]): {
  total: number; withFinal: number; flagged: number; violations: number; disagreements: number;
};   // flagged = rows with needsAttention; violations = sum of violations.length; withFinal = rows with final !== null
export function filterRows(rows: ReviewRow[], onlyAttention: boolean): ReviewRow[];   // preserves order
export function hitColor(hit: GlossaryHit): string;
//   violation (locked && target_in_final === false) -> "#dc2626"; locked -> "#16a34a"; proposed -> "#d97706"; other -> "#6b7280"
```
`candidates` for a run is built from that run's `candidates[]` by `region_id` (if a run lists the same region twice, the
first one wins). `final` for a row is the `FinalLine` whose `region_id` matches, else null.

`webui/src/TranslationView.svelte` — props `{ series: string; chapter: string }`. On mount / prop change fetch, in
parallel, `getOcr`, `listTranslations` (then every `getTranslation`), `getFinal`, `getGlossaryHits`. Handling:
missing `ocr.json` (fetch fails) → inline message `no ocr.json yet — run ocr first` and nothing else; a failing
`getFinal` or `getGlossaryHits` is NOT an error (treat as `null`); a failing `getTranslation` for one run drops that
run and shows `could not load run <id>` under the toolbar.
- Toolbar: a checkbox `only rows needing attention` (unchecked by default) and a one-line summary from
  `summarizeReview` of ALL rows, e.g. `24 regions · 20 with final · 5 flagged · 1 glossary violation · 3 disagreements`.
- A `<table>`: header row `#` | `source` | one column per run (header = run id, `title` attribute = `profile · model`) |
  `final` | `glossary`. One body row per `filterRows(...)` row, background `#fef2f2` when `violations.length > 0`,
  `#fffbeb` when otherwise `needsAttention`.
  - `#` cell: `region.id`, `slice {slice_index}`, `order {reading_order}`, `kind`.
  - `source` cell: the segments of `highlightSource(region.text, row.hits)`; a hit segment is a `<mark>` styled with
    `hitColor(hit)` as background at 0.2 opacity and a `title` of `${hit.source} → ${hit.target} (${hit.status})`.
    If `region.ocr_alt` is not null and differs from `region.text`, show it below in gray labelled `alt`.
  - run cells: the candidate text, or `—` in gray when null; the `notes` (if any) in a `title` attribute.
  - `final` cell: the final text; below it a small badge with `decision`, one chip per flag (red when the flag is
    `glossary_violation`, otherwise amber), and the `rationale` inside a `<details><summary>why</summary>…</details>`
    only when non-empty. When `final` is null: gray `—`.
  - `glossary` cell: one chip per hit `${hit.source} → ${hit.target}` colored via `hitColor`; prefix `✗ ` for a
    violation. No hits → empty cell.
- Use `white-space: pre-wrap` in text cells (translations contain line breaks). Sticky table header.

## Acceptance tests

**Backend** (append to `tests/unit/test_web_app.py`; reuse its `make_client`/`write_chapter`-style helpers and
build a small `ocr.json` with `RegionsArtifact`, a `translations/runA.json` and `runB.json` via `CandidateRun(...).save`,
a `final.json` via `FinalArtifact(...).save`, and a glossary via `GlossaryStore(series_dir/"series.db")`):
1. `translations` lists `["runA", "runB"]` (natural order) when both files exist; `[]` when the directory is absent.
2. `translations/runA` returns the exact file bytes; `translations/nope` → 404; a run id of `..%2F..%2Fsecret` and
   of `..` → 404 (no file leak, no 500).
3. `final` returns the exact bytes; absent → 404.
4. `glossary` returns the entries (with their ids) for a store containing one locked and one rejected entry (both
   returned); returns `[]` when no `series.db` exists, and **the sqlite file must still not exist afterwards**.
5. `glossary-hits`: regions `r0001` text `"철수가 왔다"` and `r0002` text `"아무것도 없다"`; locked entry
   `철수 → Cheolsu`; `final.json` line for r0001 is `"Cheolsu came"` → `regions["r0001"]` has exactly one hit with
   `entry_id`, `source="철수"`, `target="Cheolsu"`, `status="locked"`, `particle="가"`, `start=0`, `end=3`,
   `target_in_final=true`; `regions["r0002"] == []`.
6. Same as 5 but the final line says `"Chul-soo came"` → `target_in_final` is `false`. With no `final.json` at all →
   `null`. With a `final.json` that has no line for r0001 → `null`.
7. A rejected entry produces no hit. Missing `ocr.json` → 404. Missing `series.db` → every region maps to `[]` and no
   sqlite file is created.
8. `..` in the series or chapter value on the new chapter routes → clean 404.

**Frontend** (vitest, pure functions only):
9. `sortRegions`: by slice_index, then reading_order, then id (`"r2"` before `"r10"`); input not mutated.
10. `candidatesDisagree`: `{a:"Hi", b:" hi "}` → false; `{a:"Hi", b:"Hello"}` → true; `{a:"Hi", b:null}` → false;
    `{}` → false.
11. `buildRows`: two regions, two runs, one final line + hits with one violation → row order, `candidates` map
    (`null` where a run lacks the region), `violations`, `disagree`, `needsAttention` (also true for a final flag, and
    for "no candidate text and no final" with runs present; false for a clean row).
12. `highlightSource`: `"철수가 왔다"` with one hit `[0,3)` → 2 segments (`"철수가"` with the hit, `" 왔다"` without);
    overlapping second hit ignored; out-of-range hit ignored; hit ending past the text is clamped; concatenation
    equals the input in all cases; `""` → `[]`.
13. `summarizeReview` and `filterRows` on a hand-built list; `hitColor` returns the four documented colours.

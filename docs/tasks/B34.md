# B34 — `omniscan usage`: aggregate LLM token/request usage per chapter/series

**Owner:** GLM builder · **Branch:** `B34` · **Worktree:** `V:\OmniScan-wt\B34` (created by `scripts/omni_builder.py`)
Read `CLAUDE.md` first. It overrides nothing below but applies everywhere.

## Goal
The pipeline already counts every LLM request it makes — `CandidateRun.usage` (translation runs) and, since
commit `5ae2276`, `FinalArtifact.usage` (the judge) both carry `dict[str, float]` counters — but nothing
populates the judge's field and nothing reads either one back. This card adds a read-only report command,
`omniscan usage [SERIES] [--json]`, that walks the work tree and prints token/request/seconds totals per
chapter, per source (each translation profile, then the judge), with per-series and grand totals. Motivation
(docs/PLAN.md backlog "Cost/usage tracking"): a single stuck builder run burned ~5M tokens / $26.77 — usage
must be visible per chapter/series before any budget cap can even be designed.

## Interfaces (exact — do not rename or change signatures)
```python
# src/omniscan/usage.py
from dataclasses import dataclass


@dataclass(frozen=True, slots=True)
class UsageRow:
    """One chapter artifact's LLM usage: one translation run or the judge's final.json."""

    series: str
    chapter: str
    source: str  # the run's profile name, or "judge" for final.json
    model: str
    usage: dict[str, float]  # the raw usage dict exactly as stored in the artifact


def collect_usage(cfg: Config, series: str | None = None) -> list[UsageRow]:
    """One row per chapter artifact carrying usage (translation runs then judge), in reading order."""


def totals(rows: Sequence[UsageRow]) -> dict[str, float]:
    """Element-wise sum of every usage key present in any row (generic, not key-set-limited)."""
```

```python
# src/omniscan/cli.py (registered on the top-level app, NOT a sub-typer)
@app.command("usage")
def cmd_usage(
    series: Annotated[str | None, typer.Argument(help="Series name; omit for every series.")] = None,
    json_output: Annotated[bool, typer.Option("--json", help="Emit JSON instead of a table.")] = False,
) -> None:
    """Summarise token/request usage recorded in translation runs and final.json."""
```

## Definitions (no interpretation needed)
- **Row order.** Series sorted by name (casefold); within a series, chapters in reading order (`natural_key`
  on the chapter directory name); within a chapter, `translations/*.json` rows first (alphabetical by file
  name, dot-prefixed files skipped — same rule as `judge_chapter._load_runs`), then the `final.json` judge row
  last. This matches pipeline execution order.
- **Which files count.** `work_root/<series>/<chapter>/translations/*.json` loaded as `CandidateRun`
  (source = `run.profile`, model = `run.model`), and `work_root/<series>/<chapter>/final.json` loaded as
  `FinalArtifact` (source = `"judge"`, model = `judge_model`). Chapter directories are the dirs of
  `work_root/<series>`, skipping names starting with `_` or `.`. A chapter directory with no loadable
  artifacts contributes no rows (not an error).
- **Legacy artifacts.** Any artifact whose `usage` dict is missing or empty (everything written before
  `5ae2276`, and every `final.json` until the judge-stage change in this card lands) yields a row with
  `usage == {}` — it counts as zeros, never as an error and never as a skip. This is the backward-compatibility
  property `5ae2276` deliberately provided (additive `default_factory=dict` field).
- **Corrupt files.** A `translations/*.json` or `final.json` that fails to load (invalid JSON, schema
  validation error) is skipped silently — `usage` is a read-only report, never a crash. (Match the web app's
  "never a 500" philosophy.)
- **`series=None`** means every series directory under `work_root` (dirs only, skipping `_`/`.`-prefixed
  names). A named series that is not a directory under `work_root` → the command exits with code 2 and an
  error message (reuse `filter_run`'s unknown-series pattern). A named series that exists but has no
  artifacts → exit 0, header/totals only.
- **Judge usage key set — pin exactly this.** In `judge_chapter.py`, the done path builds
  `FinalArtifact(judge_model=cfg.model, lines=lines, usage={...})` from the `JudgeStats` it already holds:
  `prompt_tokens`, `completion_tokens`, `requests`, `repair_requests`, `regions`, `seconds`, `rate_limited`
  — in that key order, every value `float(...)`, `seconds` already a float, `rate_limited` via
  `float(stats.rate_limited)`. (`stats` is only `None` on the skipped path, which returns early; if pyright
  still narrows it as `JudgeStats | None`, a local `assert stats is not None` before the constructor is the
  accepted minimal fix.) Do NOT add `judged`/`auto_picked`/`untranslated`/`violations_left` — those are
  pipeline metrics, not usage.
- **Table output.** Columns, left to right: `SERIES`, `CHAPTER`, `SOURCE`, `MODEL`, `PROMPT`, `COMPLETION`,
  `REQUESTS`, `SECONDS`. `PROMPT`/`COMPLETION`/`REQUESTS` print `int(x)` when the value is whole (the
  `cmd_translate` echo style), else the float; `SECONDS` prints one decimal. One row per `UsageRow`; after
  the rows, a single `TOTAL` line (`SERIES` column = `"TOTAL"`, chapter/source/model columns empty) with the
  `totals(all_rows)` values for the same four numeric columns. When there are no rows at all, print only the
  `TOTAL` line (all zeros).
- **`--json` output.** One JSON object printed to stdout: `{"rows": [<asdict(UsageRow) per row>],
  "totals": <totals(all_rows) as dict>}` — `json.dumps(..., indent=2)`; nothing else on stdout.
- **No pricing.** The command reports tokens/requests/seconds only. Cost estimation and budget caps are
  explicitly out of scope (no price table exists; that needs an owner decision — note it under Questions).

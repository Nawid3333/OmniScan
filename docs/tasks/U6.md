## Why
Owner decision 2026-09-19: the app updates itself from GitHub — **releases built by GitHub Actions are the update channel**, and a click on "Update" in the program uses them. This card builds the part that is independent of packaging: ask GitHub which release is newest, pick the asset for this platform, download it and verify it against the release's checksum file, and leave it staged in a folder.
Replacing the running program is platform-specific and belongs to the packaging cards (U4/U5); the GUI button belongs to the desktop shell. Both will call the functions written here.
Two facts shape the design: (1) the same repository also carries a release `models-v1` (model mirror, not an app release) — GitHub's `releases/latest` could return it, so the updater must **list** the releases and accept only **app tags** `vMAJOR.MINOR.PATCH[-prerelease]`; (2) the repository is private today, so an anonymous request answers 404 — that must give a clear message, not a stack trace.

## Part 1 — `update/version.py`
```python
@dataclass(frozen=True, slots=True, order=False)
class Version:
    major: int; minor: int; patch: int; pre: tuple[str | int, ...]      # pre = () for a final release
def parse_version(text: str) -> Version            # "v1.2.3", "1.2.3", "1.2.3-beta.2", "v0.1.0-rc.1"; ValueError(f"not a version: {text!r}") otherwise
def is_app_tag(tag: str) -> bool                   # True only for the strict form ^v\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$   ("models-v1", "v1", "v1.2", "1.2.3", "v1.2.3.4" -> False)
def compare_versions(a: Version, b: Version) -> int   # -1, 0, 1 with SemVer precedence
def current_version() -> Version                   # importlib.metadata.version("omniscan"); PackageNotFoundError -> Version(0, 0, 0, ())
```
SemVer precedence: compare major, minor, patch numerically; a version **with** `pre` is lower than the same core without; two `pre` tuples compare element by element (identifiers split on `.`; numeric identifiers compare as integers and are lower than alphanumeric ones; alphanumeric compare as strings; a shorter tuple that is a prefix is lower). Build metadata (`+...`) is not accepted (`ValueError`).

## Part 2 — `update/github.py`
```python
@dataclass(frozen=True, slots=True)
class Asset:  name: str; url: str; size: int            # url = browser_download_url
@dataclass(frozen=True, slots=True)
class ReleaseInfo:  tag: str; version: Version; prerelease: bool; notes: str; published_at: str | None; assets: tuple[Asset, ...]
class UpdateError(RuntimeError): ...

DEFAULT_REPO = "Nawid3333/OmniScan"
def platform_key() -> str                                  # f"{os}-{arch}": os in windows|macos|linux (from sys.platform), arch in x64|arm64 (from platform.machine(): AMD64/x86_64 -> x64, ARM64/aarch64/arm64 -> arm64); anything else -> UpdateError
def list_app_releases(client: httpx.Client, repo: str = DEFAULT_REPO, *, token: str | None = None) -> list[ReleaseInfo]
def latest_release(releases: Sequence[ReleaseInfo], *, channel: Literal["stable", "beta"] = "stable") -> ReleaseInfo | None
def select_asset(release: ReleaseInfo, key: str) -> Asset                # the asset named f"omniscan-{key}.zip"; missing -> UpdateError(f"release {tag} has no build for {key}")
def checksum_asset(release: ReleaseInfo) -> Asset                       # the asset named "SHA256SUMS"; missing -> UpdateError(f"release {tag} has no SHA256SUMS")
```
- `list_app_releases`: `GET https://api.github.com/repos/{repo}/releases?per_page=100` with headers `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`, `User-Agent: OmniScan-updater`, and `Authorization: Bearer <token>` when a token is given. Drafts are skipped; entries whose `tag_name` is not an app tag (`is_app_tag`) are skipped (this is what removes `models-v1`); the rest become `ReleaseInfo` (`prerelease` from the payload, `notes` = `body or ""`, assets from `assets[*].{name, browser_download_url, size}`), sorted by version descending.
  Errors: 404 → `UpdateError("no releases visible at github.com/<repo> (the repository may be private or the name wrong)")`; 403 or 429 with `X-RateLimit-Remaining: 0` → `UpdateError("GitHub rate limit reached; try again after <HH:MM UTC of X-RateLimit-Reset, or 'a while' when missing>")`; other status ≥ 400 → `UpdateError(f"GitHub answered HTTP {status}")`; `httpx.TransportError` → `UpdateError(f"cannot reach GitHub: {exc}")`.
- `latest_release`: `stable` → the highest version that is not a prerelease (neither `prerelease` true nor a `pre` part); `beta` → the highest version overall; none → `None`.

## Part 3 — `update/download.py`
```python
@dataclass(frozen=True, slots=True)
class StagedUpdate:  version: Version; tag: str; path: Path; sha256: str; asset: str

def parse_checksums(text: str) -> dict[str, str]                       # lines "<64 hex>  <name>" or "<64 hex> *<name>" (sha256sum output); blank lines and lines starting with "#" ignored; names lower-case hex values; malformed line -> UpdateError(f"bad line in SHA256SUMS: {line!r}")
def check_for_update(client: httpx.Client, *, repo: str = DEFAULT_REPO, channel: str = "stable", current: Version | None = None, token: str | None = None) -> ReleaseInfo | None   # newest release strictly newer than `current` (default: current_version()), else None
def download_update(client: httpx.Client, release: ReleaseInfo, updates_dir: Path, *, key: str | None = None, on_progress: Callable[[int, int | None], None] | None = None) -> StagedUpdate
```
`download_update`: `key` defaults to `platform_key()`; fetch the `SHA256SUMS` asset text (`GET`, follow redirects), take the entry for the selected asset's name (missing → `UpdateError(f"SHA256SUMS has no entry for {name}")`); stream the asset into `<updates_dir>/<tag>/<name>.part` while hashing (progress callback with done bytes and `Content-Length` or `None`); compare: mismatch → delete the `.part` and raise `UpdateError(f"checksum mismatch for {name}")`; on success `os.replace` to `<updates_dir>/<tag>/<name>`, write `<updates_dir>/<tag>/staged.json` (`{"tag","version","asset","sha256","downloaded_at"}`), return `StagedUpdate`. A file already there whose SHA-256 matches is reused without a request for the asset (checksums are still fetched). `.part` files never remain. HTTP errors while downloading → `UpdateError`.

## Part 4 — CLI `omniscan update`
- `check [--channel stable|beta] [--repo OWNER/NAME] [--json]`: prints `up to date (vX.Y.Z)` or `update available: vA.B.C (current vX.Y.Z)` + the release notes (first 20 lines) ; `--json`: `{"current": "0.1.0", "latest": "1.2.3"|null, "update_available": bool, "tag": ..., "notes": ..., "asset": name|null}`. `UpdateError` → message on stderr, exit 1. The optional token comes from the environment variable `GITHUB_TOKEN` (read with `os.environ`, never printed).
- `download [--channel ...] [--repo ...]`: check, then `download_update` into `<user data dir>/updates` where the user data dir is `get_config().paths.work_root.parent / "updates"`; prints progress every 10 % and the final staged path; nothing newer → `already up to date`, exit 0.
Use `httpx.Client(follow_redirects=True, timeout=30.0)`, closed at the end.

## Acceptance tests (CPU, no network)
1. **Versions**: parsing valid/invalid forms (`v1.2.3`, `1.2.3-beta.2`, `01.2.3` is accepted as numbers, `1.2`, `1.2.3+meta`, `latest`, `""` → errors); `is_app_tag` for `v1.2.3`, `v0.1.0-rc.1` (True) and `models-v1`, `v1`, `v1.2`, `1.2.3`, `v1.2.3.4`, `v1.2.3-` (False); the SemVer precedence chain `1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-alpha.beta < 1.0.0-beta < 1.0.0-beta.2 < 1.0.0-beta.11 < 1.0.0-rc.1 < 1.0.0`, plus `1.2.10 > 1.2.9`, `2.0.0 > 1.99.99`, equality; `current_version()` returns a `Version` and falls back to `0.0.0` when the package metadata is missing (monkeypatch).
2. **Listing**: a mocked `/releases` payload with `models-v1`, a draft `v9.9.9`, `v1.0.0`, `v1.1.0-beta.1` (prerelease) and `v0.9.0` → the list has exactly the three app releases sorted `v1.1.0-beta.1`, `v1.0.0`, `v0.9.0`; the request carries the documented headers and the bearer token only when given; `latest_release(stable)` → `v1.0.0`, `beta` → `v1.1.0-beta.1`, empty list → `None`.
3. **Errors**: 404, 403 with `X-RateLimit-Remaining: 0` and a reset time (message contains the UTC time), 500, a `httpx.ConnectError` → the exact messages above; malformed JSON → `UpdateError`.
4. **Assets**: `platform_key()` for the combinations Windows/AMD64, Linux/x86_64, Darwin/arm64, Linux/aarch64 (monkeypatch `sys.platform` and `platform.machine`) and an unsupported one; `select_asset` and `checksum_asset` including the error messages.
5. **Checksums**: `parse_checksums` for both `*name` and plain forms, comments, blank lines, upper-case hex, a bad line.
6. **Download**: happy path (assets served by the mock transport with a redirect for one of them) → `omniscan-windows-x64.zip` in `<updates_dir>/v1.0.0/`, `staged.json` correct, progress callback monotonic; checksum mismatch → error, `.part` gone and no final file; missing entry in `SHA256SUMS` → error; the second call with the file already present makes no request for the asset; a 500 while downloading → `UpdateError`.
7. **`check_for_update`**: newer, equal and older releases relative to `current`; a prerelease is ignored on `stable`; `None` when nothing is newer.
8. **CLI**: `check` text and `--json` (parse it), `check` when up to date, an `UpdateError` → exit 1 with the message on stderr, `download` stages the file in a temp work root and prints the path, `GITHUB_TOKEN` is sent as a bearer header and never printed; `tests/unit/test_docs.py` and the whole suite stay green.

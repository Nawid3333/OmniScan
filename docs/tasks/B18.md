## Why
extract.pics sends a webhook (POST, fixed JSON body, no custom headers, no signature, retries on non-200) when an
image extraction finishes. It must hit a public HTTPS URL. This relay receives it, stores it durably and
idempotently, and pushes it to the local OmniScan client over a WebSocket (with replay of anything missed).

## HTTP API (exact)
| Method + path | Auth | Behaviour |
|---|---|---|
| `GET /health` | none | 200, body `ok` |
| `POST /hooks/extractpics/:secret` | `:secret` must equal `HOOK_SECRET` (constant-time compare) | wrong secret → **404** (don't reveal). Body > 5 MiB → 413. Invalid JSON → 400. `type` not in {`extraction_done`,`extraction_batch_done`,`download_done`} → 422. Dedupe key = `${type}:${data.id ?? data.batch_id}` (missing both → 422). Store; respond **200** `{"ok":true,"duplicate":<bool>,"seq":<n>}` (duplicate returns the original seq). |
| `GET /events?after=<seq>&limit=<n>` | `Authorization: Bearer <CLIENT_TOKEN>` else 401 | events with `seq > after` ascending, `limit` default 100, max 500. Response `{"events":[Event...],"next":<last seq or after>}` |
| `POST /ack` | Bearer | body `{"upto": <seq>}` → delete events with `seq <= upto`; response `{"deleted": n}` |
| `GET /ws` | Bearer | WebSocket upgrade (else 426). Hibernation API (`ctx.acceptWebSocket`). Client may send `{"type":"hello","after":<seq>}` → hub sends every stored event with `seq > after`, then live events. Every newly stored (non-duplicate) event is broadcast to all sockets as the Event JSON. |
| anything else | — | 404 |

`Event` JSON: `{"seq": int, "key": str, "type": str, "received_at": int (ms epoch), "payload": <original body object>}`.

## Storage (inside `EventHub`, `ctx.storage.sql`)
Table `events(seq INTEGER PRIMARY KEY AUTOINCREMENT, key TEXT UNIQUE NOT NULL, type TEXT NOT NULL,
received_at INTEGER NOT NULL, payload TEXT NOT NULL)`. Retention: an alarm runs every 24 h and deletes rows older
than 14 days; schedule it on first store if none is set.

## Acceptance tests (`relay/test/relay.test.ts`, vitest-pool-workers, `SELF.fetch`)
1. `/health` → 200 `ok`.
2. Wrong hook secret → 404; right secret + valid `extraction_done` payload → 200 with `duplicate:false`.
3. Same payload POSTed twice → second response `duplicate:true`, same `seq`; `/events` returns it once.
4. Invalid JSON → 400; unknown `type` → 422; missing id and batch_id → 422.
5. `/events` without/with wrong bearer → 401; `after` and `limit` work; `next` correct.
6. `/ack {"upto": n}` deletes those events.
7. WebSocket: connect to `/ws` with bearer, send hello `after:0` → receives previously stored event; then POST a
   new hook → the socket receives it within 1 s.
8. `/ws` without bearer → 401.
Use the extract.pics example payload shape:
`{"type":"extraction_done","data":{"id":"<uuid>","status":"done","url":"https://example.com/page","images":[{"id":"<uuid>","url":"https://example.com/a.jpg"}],"created_at":"2026-09-18T00:00:00.000000Z","project_id":"<uuid>"}}`.

## Evidence gathered (all reproducible; details in `docs/benchmarks/` and `docs/reports/`)
- **Windows native works** (`windows-native.md`): AMD's `win_amd64` ROCm wheels run on the RX 9070 XT; GPU selection via `omniscan.gpu.device.resolve_device` (the iGPU is `cuda:0` and crashes, the 9070 XT is `cuda:1`; call `torch.cuda.set_device` before MIOpen work).
- **fp16 is unreliable → everything runs fp32** (`windows-native.md` addendum, `docs/DECISIONS.md`): RT-DETR fp16 works only at batch 8, the PP-OCR detector and LaMa fail in fp16 too. fp32 speeds: RT-DETR 31–65 tiles/s, PP-OCR det 25 ms per 960×704, LaMa 30 ms per 512² (steady state).
- **OCR** (`ocr-probe.md`): PP-OCRv5 server text-line detector + Korean recognition through `transformers`: CER 0.048 in the probe, 0.03–0.04 on synthetic pages; DB post-processing on the CPU with OpenCV (3.4 ms per page).
- **LaMa** (`lama-probe.md`): TorchScript `big-lama.pt` in fp32, 30 ms per 512² crop; every new input shape costs a 10–25 s warm-up → one fixed 512² window warmed once.
- **Detection on real art** (C3 report): on English hand-lettered Pepper&Carrot pages (out of domain) it finds titles and bubbles, misses some, puts low-confidence boxes on objects; on synthetic Korean pages it finds all regions (boxes ~15 px padded around the ink).
- **Codec:** rocJPEG cannot run here; CPU `turbo` ≈ 141–148 Mp/s (`codec.md`). **A CUDA-only race in `TurboCodec.decode_into` duplicated pages** (fixed `8c3a32f`, guarded by a GPU test and by the golden test).
- **Translation** (`translation-probe.md`): gemma4 needs `think:false`; cloud models ignore Ollama's JSON `format`; translategemma ignores the glossary unless locked terms are pre-substituted. Cloud models are reachable through the local daemon (`x:cloud` and `x:31b-cloud` names).
- **Mutation reviews** (`scripts/mutate.py`, lists in `tests/mutants/`): 61 mutants on run/queue/adapters, 129 on slicer/ingest, 115 on filter/glossary/importer — all real gaps closed by tests; the director's earlier reviews of C3–C7c (~150 mutants) likewise.
- **Builders on Windows:** `scripts/omni_builder.py` (3 concurrent slots, `PYTHONPATH` pinned to the worktree, hard limit 150 tool calls per run) runs `claude` against the local Ollama with `glm-5.3-flash:cloud`.

## How to work the loop (for the next session)
- **Builders:** `uv run python scripts/omni_builder.py run <ID>` from `V:\OmniScan` (default `glm-5.3-flash:cloud`; `--model glm` only for genuinely hard cards or after flash failed; `resume <ID> <feedback-file> [--max-turns N]`; `smoke`). Launch it as a **background tool call** so the completion notification arrives; at most 3 at once
  (`OMNI_SLOTS=2` when a live Ollama check is planned). Worktrees go to `V:\OmniScan-wt\<ID>` with a junction to the shared `.venv`. A stuck builder can be stopped (kill the `omni_builder.py run <ID>` process tree with `taskkill /PID <uv pid> /T /F`), its session id copied from the log into `.builder/logs/<ID>.session`, and resumed with a feedback file.
  **Every run has a hard limit of 150 tool calls**; a run that ends at the limit has usually finished but not committed — look at `git status` in its worktree before anything else.
- **Card → review → merge:** write `docs/tasks/<ID>.md` (exact interfaces, numbered acceptance tests, file allowlist, stop-and-ask, "commit early"; compute golden values from real code first), `uv run ruff format` it and commit; after the builder finishes: in the worktree `git rebase main` (README/USER_GUIDE/stub-list conflicts are routine: keep both sides' additions, remove every implemented command from the stub lists), read `docs/reports/<ID>.md` (Deviations + Questions),
  run ruff/pyright/pytest **with `PYTHONPATH=<worktree>\src` and `.venv\Scripts\python.exe -m …`** (the shared editable install flips on every `uv run`), mutation-check the logic with `scripts/mutate.py` (a list of `(file, old, new, label)` in a scratch file; ~20–60 mutants; kill survivors with tests), look at real output where it is visual,
  add a "Review addendum (director)" to the report, `git merge --ff-only <ID>` in `V:\OmniScan`, run the suite on `main`, push, remove the worktree (delete the leftover `.venv` junction with `[System.IO.Directory]::Delete(path, $false)` — never recursive) and the branch.
- **Gotchas:** builders' `ruff format .` may reformat older un-formatted cards (`git checkout -- docs/tasks/<file>` before rebasing); a builder whose worktree was cut before a dependency merged may re-implement it (dedupe on review); the PowerShell tool resets its cwd on every call; use `uv run --frozen`; files with quotes are easier to write with the editor tools than with heredocs; symlinks need Developer Mode; `python -m omniscan` does not exist (use `python -c "from omniscan.cli import app; app()" <args>` with `PYTHONPATH` set); Korean output needs `PYTHONIOENCODING=utf-8`.
- **Data:** never commit raws or samples (`data/`, `library/`, `samples/` are gitignored); tests use synthetic fixtures (`tests/fixtures/korean_pages.py`).

## Pipeline design
| Decision | Why / evidence | Status |
|---|---|---|
| **Clean only the lettering, not its box** (`inpaint/glyph_mask.py`): an Otsu split along the text boxes' principal colour axis, the ink side decided by the crop border, enclosed fills added, the letters (own colour, thin art lines opened away) grown over their measured outline + 2 px; implausible splits fall back to the old rectangle | With PaddleOCR-VL (the ko/zh default) the "line" is the whole region box, so LaMa repainted whole boxes of art. On synthetic pages over drawn art: 100 % of text pixels still covered on flat/gradient/noise backgrounds, LaMa masks 23-45 % smaller, SFX on flat panels cleaned without LaMa; a white outline around black letters crossed by black art lines no longer survives as a ghost. `docs/benchmarks/lettering-quality.md` | firm (2026-09-25) |
| **LaMa never sees lettering as context**: flat-filled regions are applied first, each finished region is written back, every window masks all not-yet-cleaned regions it reaches (the whole tiled region, neighbours) | A tiled SFX left orange remnants: each tile masked only its own part and LaMa copied the rest of the effect's colour into the hole | firm (2026-09-25) |
| **Letter to the balloon, not its inscribed rectangle** (`typeset/fit.py`): per-line widths from the ellipse's chords; every line count tried; the ones within 10 % of the largest size (and 1-2 px below it) compete on size + phrasing (break after sentences/clauses, never after an article, no stranded little word); lines balanced by DP | The professional "lozenge" with phrase-aware breaks ("Are you okay? / The dungeon just / ..." instead of "Are you okay? The / dungeon just / ..."), 12 % breathing room from the outline, at about the same size as before (-2..+1 px); ragged greedy blocks and "back." widows gone. `docs/benchmarks/lettering-quality.md` | firm (2026-09-25) |
| **Chapter-wide sizes**: dialogue at most `size_spread` (1.15) x the chapter's median balloon size, shouts `shout_spread` (1.35) | Official releases keep dialogue size uniform; per-balloon maximising set "Huh?" at 48 px next to 20 px dialogue | firm (2026-09-25) |
| **Lettering presets** `webtoon` (Mali, mixed case) / `manga` (Kalam in capitals, the CC Wild Words look), picked by source language; every role's font overridable with the user's own licensed fonts | Comic Neue read as "Comic Sans" (the amateur tell); official English manga letter in slanted capitals, official webtoons in clean rounded mixed case; commercial fonts cannot be bundled (E2) | firm (2026-09-25) |
| **Sound effects: detect by lexicon after OCR, redraw in the original's style** (`ocr/sfx.py`, `typeset/sfx.py`): onomatopoeia words (ko/ja/zh, repeats and stretching understood) turn free text into kind `sfx`; fill/outline colour, tilt (thinnest-extent angle, 2+ letters) and stroke weight (erosion median on the levelled letters) are measured; the English effect uses those colours, that tilt and a face of matching weight, stacked in tall boxes; a small subtitle where the original stays | Owner 2026-09-25 wants SFX "stylistic matched like official translations" (supersedes "leave as-is", 2026-09-23). The detector's classes never produce `sfx` on real pages (M10). Weight classes hold across size, tilt, outline and fill colour on Nanum Gothic (bold 0.089-0.108, regular 0.057-0.070); size-only detection (huge short text) exists but is off by default — a big sign would pass it | firm (2026-09-25); real-chapter check pending |
| **Stages with resumable manifests**: each stage declares inputs (content-hashed), a config subset and outputs; a re-run is a no-op | Hundreds of chapters, cloud rate limits, cheap re-runs after editing one thing (`core/stage.py`) | firm |
| **Strip space**: a chapter is one vertically stitched, width-normalised strip; slices are virtual y-ranges | Webtoon reading order, no physical slice files until export | firm |
| Slicer: cut only inside uniform bands ≥ 50 px, DP toward a target height, forced cuts flagged | Never cut through art/bubbles; verified on synthetic property tests (150 seeds) and real pages | firm |
| **CPU `turbo` codec is the baseline**; the hybrid GPU codec (C2) waits for a real-data profile | rocJPEG hardware decode unavailable (WSL had no VCN; not on Windows); turbo ≈ 141–148 Mp/s (`docs/benchmarks/codec.md`) | firm baseline, C2 open (Q F1) |
| Detection: `ogkalu/comic-text-and-bubble-detector` (RT-DETR-v2, Apache-2.0) on overlapping square tiles (tile = min(1280, strip width), overlap 0.5, resized to 640²) | The model was trained on 640² resized images with tall webtoons split vertically; finds bubbles, their text and free SFX on real pages | firm (C3 in review) |
| Detect writes `regions.json` only — **no text masks, no "cut validator"** | Masks come from OCR line boxes in the inpaint stage; all later stages work in strip space, so a region crossing a cut only matters when export re-cuts slices | firm |
| OCR: PP-OCRv5 **server text-line detector** + PP-OCRv5 Korean / PP-OCRv6 zh+ja recognition via `transformers`; PaddleOCR-VL as second opinion | Probe: 7/7 lines, recognition CER 0.048 on boxes from the detector, no false positives on real art (`docs/benchmarks/ocr-probe.md`) | firm (C4a), second opinion planned |
| **All torch vision models run in fp32** (comic detector, PP-OCR detector and recognizer): no `.half()` / autocast | On this ROCm-Windows stack MIOpen's FP16 kernels are unreliable: the PP-OCR detector fails in fp16/bf16 at every shape tried, and RT-DETR fp16 works only at batch 8 (142.7 tiles/s) but fails at batch 1, 2 and 3 (`miopenStatusUnknownError`, `invalid device function`), so a short chapter or a partial last batch would crash. fp32 works at every batch size (RT-DETR 31–65 tiles/s, PP-OCR det 25 ms per 960×704) — a 200-tile chapter costs ~3 s. `docs/benchmarks/ocr-probe.md`, `windows-native.md` addendum | firm (re-test after driver/torch updates) |
| **DB post-processing of the text-line heatmap runs on the CPU (OpenCV)** — an exception to "GPU end-to-end" | Measured 3.4 ms per page vs ~41 ms for a GPU connected-components version; ~0.1 s per chapter; needs `opencv-python-headless` | firm on evidence (question F9 covers the other CPU exception) |
| Inpaint: flat fill for uniform bubble interiors (C6a), LaMa for text over art (C6b); export composites only the masked pixels onto the original | Minimal quality loss and IO | flat fill firm; LaMa firm on evidence |
| **LaMa = TorchScript `big-lama.pt`, fp32, one fixed 512×512 window per region, warmed once per process** | 30 ms per crop steady state, output identical outside the mask, text on painted art removed convincingly; every new input shape costs a 10–25 s warm-up, fp16 fails (`docs/benchmarks/lama-probe.md`) | firm (C6b planned) |
| Model groups are never co-resident with the local LLM (VramManager evicts Ollama models) | 16 GB VRAM; WDDM silently pages instead of failing | firm |

## Translation
| Decision | Why / evidence | Status |
|---|---|---|
| **Several candidate runs + a judge**, profiles in TOML; judge = `gemma4:31b-cloud` | Different models resolve ambiguity differently (probe); the judge picks/merges using glossary and context | firm design, judge planned (C5) |

| Regions are sent with whitespace collapsed to one line | Source line breaks leaked into the English; the typesetter re-wraps | firm |
| `endpoint = "local"` for all shipped profiles, including `*-cloud` models | The local Ollama daemon proxies cloud models; no API key needed | firm |
| Reference mode (already-translated chapters as baseline, auto-lock terms seen in ≥ 3 chapters) | Human translations are the best glossary/style source | planned (C12, Q D7) |

## Desktop app (owner 2026-09-20: "PySide, research the rest, keep building")
| Decision | Why / evidence | Status |
|---|---|---|
| **PySide6** (Qt for Python, official), not PyQt6 | LGPL-3.0 (PyQt6 is GPL/commercial → would force the whole app under GPL or a licence fee); wheels exist for Python 3.14 (6.11.2, `<3.15`); owner preference | firm |
| **Native Qt widgets on `PySide6-Essentials` only** (optional extra `gui`); **no `QWebEngineView`** | Essentials is 77 MB (Windows wheel) vs +168 MB for Addons, which carries Chromium/WebEngine; small installer is a product principle; side-by-side with exact scroll sync and manual brush tools are easier in `QGraphicsView`/`QScrollArea` than in an embedded web app. The FastAPI + Svelte debug UI stays as the *browser mode* (LAN/relay use), it is not embedded | firm |
| The GUI never shells out to the CLI: a Qt-free **service layer** (`omniscan/gui/services/*`: library, models, hardware, settings, runs) returns plain dataclasses that the CLI `--json` commands also use; widgets only render them; long work runs in `QThread` workers with signals | Testable without a display (`QT_QPA_PLATFORM=offscreen`), one code path for CLI and GUI | firm |
| **Side-by-side / reader work in strip space**: raw pages (`ingest.json` `files[].y0/y1`) and output slices (`slices.json` + `export.json`) share the same scaled strip coordinates, so "synced scrolling" is exact (same strip y), filtered slices show as gaps; "independent" is the free mode | The ingest step already scales every raw page to the strip width | firm |
| Packaging (U4) is decided later: PyInstaller first (best Qt + torch support), Nuitka evaluated; per-vendor torch runtime (CPU ≈ 0.2 GB, CUDA ≈ 3–4 GB, ROCm ≈ 4–5 GB) chosen at install/first run | Installer must stay small; see `docs/NEXT.md` M13 | open |
